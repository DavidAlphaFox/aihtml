# T35 · include/ai_jinja.hrl 数据契约

- **阶段**：9
- **依赖**：[T33](T33.md)
- **状态**：已完成

## 目标

定义 scanner / lexer / expr / parser / ast / compiler / plugin / 用户扩展模块共同遵守的类型、宏与记录。**只有类型、宏和注释，没有函数**（与 `ai_mustache.hrl` 同规格）。

## 交付物

- `include/ai_jinja.hrl`

## 实现要点

### 1. 定界符与版本

```erlang
-define(AI_JINJA_EXPR_START,  <<"{{">>).
-define(AI_JINJA_EXPR_STOP,   <<"}}">>).
-define(AI_JINJA_STMT_START,  <<"{%">>).
-define(AI_JINJA_STMT_STOP,   <<"%}">>).
-define(AI_JINJA_COMM_START,  <<"{#">>).
-define(AI_JINJA_COMM_STOP,   <<"#}">>).

%% 生成代码形态版本。compiler 改变输出形态时必须递增，否则已生成模块不会重编。
-define(AI_JINJA_VSN, 1).
```

定界符不可配置（[09 §1](../designs/09-jinja-syntax.md)），因此是宏不是选项。

### 2. token 类型

按 [09 §5.1](../designs/09-jinja-syntax.md)：`jinja_token()`，以及表达式 token
`jinja_expr_token()`（名字/数字/字符串/运算符/关键字/括号，各带 loc）。

### 3. AST

按 [09 §5.2](../designs/09-jinja-syntax.md) 的 `jinja_node()`
与 [11 §3.1](../designs/11-jinja-codegen.md) 的 `expr()`。

两条必须在 hrl 注释里写死的约定：

- `expr()` 的每个节点都带 loc，理由见 [09 §6](../designs/09-jinja-syntax.md)；
- `include`/`extends`/`import`/`from` 的 Target 在 AST 后处理前是 `binary()`，
  之后是 `module()` —— 与 mustache 的 partial 同构，注释里点明这层对应关系。

### 4. 选项

```erlang
-type ai_jinja_opts() :: #{
        module     := module(),
        source     := binary(),
        prefix     => binary(),      % 默认 <<"j2_">>
        views      => binary(),
        views_abs  => binary(),      % 解析后的绝对路径，不进 stamp
        suffix     => binary(),      % 默认 <<".j2">>
        extensions => [module()],
        escape                => boolean(),   % 默认 true
        trim_blocks           => boolean(),   % 默认 true
        lstrip_blocks         => boolean(),   % 默认 true
        keep_trailing_newline => boolean(),   % 默认 false
        strict_undefined      => boolean(),   % 默认 false
        line_map              => boolean()    % 默认 true
       }.
```

**五个 Jinja 独有的布尔选项全部进 stamp**（改了要重编）。
`views_abs` 与 `suffix` 不进，理由与 mustache 侧相同（[04 §4.1](../designs/04-codegen.md)）。

### 5. 错误

按 [11 §9](../designs/11-jinja-codegen.md) 的 `ai_jinja_reason()`，
外壳复用 `ai_html_error/1`。

### 6. 自描述 attribute

```erlang
-type ai_jinja_source() :: #{
        path := binary(), stamp := binary(), mtime := integer(),
        vsn := pos_integer(), opts := map()}.
```

与 mustache 的 `-mustache_source` 同形，但 attribute 名是 `jinja_source`
（[08 §2](../designs/08-jinja-architecture.md) 解释了为何不统一）。

### 7. 内置名字表

```erlang
%% 不能被 {% set %} / {% for %} / 宏参数遮蔽的名字。遮蔽即编译警告。
-define(AI_JINJA_RESERVED, [loop, super, caller, varargs, kwargs, self]).
```

## 验收标准

- [ ] hrl 内无函数定义，只有 `-define` / `-type` / 注释
- [ ] 有 include guard
- [ ] 每个 `-type` 都有注释说明它在管线的哪一段出现、由谁产生、由谁消费
- [ ] `?AI_JINJA_VSN` 的注释写明「什么时候必须递增」
- [ ] 空模块 `-include("ai_jinja.hrl").` 可编译且无 warning
- [ ] 五个 Jinja 独有选项的默认值在注释中写明，且与 [10](../designs/10-jinja-semantics.md) 一致
