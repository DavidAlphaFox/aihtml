# T49 · macro / call / import / from / include codegen

## 目标

实现宏与跨模板复用的四种机制，全部编译成静态调用。

## 交付物

- `src/ai_jinja_compiler.erl` —— 宏与复用部分
- `test/ai_jinja_macro_tests.erl`
- `test/ai_jinja_include_tests.erl`

## 实现要点

### 1. `macro`

编译成模块级函数 `macro_<name>(Args :: map(), V :: scope()) -> iolist()`
（[10 §7](../designs/10-jinja-semantics.md)）。

**宏看不见调用点的局部变量** —— 这是 Jinja2 的规定，也正好对应
「编译成独立函数」。宏体内可见：

- 自己的参数（含默认值）
- 模板顶层的 `{% set %}`（编译成模块级常量或在 `V` 的根帧）
- `varargs` / `kwargs` / `caller`

参数默认值是表达式，在**调用点**求值还是**定义点**求值？
Jinja2 是定义点（模块加载时）。本实现取**调用点求值**并记入差异清单 ——
定义点求值需要在模块里存一份求值结果，而默认值可能依赖模板全局，
调用点求值行为更直观且实现简单。

`varargs` / `kwargs`：多余的位置/关键字参数收集进这两个名字。
宏体不引用它们时不生成收集代码。

### 2. `call`

```jinja
{% call(x) render_item() %}{{ x }}{% endcall %}
```

块体包成 `caller` 传给宏：

```erlang
macro_render_item(#{caller => fun(CallerArgs__, V__) -> [<Body>] end}, V)
```

`caller` 有自己的参数表（`{% call(x) %}` 的 `x`）。
宏体内 `{{ caller(v) }}` 编译成对该 fun 的调用。

宏体不引用 `caller` 时，`{% call %}` 的块体**仍然要生成**（可能有副作用）
但结果丢弃 —— 实际上 Jinja2 里就是不输出。生成 `_ = fun(...)` 会有 unused 警告，
所以直接不传 `caller` 键即可。

### 3. `import` / `from`

```erlang
%% {% import "m.j2" as m %}  →  #cs.imports 增加 {m, j2_m}，不生成代码
%% {{ m.input(...) }}        →  j2_m:macro_input(Args, V)     直接跨模块调用

%% {% from "m.j2" import input, box as b %}
%%   →  #cs.imports 增加 {input, {j2_m, macro_input}}, {b, {j2_m, macro_box}}
```

**零运行期查表**（[10 §7](../designs/10-jinja-semantics.md)）。
改被导入模板不需要重编导入方，只要宏签名不变。

`with context` / `without context`：控制被导入模板的宏能否看到当前上下文。
默认 `without context`（Jinja2 的默认）。
`with context` 时把当前 `V` 传过去，`without` 时传 `[root(V)]`。

导入的名字不存在于目标模板 → **编译错误** `{macro_not_found, Name, Mod}`。
这需要在编译期知道目标模板导出了哪些宏 —— 由 plugin 提供（[T52](T52.md)），
单模板编译时降级为不检查并发 warning。

### 4. `include`

[11 §4.4](../designs/11-jinja-codegen.md)：

```erlang
%% {% include "widgets/box.j2" %}
j2_widgets_box:render_scope(V, I)

%% {% include "x.j2" ignore missing %}
case erlang:function_exported(j2_x, render_scope, 2) of
    true -> j2_x:render_scope(V, I); false -> [] end

%% {% include "x.j2" without context %}
j2_x:render_scope([ai_jinja_rt:root(V)], I)
```

`ignore missing` 用 `function_exported/3` 而非 `code:is_loaded/1`：
更可靠且不触发加载。**但它对未加载的模块返回 false** ——
需要先 `code:ensure_loaded/1`。生成代码里加这一步，或在 module doc 里
说明使用方需保证模块已加载。**选前者**，行为更符合直觉。

### 5. 内联模板的限制

[11 §8](../designs/11-jinja-codegen.md)：内联模板拒绝
include / extends / import / from / block，允许 macro（编译成绑定的匿名 fun）。
本任务负责在 `#cs.inline = true` 时报 `{target_in_inline_template, Kind}`。

## 验收标准

- [ ] 宏的参数、默认值、`varargs`、`kwargs` 各有用例
- [ ] 宏看不见调用点的局部变量（专项用例）
- [ ] 默认值在调用点求值，有 `deviation` fixture 记录该差异
- [ ] `{% call %}` 的 `caller` 正确传递，含带参数的 `{% call(x) %}`
- [ ] 宏不引用 `caller` 时不传该键，无 unused 警告
- [ ] `{% import as %}` 与 `{% from import %}` 都编译成直接跨模块调用（遍历 forms 断言无 `apply/3`）
- [ ] `with context` / `without context` 的默认值与行为正确
- [ ] 导入不存在的宏在有 plugin 信息时报编译错误，无信息时 warning
- [ ] `include` 三种形态正确；`ignore missing` 对不存在模块返回空且先 `ensure_loaded`
- [ ] 内联模板对五种语句报 `{target_in_inline_template, Kind}`
- [ ] 被 include 模板进 `partials/0`
- [ ] fixture 中 `macro` / `include` 组用例全部点亮
