# T44 · ai_jinja_tests 与 ai_jinja_ext

- **阶段**：11
- **依赖**：[T43](T43.md)
- **状态**：已完成

## 目标

实现内置 test 库，以及自定义 filter/test 的注册 behaviour。

## 交付物

- `src/ai_jinja_tests.erl`
- `src/ai_jinja_ext.erl` —— behaviour + 注册表构建与校验
- `test/ai_jinja_tests_tests.erl`
- `test/ai_jinja_ext_tests.erl`

## 实现要点

### 1. 内置 test（[10 §8.3](../designs/10-jinja-semantics.md)）

```
defined undefined none boolean false true integer float number string
sequence mapping iterable callable sameas escaped
in eq ne lt le gt ge odd even divisibleby lower upper filter test
```

签名与 filter 一致：`test_name(V, Args) -> boolean()`。

两个要点：

- **`defined` 对显式传入的 `none` 返回 `false`**（[10 §9](../designs/10-jinja-semantics.md) J2）。
  这是合并 `none` 与 `undefined` 的直接后果，必须有 fixture 明确锁定，
  并在文档的差异清单里指向这条用例。
- `escaped(V)` 判断 `V` 是否为 `{safe, _}`。
- `filter(Name)` / `test(Name)` 判断某个名字是否是已注册的 filter/test ——
  它们要读注册表，因此依赖 `ai_jinja_ext`。

### 2. `ai_jinja_ext` behaviour

```erlang
-callback filters() -> #{atom() => {module(), atom(), arity()}}.
-callback tests()   -> #{atom() => {module(), atom(), arity()}}.
-callback params()  -> #{atom() => [atom()]}.
-optional_callbacks([params/0]).
```

比 mustache 的扩展 behaviour（`markers/0` + `compile_tag/4`）**窄得多**，
因为 filter 不参与 codegen —— 它就是一个普通函数
（[12 §5](../designs/12-jinja-toolchain.md) 解释了为何不做自定义 tag）。

### 3. 注册表构建

```erlang
-spec registry([module()]) -> {ok, #{filters := map(), tests := map(),
                                     params := map(), modules := [module()]}}
                            | {error, ai_jinja_reason()}.
```

- 遍历 `extensions` 列表，`code:ensure_loaded/1` 后读三个 callback。
- **与内置同名 → 编译错误** `{filter_name_conflict, Name, Mod}`，不静默覆盖
  （[10 §8.4](../designs/10-jinja-semantics.md)）。
- 两个扩展模块之间同名 → 同样报错，错误里列出两个模块。
- `modules` 是收集到的模块列表，交给 compiler 加进 `check_remotes/3` 白名单
  （[08 §5](../designs/08-jinja-architecture.md) 不变量 8）。

### 4. 静态校验（供 parse_transform 用）

模块尚未编译时也要能校验 `-jinja_ext(Mod)`（[12 §2](../designs/12-jinja-toolchain.md)）。
复用 `ai_mustache_ext` 的手法：读 `Mod.erl` 源码、扫描 forms、
从 `filters/0` 的函数体里静态求值出 map 字面量。

```erlang
-spec spec_module(module()) -> {ok, info()} | {error, reason()}.
```

这份实现在 mustache 侧已经有了（`ai_mustache_ext:spec_module/1` / `spec_markers/1`），
**结构照抄，求值的目标不同**（那边是字符列表，这边是 map 字面量）。

### 5. 错误文案

每个 reason 的 `format_error/1` 要说清「哪里错了 + 怎么改」。
`{filter_name_conflict, Name, Mod}` 的文案要同时给出内置的那个和用户的那个。
