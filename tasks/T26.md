# T26 · 删除 attic 与旧实现

- **阶段**：6
- **依赖**：[T15](T15.md), [T20](T20.md), [T25](T25.md)
- **状态**：已完成

## 目标

删除阶段 1 暂存在 `attic/` 的全部旧实现（含从 `examples/` 移入的 `dom_render.erl`），让仓库中只剩下新架构的代码，并用 xref / grep 确认没有任何悬空引用。

## 交付物

- `attic/`（整个目录删除，含 `attic/README.md`）—— 阶段 1 暂存的旧实现，parser 重写（阶段 2）与 rt 分派表（阶段 3）完成后不再需要
- `rebar.config` / `Makefile` / `.gitignore` —— 清理与 `attic/` 相关的 `src_dirs`、排除项、忽略项
- xref 与 grep 的检查结果（作为验收证据，不落盘为文档）

## 实现要点

### 1. 待删除文件清单

依据 [designs/02-architecture.md](../designs/02-architecture.md) 第 4 节「删除清单（决策 D4 + 架构收敛）」，以及 [designs/07-roadmap.md](../designs/07-roadmap.md) 阶段 1 中「旧实现移出构建路径，暂存于 `attic/`，阶段 6 删除」的约定。阶段 1（[T01](T01.md)）实际暂存的内容如下，本任务全部删除：

| 文件（阶段 1 后的路径） | 原路径 | 删除原因 |
|---|---|---|
| `attic/ai_mustache_loader.erl` | `src/ai_mustache_loader.erl` | ets + gen_server 缓存机制被编译期方案完全取代 |
| `attic/ai_mustache_runner.erl` | `src/ai_mustache_runner.erl` | 栈式解释器被生成代码取代 |
| `attic/aihtml_app.erl` | `src/aihtml_app.erl` | 退化为 library app，无 application 回调 |
| `attic/aihtml_sup.erl` | `src/aihtml_sup.erl` | 无进程可管 |
| `attic/ai_dom_node.erl` | `src/ai_dom_node.erl` | 与 mustache 无关、无内部引用（决策 D4） |
| `attic/ai_dom_render.erl` | `src/ai_dom_render.erl` | 同上，且 `render/2` 有必崩 bug（[01 §B2](../designs/01-current-state.md)） |
| `attic/dom_render.erl` | `examples/dom_render.erl` | `ai_dom_*` 的唯一使用者，随之一并删除 |
| `attic/ai_mustache.erl` | `src/ai_mustache.erl` | v0.3.7 门面（bootstrap / reload / 进程字典缓存），已由新门面在 `src/` 重写 |
| `attic/ai_mustache_parser.erl` | `src/ai_mustache_parser.erl` | 旧 parser，阶段 2 已在 `src/` 重写；bbmustache MIT 版权头随新实现保留 |
| `attic/README.md` | 新增 | attic 自身的说明文件，随目录一并删除 |

补充说明：

- 删除的前置条件是 `attic/README.md` 中「保留理由」已全部失效：`ai_mustache_parser.erl` 的 `split_tag/2` / `standalone/3` / `repeatedly_binary/2` / `part/3` 已由 [T07](T07.md) / [T08](T08.md) 移植完毕，`ai_mustache_runner.erl` 的 section / has / lambda 分派语义已由 [T12](T12.md) 在 `ai_mustache_rt` 中重建。删除前应逐条确认，而不是直接 `rm`。
- 删除方式用 `git rm -r attic`，保证 git 历史可追溯；**不要**只从构建路径里摘掉而留文件在树上。旧逻辑之后通过 git 历史（基线 commit `82c01eb`）追溯即可。
- 注意 `examples/dom_render.erl` 已在阶段 1 被移动到 `attic/dom_render.erl`，因此本任务不需要再单独处理 `examples/` 下的文件；[designs/02 §4](../designs/02-architecture.md) 删除清单中的 `examples/dom_render.erl` 一项由此条覆盖。
- 本任务只删除，不做任何行为改动。如果删除时发现新代码仍在引用 attic 中的函数，说明前置阶段有遗漏，应回到对应任务修复而不是在这里补桥接。

### 2. 构建配置清理

阶段 1 为了「移出构建路径」可能在以下位置留了痕迹，需要一并清掉：

- `rebar.config` 的 `{erl_opts, [{src_dirs, ...}]}` 与各 profile 中不应再出现 `attic`
- `.gitignore` 中若为 attic 加过条目，删除
- `Makefile` / `erlang.mk` 侧若有 `ERLC_EXCLUDE` 之类的排除项，删除
- 确认 `src/aihtml.app.src` 的 `modules` 与 `applications` 中不含 `aihtml_app` / `aihtml_sup` / `ai_dom_*`，且**没有 `mod` 项**（library app，见 [02 §2.4](../designs/02-architecture.md)）
- 根目录 erlang.mk 生成的 `aihtml.d` 若含旧模块的 `COMPILE_FIRST`，重新生成或清空

### 3. 悬空引用检查

删除后必须能证明「没有任何东西还指向被删的模块」：

1. `rebar3 xref` —— 依据 [05 §8](../designs/05-rebar3-plugin.md) 的 `{xref_checks, [undefined_function_calls, locals_not_used, deprecated_function_calls]}`，`undefined_function_calls` 会直接抓出对已删模块的调用。
2. `rebar3 dialyzer` —— `{warnings, [unknown, ...]}` 会报未知模块/函数。
3. 全仓 grep，排除 `.git/` 与 `designs/`（设计文档中对旧实现的引用是历史记录，**不得修改**）：

```
grep -rn -e ai_mustache_loader -e ai_mustache_runner \
        -e aihtml_app -e aihtml_sup -e ai_dom_node -e ai_dom_render \
        -e 'ai_mustache:bootstrap' -e 'ai_mustache:reload' \
        -e 'application:start(aihtml)' -e 'application:start(ailib)' \
        --exclude-dir=.git --exclude-dir=designs --exclude-dir=_build .
```

预期命中数为 0。若 `README.md`、`examples/` 仍有命中（`examples/complex.erl` 目前仍在调 `ai_mustache:bootstrap` 与 `application:start(ailib)`），属于 [T28](T28.md)（examples 重写）与 [T29](T29.md)（README 重写）的范围，在本任务中只记录、不代改，但要在这两个任务完成前不得关闭 T26 的验收（依赖关系上 T29 依赖 T26，因此 README 的清理由 T29 兜底；examples 的清理由 T28 兜底，二者与本任务并行推进）。

### 4. 零依赖复查

决策 D5「彻底移除 ailib」（[02 §6](../designs/02-architecture.md)）在本任务收口：

- `rebar.config` 的 `{deps, []}`，包括 `test` profile 也是空
- `Makefile` 中 `DEPS = ailib` 与 `dep_ailib = ...` 两行删除
- 全仓不再出现 `ai_maps:` / `ai_string:` / `ai_function:` 调用
- `deps/` 目录（若曾 checkout 过）不进版本库

### 5. 架构不变量复查

删除完成后，对照 [02 §7 架构不变量](../designs/02-architecture.md) 逐条自查，作为本阶段的 code review 检查项：

1. 运行期无进程、无 ets、无 persistent_term（`ai_mustache_dev` 例外，见 [T27](T27.md)，且不进 prod profile）
2. `ai_mustache_compiler` 是唯一的 AST → forms 实现
3. 生成模块只依赖 `ai_mustache_rt` 与其它生成模块
4. 生成代码中静态文本全部是字面量
5. 每个生成模块都带 `-mustache_source/1` attribute

具体验证手段：`grep -rn 'ets:\|persistent_term:\|gen_server\|supervisor' src/` 应只在（若存在的）注释中出现。
