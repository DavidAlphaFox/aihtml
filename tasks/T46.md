# T46 · 表达式 codegen

- **阶段**：12
- **依赖**：[T45](T45.md)
- **状态**：已完成

## 目标

把 `expr()` AST 编译成 Erlang abstract expression，含常量折叠与三种静态调用绑定。

## 交付物

- `src/ai_jinja_compiler.erl` —— 表达式编译部分
- `test/ai_jinja_expr_codegen_tests.erl`

## 实现要点

### 1. 逐节点规则

严格按 [11 §3.2](../designs/11-jinja-codegen.md) 的表。要点：

- `{lit, _, V}` → `erl_parse:abstract(V)`，进 literal pool。
- 算术/比较**全部走 `ai_jinja_rt`**，不用 Erlang 原生运算符
  （[11 §3.3](../designs/11-jinja-codegen.md) 的三个理由）。
- `and` / `or` / `cond` 生成 `case`，**左侧只求值一次**：
  ```erlang
  case ai_jinja_rt:truthy(A__ = <A>) of false -> A__; true -> <B> end
  ```
  写成 `case truthy(<A>) of false -> <A>; ...` 会让副作用（filter 调用）执行两次。
- `filter` → `Mod:F(E, ArgsMap)`，Mod 由 registry 在编译期确定。
- `test` → `ai_jinja_tests:T(E, ArgsMap)`，`is not` 包一层 `not`。

### 2. 常量折叠

两侧都是 `{lit, _, _}` 时**调用 `ai_jinja_rt` 的实现**求值
（[11 §3.3](../designs/11-jinja-codegen.md)）。求值抛异常时不折叠，保留原节点。

filter 也可折叠：`{{ "abc"|upper }}` → `<<"ABC">>`。
但**只折叠纯 filter** —— `random` 不是纯函数（[T43](T43.md)），
必须有一张「可折叠 filter」白名单，不能对所有 filter 一视同仁。

### 3. 三种静态调用绑定

[11 §3.4](../designs/11-jinja-codegen.md)：

| f 的来源 | 生成 | 判定依据 |
|---|---|---|
| import 引入的宏 | `j2_m:macro_f(Args, V)` | `#cs.imports` |
| 本模板的宏 | `macro_f(Args, V)` | `#cs.macros` |
| 内置函数 | `ai_jinja_rt:builtin_f(...)` | 内置名表 |
| 其它 | `ai_jinja_rt:call(F, Pos, Kw)` | 兜底 |

判定顺序固定：imports → macros → builtin → 兜底。
**本模板的宏优先于内置**？不 —— 内置名（`range` 等）不允许被宏遮蔽，
parser 层已对遮蔽保留名发 warning，这里内置优先并再发一次 warning。

### 4. 属性访问的三个特例

`.items()` `.keys()` `.values()` 在 compiler 层识别成
`ai_jinja_rt:items/1` / `keys/1` / `values/1`，不走 `attr/2` + `call/3`
（[10 §9](../designs/10-jinja-semantics.md) J13）。

识别形态是 `{call, _, {attr, _, E, items}, {[], []}}`。

### 5. 参数表映射

filter 的位置参数按 `ai_jinja_filters:params/0` 的声明映射成关键字
（[T43](T43.md) §1）。位置参数多于声明 → 编译错误。

### 6. 位置信息

每个生成表达式的 anno 取该 `expr()` 节点的行号（`line_map` 开启时）。
这让运行期异常的堆栈指回模板的正确行。

### 7. 未知 filter / test

编译期查 registry，查不到报 `{unknown_filter, Name}` / `{unknown_test, Name}`，
Loc 指向 filter 名本身（[09 §6](../designs/09-jinja-syntax.md)）。

## 验收标准

- [ ] [11 §3.2](../designs/11-jinja-codegen.md) 每一行都有对应用例
- [ ] `and`/`or`/`cond` 的左侧只求值一次（用带副作用的自定义 filter 计数验证）
- [ ] 源码 grep：生成的 forms 里不出现裸 `{op, _, '+', _, _}` 之类的算术
- [ ] `{{ 1 + 2 }}` 折叠为字面量；`{{ 1 / 0 }}` 不折叠且不在编译期抛出
- [ ] `{{ "abc"|upper }}` 折叠；`{{ x|random }}` 不折叠（白名单生效）
- [ ] 三种静态调用绑定各有用例，且生成的是直接调用而非 `apply/3`
- [ ] `.items()` / `.keys()` / `.values()` 走特例路径
- [ ] filter 位置参数正确映射；多余参数报错
- [ ] 未知 filter/test 报错且 Loc 指向名字本身（`{{ a|f1|nosuch|f3 }}` 的列号断言）
- [ ] `line_map` 开启时生成表达式的行号与模板一致
- [ ] fixture 中 `expr` 组用例全部点亮
