# T17 · 模板编译流程与增量判断

- **阶段**：4
- **依赖**：[T16](T16.md)
- **状态**：已完成

## 目标

实现 `rebar3_aihtml_prv:do/1` 的完整编译流程：扫描模板、按内容 hash 做增量判断、调用 compiler 产出 forms、用 `erl_prettypr` 写出 `.erl` 到 `out_dir`，并顺带完成形态 c 的 staleness 兜底 touch。

## 交付物

- `rebar3_aihtml/src/rebar3_aihtml_prv.erl` —— 补全 `do/1` 的 `process_app/3` 与编译主循环
- `rebar3_aihtml/src/rebar3_aihtml_scan.erl` —— 模板扫描、模板 hash 计算、`-mustache_source` attribute 读取
- `rebar3_aihtml/src/rebar3_aihtml_emit.erl` —— forms → `.erl` 文本的渲染与原子化写盘
- `rebar3_aihtml/src/rebar3_aihtml_stale.erl` —— 扫描 `-mustache_template` 建反向依赖表并 touch（与 [T25](T25.md) 交叉）

## 实现要点

### 1. 主流程

严格照 [05 §3](../designs/05-rebar3-plugin.md) 的流程图：

```
do/1
 ├─ 对每个 app（rebar_state:project_apps/1）
 │   ├─ 读 {mustache_opts, ...}（app 级覆盖 project 级）   ← T16 已实现
 │   ├─ 扫描 views/**/*.mustache
 │   ├─ 模块名映射 + 重名冲突检测                            ← T18
 │   ├─ 对每个模板：hash 判定 → skip 或 编译写盘
 │   ├─ partial 缺失的交叉校验                               ← T18
 │   ├─ 孤儿 .erl 清理                                       ← T18
 │   └─ -mustache_template staleness touch                   ← 本任务 §6
 └─ 返回 {ok, State}
```

本任务负责扫描、hash 判定、编译写盘、staleness touch 四段；模块命名与三项校验/清理在 [T18](T18.md)。

### 2. 模板扫描

- 用 `filelib:wildcard(filename:join(ViewsDir, "**/*" ++ Suffix))` 递归收集，或 `filelib:fold_files/5` 配合正则（后者对 suffix 中的正则元字符更安全，推荐）。
- 结果按路径 `lists:sort/1`，保证编译顺序与错误报告顺序稳定可复现。
- 对每个模板产出 `#tpl{abs_path, rel_path, module, out_path, source_bin, content_hash}`：
  - `rel_path` 是相对 `views_dir` 的路径，用于模块命名与 `-mustache_source` 中的 `path` 字段。
  - `source_bin` 用 `file:read_file/1` 一次读入，后续 hash 与 scanner 共用，避免重复 IO。
- 符号链接、非常规文件跳过；文件读失败按 `{error, {RelPath, 0, {read_failed, Posix}}}` 上报。

### 3. 增量判断 —— 只看 hash，不看 mtime

这是 [05 §3.1](../designs/05-rebar3-plugin.md) 明确的决策，实现时必须遵守：

> 不用 mtime 做判断依据（git checkout、CI 缓存都会打乱 mtime），只用**模板内容 hash + 编译选项 hash + compiler 版本号**三者的组合 hash。读取方式是解析已生成 `.erl` 的 `-mustache_source` attribute，**不需要额外的 cache 文件** —— 生成物自描述。

具体算法 —— **hash 不由 plugin 计算**。[04 §4.1](../designs/04-codegen.md) 把归属定死在 aihtml 侧：

> hash 必须由 **aihtml 侧**导出一个函数，plugin 与 dev 模块都调它：`ai_mustache_compiler:source_hash(Body :: binary(), opts()) -> binary()`。绝不能让 plugin 自己算一份、dev 再算一份 —— 两侧口径一旦漂移，dev 会认为模块永远是陈旧的从而无限重编，而 plugin 会认为永远是新鲜的从而不重编。计算输入固定为：模板内容、规范化后的编译选项、`?COMPILER_VSN` 宏。

所以 plugin 侧只有一行：

```erlang
StampIn = ai_mustache_compiler:source_hash(SourceBin, CompilerOpts).
```

`CompilerOpts` 就是 [T16](T16.md) §6 的 `#mopts.compiler_opts`。plugin 中**不得**出现 `crypto:hash/2`、`term_to_binary/1` 或自定义的版本常量来拼这个 stamp。

判定：

1. 目标 `out_dir/view_x.erl` 不存在 → 编译。
2. 存在 → 读出它的 `-mustache_source` attribute 中的 `hash` 字段（下称 `StampOut`）。
3. `StampIn =:= StampOut` 且未传 `--force` → **skip**（`rebar_api:debug/2` 记一条，不打 info，避免刷屏）。
4. 否则 → 编译并覆写。

要点与边界：

- **`-mustache_source` 中的 `hash` 存的是 `source_hash/2` 的返回值（组合 stamp），不是模板原文 hash。** 语义要在生成的头注释与 README 中写明，避免误读。`mtime` 字段保留（供展示与诊断），但**任何判定逻辑都不得读它**。
- **`opts` 字段是必需的，不是冗余**（[04 §4](../designs/04-codegen.md) 关键点 6）。它让 `ai_mustache_dev`（[T27](T27.md)）能忠实复现 plugin 当初的编译。写入时用相对 app 目录的路径形式（[T16](T16.md) §6），保证 CI 与本地产出同一份字节。
- 读 attribute 的方式：**不要 `compile:file` 也不要加载 beam**，直接 `epp:parse_file/2` 目标 `.erl` 并找 `{attribute, _, mustache_source, Map}`；`epp` 失败（生成物被人手改坏、被截断）时按「需要重编」处理而非报错。更轻量的替代是 `erl_scan` + `erl_parse` 只解析文件头若干 form，遇到第一个函数定义即停止 —— 生成物中 `-mustache_source` 必在文件头，推荐这个走法。
- `--force` 时跳过整个判定，全量重编。

### 4. 编译与写盘

对需要编译的模板：

```
SourceBin --scanner--> Tokens --parser--> AST --后处理--> AST'
        --ai_mustache_compiler:forms(AST', Opts)--> {ok, Forms, Deps}
        --erl_prettypr:format(erl_syntax:form_list(Forms))--> IoList
        --> 写 out_dir/view_x.erl
```

- `Opts` 传给 compiler 的是 [04 §3](../designs/04-codegen.md) 定义的 map：`#mopts.compiler_opts` 加上 per-template 的 `#{module => Mod, source => RelPath}`。同一个 map 也是 `source_hash/2` 的第二参数，保证「用来算 stamp 的选项」与「用来编译的选项」是同一份，不会漂移。
- 生成文件的第一行是 `%% Generated by rebar3_aihtml from views/complex.mustache -- DO NOT EDIT.`（[04 §4](../designs/04-codegen.md)）。`erl_prettypr:format/1` 不保留注释，因此头部注释由 emit 层直接拼字符串前置，而不是塞进 forms。
- `-mustache_source` attribute 由 plugin 侧构造并作为一个 form 插到 `-module` 之后（compiler 只负责语义 forms，attribute 中的 hash 是 plugin 才知道的信息）。也可以由 compiler 接受一个 `source_attr => map()` 选项 —— 二选一，实现时在 compiler 接口文档中明确，避免 plugin 与 parse_transform 两个消费者行为分叉（[架构不变量 #2](../designs/02-architecture.md)）。
- **原子化写盘**：先写 `view_x.erl.tmp`（同目录，保证同一文件系统），再 `file:rename/2`。中途失败不留下半截文件，`rebar3 compile` 也不会读到坏文件。
- 写盘前先比对：若渲染出的文本与已存在文件字节相同，**不写**（避免无谓地改 mtime 触发 rebar3 重编 `.erl`）。这一条在 `--force` 下同样生效。
- `filelib:ensure_dir/1` 保证 `out_dir` 存在。生成物是扁平的（`views/shared/item.mustache` → `_gen/view_shared_item.erl`，不建子目录），与 [05 §4](../designs/05-rebar3-plugin.md) 的命名规则一致。

### 5. partial 不触发父模板重编

[05 §3.2](../designs/05-rebar3-plugin.md) 明确：

> 因为 partial 编译成跨模块调用，**改 partial 不需要重编父模板**。plugin 不需要维护模板依赖图。

因此本任务**明确不实现**任何模板依赖图、不做传递性失效传播。改 `shared/item.mustache` 只会重编 `view_shared_item.erl`，父模板 `view_complex.erl` 的组合 stamp 未变，直接 skip。这是可观测的验收点（见 [T20](T20.md)）。

唯一例外是 partial 从「存在」变「不存在」，交叉校验在 [T18](T18.md)。

### 6. `-mustache_template` staleness 兜底

[05 §6](../designs/05-rebar3-plugin.md) 的兜底机制，与 [T25](T25.md) 交叉（形态 c 在 transform 侧生成函数，依赖跟踪在 plugin 侧补）：

- 扫描该 app 所有源目录（`rebar_dir:src_dirs/2` 得到的目录，含 `src` 与用户配置的 `extra_src_dirs`）下的 `*.erl`，用 `epp:parse_file/2` 或轻量 scan 提取 `-mustache_template({Name, Path})` attribute。为避免对全部源文件跑 epp 的开销，先用 `binary:match/2` 过滤含 `mustache_template` 字面量的文件，再对命中的文件做解析。
- 建反向依赖表 `#{TemplateAbsPath => [ErlAbsPath]}`。同一个 `.erl` 可以有多条 `-mustache_template`，同一模板也可被多个 `.erl` 引用，都是多对多。
- 路径解析顺序照 [06 §4](../designs/06-parse-transform.md)：**模块所在目录 → `{mustache_opts, {views, ...}}` → 编译选项 `i` 路径**。plugin 侧必须复用同一套解析顺序，否则 touch 的目标与 transform 实际读的文件对不上。这段解析逻辑抽成 `rebar3_aihtml_stale:resolve/3`，并在 [T25](T25.md) 中由 transform 侧以相同规则实现（或直接共享一个模块）。
- 判定 staleness：模板内容 hash 与 `.erl` 的关系没有生成物可查（`.erl` 是用户手写的），因此这里**只能**退回到时间戳比较：若模板文件 mtime 新于对应 `.erl` 的 mtime，则 `file:change_time/2` 把 `.erl` 的 mtime 设为当前时间（即 touch），逼 rebar3 重编。
  - 注意这与 §3 「不用 mtime」并不矛盾：§3 说的是**生成物的增量判断**，那里有自描述的 stamp 可用；这里的目标文件是用户手写的 `.erl`，没有地方存 stamp，rebar3 自身的重编触发也是 mtime 驱动的，只能用 mtime。实现中要写注释说明这个区别，防止后来者「统一」掉。
  - touch 只在确实 stale 时做，绝不无条件 touch（否则每次 `rebar3 compile` 都会重编这些模块）。
- 模板路径解析不到时报 `{error, {ErlRelPath, Line, {template_not_found, Path}}}`，Line 取 attribute 所在行。

### 7. 诊断与日志

- 编译一个模板：`rebar_api:debug("mustache: compiling ~s -> ~s", [Rel, OutRel])`。
- skip：`rebar_api:debug(...)`，不用 info。
- 一次 `do/1` 结束打一条 info 汇总：`compiled N, skipped M, cleaned K`（K 来自 [T18](T18.md)）。
- compiler 返回的 `{error, {File, Line, Reason}}` 不要在第一条就 abort：**收集全部模板的错误**，逐条按 erlc 格式打印后再统一失败，否则用户要跑 N 次才能修完 N 个模板。
- `warnings_as_errors` 为真时，warning 计入错误列表。

## 验收标准

- [ ] 首次 `rebar3 mustache` 编译全部模板并在 `_gen/` 产出对应 `.erl`，每个文件带 `DO NOT EDIT` 头注释与含 `path` / `hash` / `mtime` / `vsn` / `opts` 五个字段的 `-mustache_source` attribute
- [ ] stamp 全部来自 `ai_mustache_compiler:source_hash/2`，plugin 代码中无 `crypto:hash` / `term_to_binary` / 自定义版本常量
- [ ] `-mustache_source` 的 `opts` 中不含开发机绝对路径，同一仓库在不同机器上生成的 `.erl` 逐字节相同
- [ ] 连续第二次 `rebar3 mustache` 全部 skip，`_gen/` 下所有文件 mtime 不变
- [ ] 只改模板的空白/内容后重跑，仅该模板对应的 `.erl` 被重写，其余不变
- [ ] `touch` 模板文件（内容不变）后重跑，全部仍 skip —— 证明判定不看 mtime
- [ ] 改 `mustache_opts` 的 `prefix` 或 `line_map` 后重跑，全部模板重编；改 `out_dir` 之外的无关项不触发重编
- [ ] `--force` 忽略 stamp 全量重编，但内容不变的文件不被改写 mtime
- [ ] 改一个 partial 后重跑，**只有该 partial 的 `.erl` 被重写**，引用它的父模板 `.erl` 未被触碰
- [ ] 手工把生成的 `.erl` 改坏（截断/删掉 attribute）后重跑，能自动重新生成而不是崩溃
- [ ] 含 `-mustache_template` 的模块：修改其模板后重跑，该 `.erl` 的 mtime 被更新；模板未变时 mtime 不变
- [ ] 多个模板同时有语法错误时，一次运行能报出全部错误，格式为 `views/x.mustache:12: unclosed tag {{#items}}`
- [ ] 写盘中途失败（可用只读目录模拟）不留下 `.tmp` 残留或半截 `.erl`
