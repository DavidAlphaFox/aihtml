# T33 · ai_html_engine behaviour 与 mustache 适配壳

- **阶段**：7
- **依赖**：[T32](T32.md)
- **状态**：已完成

## 目标

定义 `ai_html_engine` behaviour，让 plugin 与 dev 模块面向它编程；提供 `ai_mustache_engine` 适配壳，且不改动 mustache 核心模块的任何逻辑。

## 交付物

- `src/ai_html_engine.erl` —— behaviour 定义
- `src/ai_mustache_engine.erl` —— 适配壳
- `include/ai_html.hrl` —— 两引擎共用的类型（`loc()` · `path()` · error 外壳）
- `test/ai_html_engine_tests.erl`

## 实现要点

### 1. behaviour

```erlang
-callback parse(binary(), map()) -> {ok, term()} | {error, term()}.
-callback forms(term(), map()) ->
    {ok, [erl_parse:abstract_form()], [module()]} | {error, term()}.
-callback source_hash(binary(), map()) -> binary().
-callback module_name(binary(), map()) -> module().
-callback attribute() -> atom().
-callback default_suffix() -> string().
-callback default_prefix() -> binary().
-callback config_key() -> atom().        %% mustache_opts | jinja_opts
-callback known_keys() -> [atom()].
-callback banner_tag() -> string().      %% "mustache" | "jinja"，孤儿清理用
```

`parse/2` 与 `forms/2` 之间传递的 AST 是**引擎私有的 term**，
behaviour 只承诺「parse 的输出可以喂给 forms」，不对形状作任何约定。
这一点要写进 module doc，否则后来者会想去抽象 AST。

### 2. `ai_mustache_engine`

全部一行转发：

```erlang
parse(B, O)        -> ai_mustache_parser:parse(B, O).
forms(A, O)        -> ai_mustache_compiler:forms(A, O).
source_hash(B, O)  -> ai_mustache_compiler:source_hash(B, O).
module_name(N, O)  -> ai_mustache_ast:module_name(N, O).
attribute()        -> mustache_source.
default_suffix()   -> ".mustache".
default_prefix()   -> ai_mustache_ast:default_prefix().
config_key()       -> mustache_opts.
known_keys()       -> ?R3A_MUSTACHE_KEYS.
banner_tag()       -> "mustache".
```

`known_keys/0` 需要 plugin 侧的宏，而 `ai_mustache_engine` 在 aihtml 主应用里 ——
不能 include plugin 的 hrl。做法：把键表定义在 `include/ai_html.hrl`，plugin 侧引用它。
键表本就是「引擎支持哪些配置」的声明，属于引擎而非 plugin。

### 3. `include/ai_html.hrl`

只放两引擎真正共用的东西：

```erlang
-type ai_html_loc()  :: {pos_integer(), pos_integer()}.
-type ai_html_path() :: binary().
-type ai_html_error(Reason) :: {error, {ai_html_path(), pos_integer(), Reason}}.
```

**不要**把 mustache 的 `ai_mustache_node()` 之类搬进来。共享 hrl 一旦开始装
引擎特有的类型，就会变成第二个「什么都往里塞」的头文件。

## 验收标准

- [ ] `ai_html_engine` 只定义 callback，无函数实现
- [ ] `ai_mustache_engine` 全部为一行转发，无任何逻辑
- [ ] `ai_mustache_engine` 通过 `behaviour_info` 校验（`-behaviour(ai_html_engine).` 编译无 warning）
- [ ] `include/ai_html.hrl` 不含任何引擎特有类型
- [ ] mustache 核心模块（scanner/parser/ast/compiler/rt）**零改动**（`git diff` 为空）
- [ ] 全套检查全绿
