## 目标

搭起 compiler 的状态机与模块组装，落地 [11 §2](../designs/11-jinja-codegen.md) 的生成模块契约。本任务只做骨架与纯静态模板，动态节点由 T46–T50 逐个点亮。

## 实现要点

### 1. 状态

```erlang
-record(cs, {opts, file, line_map, counter, aux,
             scope_var  :: atom(),      %% 当前作用域变量名 'V0' / 'V1' ...
             bol        :: boolean(),   %% 是否处于行首（缩进用）
             registry   :: map(),       %% T44 的 filter/test 注册表
             ext_remotes = [] :: [module()],
             parent     :: module() | undefined,   %% {% extends %} 的目标
             blocks     = [] :: [{atom(), atom()}],%% {Name, FunName}
             macros     = [] :: [{atom(), atom()}],
             imports    = [] :: [{atom(), module()}],
             inline     = false :: boolean()}).
```

### 2. body 编译是 fold 不是 map

[11 §1](../designs/11-jinja-codegen.md) 的核心差异：

```erlang
-spec body_exprs([jinja_node()], atom(), state()) ->
        {[erl_parse:abstract_expr()], atom(), state()}.
```

每个节点吃进当前作用域变量名，吐出表达式列表与**新的**作用域变量名。
只有 `set` / `set_block` 推进它；其余原样返回。

**这一条决定了整个 compiler 的形状**，必须在骨架阶段就定下来，
后面所有 node 的实现都遵循这个签名。

### 3. 模块组装

按 [11 §2](../designs/11-jinja-codegen.md) 生成八个导出：
`render/1` `render_iolist/1` `render_scope/2` `render_with/3`
`blocks/0` `all_blocks/0` `partials/0`，加上 `block_*/3` 与 `macro_*/2`。

无父模板时 `all_blocks() -> blocks().`；有父模板时
`all_blocks() -> maps:merge(Parent:all_blocks(), blocks()).`
（[11 §5.1](../designs/11-jinja-codegen.md)）。

### 4. `-jinja_source` attribute

与 mustache 的 `-mustache_source` 同形，attribute 名为 `jinja_source`。
`opts` 字段来自 `normalize_opts/1`。

### 5. `source_hash/2` 与 `normalize_opts/1`

**唯一的 stamp 计算点**（mustache 侧 [04 §4.1](../designs/04-codegen.md) 的教训）。

`normalize_opts/1` 纳入：`prefix` `extensions` `escape` `trim_blocks`
`lstrip_blocks` `keep_trailing_newline` `strict_undefined` `line_map`。

**排除**：`suffix`（只喂存在性检查）、`views_abs`（绝对路径会把开发者的
home 目录写进产物，破坏可复现构建）、`views`（同 mustache 侧的理由）。

值先过 `ai_html_text:opts/1`，保证 string 与 binary 算出同一个 stamp。

### 6. 常量折叠：全静态模板

模板无任何动态节点时，`render/1` 直接返回一个字面量
（复用 `ai_html_forms` 的 `literal_of/1`，[T31](T31.md)）。
`render_with/3` 不折叠 —— 它可能被继承链调用，要保留 block 分派。

### 7. `check_remotes`

允许集合：`erlang` · `ai_jinja_rt` · `ai_jinja_filters` · `ai_jinja_tests`
· `ai_html_escape` · Deps（partials）· 父模板 · registry 的 `modules`。

违规是 compiler 自身的 bug，报 `{unexpected_remote_calls, Mods}`。

### 8. `ai_jinja_engine`

一行转发，`attribute() -> jinja_source`，`default_prefix() -> <<"j2_">>`，
`default_suffix() -> ".j2"`，`config_key() -> jinja_opts`，`banner_tag() -> "jinja"`。

## 验收标准

- [ ] `body_exprs/3` 的签名为 fold 形态（三元返回），所有 node 实现遵循
- [ ] 纯静态模板生成的模块通过编译，`render/1` 返回字面量
- [ ] 八个导出齐全，`-jinja_source` attribute 存在且字段完整
- [ ] `all_blocks/0` 在有/无父模板两种情况下形态正确
- [ ] `source_hash/2` 是唯一的 stamp 计算点（源码 grep 确认无第二处 `erlang:md5`）
- [ ] `normalize_opts/1` 纳入五个 Jinja 布尔选项；改任一个都触发 stamp 变化（逐项用例）
- [ ] `views_abs` 不影响 stamp（专项用例：两个不同绝对路径产出同一 stamp）
- [ ] `views` 传 string 与 binary 产出同一 stamp
- [ ] `check_remotes` 的白名单正确，故意注入一个非法调用能被抓到
- [ ] `ai_jinja_engine` 通过 `-behaviour(ai_html_engine)` 校验
- [ ] 生成模块能过 `warnings_as_errors`
