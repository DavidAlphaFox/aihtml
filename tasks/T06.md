# T06 · AST 定义与公共头文件

- **阶段**：2
- **依赖**：[T01](T01.md)
- **状态**：已完成

## 目标

定义新 AST 的全部类型与共享常量，落地为 `include/ai_mustache.hrl`，让 scanner、parser、compiler、rebar3 plugin、parse_transform 五方共用同一份数据契约。

## 交付物

- `include/ai_mustache.hrl` —— AST 节点类型、token 类型、编译选项、错误类型、内置 marker 表与版本常量

## 实现要点

### 1. 基础类型

按 [designs/04-codegen.md §1](../designs/04-codegen.md) 落地，但**必须改名规避 Erlang 内置类型冲突**：

```erlang
-type ai_mustache_key()  :: atom().
-type ai_mustache_keys() :: [ai_mustache_key()].
-type ai_mustache_loc()  :: {Line :: pos_integer(), Col :: pos_integer()}.
```

> 设计文档写的是 `-type node() :: ...`。`node()` 是 Erlang **内置类型**，`-type node()` 会被编译器直接拒绝（`type node() is a builtin type; it cannot be redefined`）。头文件里统一改用 `ai_mustache_node()`，并在模块内部按需 `-type node_() :: ai_mustache_node()` 局部别名。

### 2. AST 节点

```erlang
-type ai_mustache_node() ::
      {text,     ai_mustache_loc(), binary()}
    | {var,      ai_mustache_loc(), ai_mustache_keys(), escape | raw}
    | {section,  ai_mustache_loc(), ai_mustache_keys(), [ai_mustache_node()]}
    | {inverted, ai_mustache_loc(), ai_mustache_keys(), [ai_mustache_node()]}
    | {has,      ai_mustache_loc(), ai_mustache_keys(), [ai_mustache_node()], boolean()}
    | {lambda,   ai_mustache_loc(), ai_mustache_keys()}
    | {partial,  ai_mustache_loc(), Name :: binary(), Indent :: binary()}
    | {ext,      ai_mustache_loc(), Marker :: char(), ai_mustache_keys(), [ai_mustache_node()]}.
```

关键约定，实现时不得偏离：

- `{partial, ...}` 的 `Name` 是 **binary 原始路径**（如 `<<"shared/item">>`、`<<"layout.default">>`），**不是** `keys()`。这是修 [B4](../designs/01-current-state.md) 的前提：旧 parser 对 partial 也跑 `keys/1` 并只匹配单元素列表，带点路径必然 `function_clause`。
- `{partial, ...}` 的 `Indent` 是结构化字段，而非像旧实现那样把缩进当普通文本插在 partial 前面（旧行为只缩进第一行，不符合 spec，见 [designs/03-semantics.md §6](../designs/03-semantics.md)）。非 standalone partial 的 `Indent` 为 `<<>>`。
- `{has, _, _, _, Positive}` 中 `Positive = true` 对应 `{{+x}}`，`false` 对应 `{{-x}}`。
- `{ext, ...}` 的 `Body` 对行内扩展为 `[]`，块级扩展为子节点列表（见 [designs/06-parse-transform.md §2.1](../designs/06-parse-transform.md)）。
- `{var, _, Keys, escape | raw}`：`{{x}}` 是 `escape`，`{{{x}}}` 与 `{{&x}}` 都是 `raw`。

### 3. 隐式迭代器的表示

`{{.}}` 解析为 `{var, Loc, ['.'], escape}`，即 keys 恰好是单元素 `['.']`。这个哨兵值由 `ai_mustache_rt:lookup/2` 识别并返回 `hd(Stack)`（见 [T11](T11.md)），修掉 [B5](../designs/01-current-state.md)。头文件用宏固化，避免各处硬编码：

```erlang
-define(AI_MUSTACHE_DOT, '.').
```

### 4. scanner → parser 的 token 契约

token 类型也放在头文件里，作为 [T07](T07.md) 与 [T08](T08.md) 之间的唯一接口：

```erlang
-type ai_mustache_marker() :: none | char().   %% $#  $^  $/  $>  $&  ${  $!  $=  $+  $-  $*  或扩展字符

-type ai_mustache_token() ::
      {text, ai_mustache_loc(), binary()}
    | {tag,  ai_mustache_loc(), ai_mustache_marker(),
             Content :: binary(),          %% 已去掉 marker、已去首尾空白的 tag 内容
             Indent  :: binary()}.         %% standalone 时该行缩进，否则 <<>>
```

`{{=<% %>=}}` 由 scanner 内部消费掉、不产出 token（分隔符切换是词法层状态，parser 不该感知）。

### 5. 内置 marker 与扩展冲突检测

```erlang
-define(AI_MUSTACHE_BUILTIN_MARKERS, [$#, $^, $/, $>, $!, $=, $&, ${, $}, $+, $-, $*]).
```

扩展模块注册的 marker 与该集合相交时报编译错误（[designs/06-parse-transform.md §2.4](../designs/06-parse-transform.md)）。冲突检测的实现在 plugin / transform 侧，但**字符集合的唯一定义源在本头文件**。

### 6. 编译选项与错误类型

```erlang
-type ai_mustache_opts() :: #{
    module     := module(),
    source     := file:filename_all(),
    prefix     => binary(),                 %% 默认 <<"view_">>
    views      => file:filename_all(),
    extensions => [module()],
    line_map   => boolean()                 %% 默认 true
}.

-type ai_mustache_reason() ::
      {unclosed_tag, ai_mustache_keys()}
    | {mismatched_close, Expected :: ai_mustache_keys(), Got :: ai_mustache_keys()}
    | {partial_not_found, binary()}
    | {unknown_marker, char()}
    | {invalid_delimiter, binary()}
    | {partial_cycle_depth, [module()]}.

-type ai_mustache_error() :: {error, {File :: binary(), Line :: pos_integer(),
                                      ai_mustache_reason()}}.
```

错误 tuple 的形状必须与 [designs/04-codegen.md §7](../designs/04-codegen.md) 完全一致，plugin 侧才能格式化成 `views/index.mustache:12: unclosed tag {{#items}}` 这种 erlc 风格诊断。

### 7. 默认分隔符与编译器版本

```erlang
-define(AI_MUSTACHE_START, <<"{{">>).
-define(AI_MUSTACHE_STOP,  <<"}}">>).
-define(AI_MUSTACHE_VSN,   1).      %% 生成代码形态的版本号
```

`?AI_MUSTACHE_VSN` 参与 `-mustache_source` attribute 的 `vsn` 字段与 `ai_mustache_compiler:source_hash/2` 的输入（[designs/04-codegen.md §4.1](../designs/04-codegen.md)、[designs/05-rebar3-plugin.md §3.1](../designs/05-rebar3-plugin.md)）；compiler 生成形态一变就要 bump，否则旧生成物不会被重编。

hash 的**唯一计算入口**是 `ai_mustache_compiler:source_hash/2`，plugin 与 dev 都只调它、不得自行实现 —— 两侧口径一旦漂移，dev 会认为模块永远陈旧从而无限重编，plugin 会认为永远新鲜从而不重编。本头文件只提供版本宏，算法在 compiler 侧（[T13](T13.md)）。

### 8. `-mustache_source` attribute 的形状

头文件中以类型 + 注释固化，供 plugin 增量判断与 `ai_mustache_dev` 热重载读取（[架构不变量 #5](../designs/02-architecture.md)）：

```erlang
-type ai_mustache_source() :: #{
    path  := binary(),
    hash  := binary(),
    mtime := integer(),
    vsn   := pos_integer(),
    opts  := map()            %% 规范化后的编译选项
}.
```

**`opts` 字段是必需的，不是冗余**（[designs/04-codegen.md §4 关键点 6](../designs/04-codegen.md)）：增量判断算的是「内容 + 编译选项 + compiler 版本」的组合 hash，dev 热重载（T27）又要忠实复现 plugin 当初的编译，二者都需要 `views` / `prefix` / `extensions` / `line_map`。缺了它，改 `mustache_opts` 不会触发重编，dev 重编出来的模块也会和 plugin 产物不一致。

### 9. 卫生要求

- 头文件用 `-ifndef(AI_MUSTACHE_HRL)` / `-define` / `-endif` 包裹，允许重复 include。
- 头文件中**只放类型、宏、注释**，不放函数、不放 record 以外的可执行内容。
- 若确需 record（如 scanner 内部状态），放到 `ai_mustache_scanner.erl` 模块内，不要污染公共头文件 —— 公共头文件是对外契约，plugin 与用户扩展模块都会 include 它。

## 验收标准

- [ ] `include/ai_mustache.hrl` 存在，`rebar3 compile` 通过，无 `builtin type` 冲突告警
- [ ] 定义了 `ai_mustache_key/0`、`ai_mustache_keys/0`、`ai_mustache_loc/0`、`ai_mustache_node/0`、`ai_mustache_token/0`、`ai_mustache_marker/0`、`ai_mustache_opts/0`、`ai_mustache_reason/0`
- [ ] 八种 AST 节点全部覆盖，且 `{partial, ...}` 的 Name 字段类型是 `binary()` 而非 `[atom()]`
- [ ] 定义了 `?AI_MUSTACHE_START` / `?AI_MUSTACHE_STOP` / `?AI_MUSTACHE_DOT` / `?AI_MUSTACHE_VSN` / `?AI_MUSTACHE_BUILTIN_MARKERS`
- [ ] 定义了 `ai_mustache_source/0`，含 `path` / `hash` / `mtime` / `vsn` / `opts` 五个必需键
- [ ] 头文件有 include guard，重复 include 不报错
- [ ] `rebar3 dialyzer` 对引用这些类型的模块无 `unknown_type` 告警
- [ ] 头文件不含任何函数定义
