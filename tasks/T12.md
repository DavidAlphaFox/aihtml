# T12 · ai_mustache_rt 转义与分派

- **阶段**：3
- **依赖**：[T01](T01.md)
- **状态**：已完成

## 目标

实现 `escape/1` 的单遍扫描（修 [B3](../designs/01-current-state.md) 并收窄字符集），以及生成代码兜底用的 `section/4` 与 `lambda/2` 分派函数，落地 [designs/03-semantics.md §3](../designs/03-semantics.md) 的 section 分派表。

## 交付物

- `src/ai_mustache_rt.erl` —— 本任务负责 `escape/1`、`section/4`、`lambda/2` 三个导出（`lookup/2`、`to_binary/1`、`truthy/1` 见 [T11](T11.md)）

## 实现要点

### 0. 零依赖

与 [T11](T11.md) 同一模块，同一约束：只依赖 OTP，禁止 `ai_string:html_escape/1`（决策 D5，[designs/02-architecture.md §6](../designs/02-architecture.md)）。

### 1. `escape/1` —— 字符集收窄

**新转义表**（[designs/04-codegen.md §5.1](../designs/04-codegen.md)）：

| 字符 | 替换 |
|---|---|
| `&` | `&amp;` |
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;` |
| `'` | `&#39;` |

**两处行为变更，都要写进 README 的 Incompatible Changes（阶段 6）**：

1. **修掉 `&amp` 缺分号** —— ailib 的 `ai_string.erl:12` 是 `{"\\&", "\\&amp"}`，产出 `&amp` 而非 `&amp;`，这是 [B3](../designs/01-current-state.md) 的正确性部分。新表必须带分号。
2. **移除 `/`、`=`、反引号三个字符的转义** —— 旧实现把它们也转义，会破坏 URL（`href="/a/b"` → `href="&#x2F;a&#x2F;b"`）与普通文本。标准 mustache 只要求上表五个。

`&` 必须是替换表里**第一个被考虑的字符**在语义上没有意义（单遍扫描逐字节判定，不存在旧实现那种「多遍 re:replace 导致二次转义」的顺序陷阱）—— 但这正是单遍扫描相对 8 遍 `re:replace` 的又一个正确性收益，值得在注释里记一笔。

### 2. `escape/1` —— 单遍扫描实现

[B3](../designs/01-current-state.md) 的性能部分：旧实现对每个变量做 **8 遍 `re:replace` 全局扫描**，是渲染热路径上最贵的单点。

```erlang
-spec escape(term()) -> iodata().
escape(B) when is_binary(B) -> escape(B, B, 0, 0, []);
escape(V) -> escape(to_binary(V)).
```

五参数版本的语义：`escape(Bin, Bin, SegStart, Pos, Acc)` —— `Bin` 全量、`SegStart` 当前未转义片段的起点、`Pos` 当前偏移、`Acc` 反序 iolist。

关键性质：

- **无需转义时零拷贝返回原 binary**。扫到末尾且 `Acc =:= []` 且 `SegStart =:= 0` → 直接返回 `Bin` 本身，不做任何分配。绝大多数模板变量（用户名、数字、路径）都走这条路径。
- **需要转义时用 `binary:part/3` 切片 + iolist 拼接**，不做逐字节 append。命中一个特殊字符时把 `binary:part(Bin, SegStart, Pos - SegStart)` 与替换字面量一起压进 `Acc`，`SegStart := Pos + 1`。
- **返回 `iodata()` 而非 `binary()`**。生成代码产出的就是 iolist，最外层才 `iolist_to_binary/1`（[designs/02-architecture.md §5](../designs/02-architecture.md)：`render_iolist/1` 可直接喂 cowboy `Body`）。这也是修 [P4](../designs/01-current-state.md) 的一部分 —— 旧 runner 全程 `<<Acc/binary, X/binary>>`，且 `run_section/7` 与 lambda 分支会重起累加器打断 ERTS 的尾部追加优化。
- 逐字节匹配用 `binary:at/2` + `case`，或直接对 `<<C, Rest/binary>>` 做子句匹配。前者省一次子 binary 构造，后者可读性好；实测选一个，在注释里记录基准数据。
- **不做 unicode 解码** —— 五个待转义字符都是 ASCII，UTF-8 多字节序列的续字节都 ≥ 0x80，不会误命中。逐字节扫描对 UTF-8 是安全的。

`escape/1` 的非 binary 入参先过 `to_binary/1`（[T11](T11.md)），因此 `{{x}}` 中 `x` 为 `undefined` 时输出 `<<>>`。

### 3. `section/4` —— 分派兜底

```erlang
-spec section(Value :: term(), Body :: fun(([term()], binary()) -> iodata()),
              Stack :: [term()], Indent :: binary()) -> iodata().
```

生成代码把 [designs/04-codegen.md §4](../designs/04-codegen.md) 的 case 分支**在编译期全部展开**（关键点 5：无运行期查表、无 apply）：

```erlang
sec_1(S, I) ->
    case ai_mustache_rt:lookup([items], S) of
        []                       -> [];
        L when is_list(L)        -> [sec_1_body([E | S], I) || E <- L];
        M when is_map(M)         -> sec_1_body([M | S], I);
        true                     -> sec_1_body(S, I);
        F when is_function(F, 2) -> F(erlang:iolist_to_binary(sec_1_body(S, I)), hd(S));
        F when is_function(F, 1) -> ai_mustache_rt:section(F(hd(S)), fun sec_1_body/2, S, I);
        V                        -> ai_mustache_rt:section(V, fun sec_1_body/2, S, I)
    end.
```

`section/4` 因此只需要处理**兜底的两条路径**：

1. `fun/1` 的返回值 —— 需要按分派表**递归**（支持惰性求值，`fun/1` 可以返回一个 list、map 甚至另一个 fun）。
2. 其余标量值 `V`。

完整分派表（[designs/03-semantics.md §3](../designs/03-semantics.md)）：

| `V` | 行为 |
|---|---|
| falsy（`undefined` / `false` / `[]` / `<<>>` / `null`） | 返回 `[]`，不执行 |
| 非空 list | 每个元素**压栈**迭代：`[Body([E \| S], I) \|\| E <- L]` |
| map | **压栈**执行一次：`Body([M \| S], I)` |
| `true` | 执行一次，**不压栈**：`Body(S, I)` |
| `fun/2` | `F(iolist_to_binary(Body(S, I)), hd(S))` |
| `fun/1` | `section(F(hd(S)), Body, S, I)` —— 递归分派 |
| 其它（binary / number / atom） | 执行一次，**压栈**：`Body([V \| S], I)` |

**关键陷阱**：`<<>>` 是 falsy 但生成代码的 case 里没有它的显式分支（它会落到兜底的 `V` 子句），所以 **`section/4` 必须先判 falsy**，否则空 binary 会被压栈执行 body。同理 `false` / `undefined` / `null`。子句顺序：falsy 五个 → `is_list` → `is_map` → `true` → `is_function/2` → `is_function/1` → 兜底。

**`fun/1` 递归的深度保护**：`fun/1` 返回另一个 `fun/1` 会无限递归。加一个内部深度计数（比如 16 层），超限 `error({ai_mustache, {lambda_depth_exceeded, ...}})`。

**`hd(S)` 而非整个栈**：lambda 收到的是**栈顶 frame**，不是旧的扁平全局 Ctx。这是语义变更，[designs/03-semantics.md §5](../designs/03-semantics.md) 已标注 —— 需要访问根 context 的 lambda 应改用 `fun/2` 显式传值，或注册自定义 ext tag。

**lambda 返回值不做二次模板解析**（[designs/03-semantics.md §8](../designs/03-semantics.md) 的 known deviation）：spec 的 Lambdas 可选模块要求返回值再解析一遍，编译期方案下代价过高，不实现。

### 4. `inverted` 与 `has` 的分派

`{{^x}}` 与 `{{+x}}` / `{{-x}}` 的分派在生成代码里直接展开，不需要额外的 rt 函数：

- `{{^x}}`：`case ai_mustache_rt:truthy(V) of false -> Body(S, I); true -> [] end` —— **永不压栈**。
- `{{+x}}`：`fun/1` 时先 `F(hd(S))` 再判 truthy；其余直接判 truthy。**不压栈不迭代**（[designs/03-semantics.md §4](../designs/03-semantics.md)：`{{+}}` 是 if，`{{#}}` 是 with/for）。
- `{{-x}}`：`{{+x}}` 取反。

若实现中发现生成代码为此产出大量重复 forms，可以补一个 `has/2` 辅助函数（`has(V, Frame) -> boolean()`），但要在 [T13](T13.md) 中同步更新 rt 的导出清单与架构不变量 #3 的检查项。

### 5. `lambda/2`

```erlang
-spec lambda(Value :: term(), Frame :: term()) -> iodata().
lambda([F, V], _Frame) when is_function(F, 2) -> F(V, _Frame);
lambda(F, Frame)       when is_function(F, 1) -> F(Frame);
lambda(F, Frame)       when is_function(F, 2) -> F(<<>>, Frame);
lambda(undefined, _)                          -> [];
lambda(V, _)                                  -> ai_mustache_rt:to_binary(V).
```

对应 `{{*f}}`（aihtml 扩展，[designs/03-semantics.md §5](../designs/03-semantics.md)）的两种形态：

- `#{yield => fun(Frame) -> ... end}` —— `fun/1`，收当前 frame
- `#{yield => [fun render_layout/2, <<"index">>]}` —— `[Fun, Value]`，调 `Fun(Value, Frame)`

**返回值必须是 `binary()` 或 `iolist()`，且不做转义** —— lambda 的用途就是产出 HTML。要在 spec 与文档中写明这一点：`{{*f}}` 的输出**不经过 `escape/1`**。

`undefined` 返回 `[]`（旧 runner 是跳过该指令，行为一致）。

### 6. 性能与不变量

- `escape/1` 是最热的函数，避免任何 `re` 模块调用、避免 `lists:foldl/3`、避免构造中间 binary。
- 全模块无进程、无 ets、无 persistent_term、无进程字典（[架构不变量 #1](../designs/02-architecture.md)）。
- `ai_mustache_rt` 不得反向依赖 `ai_mustache_compiler` / `ai_mustache_parser` 等任何 aihtml 模块（[架构不变量 #3](../designs/02-architecture.md)）。

## 验收标准

- [ ] `escape/1`、`section/4`、`lambda/2` 导出，模块只依赖 OTP，源码 grep 不到 `re:replace`
- [ ] `escape(<<"&">>)` 返回 `&amp;`（**带分号**，B3 正确性修复）
- [ ] `escape/1` 转义且仅转义 `& < > " '` 五个字符
- [ ] `escape(<<"/a/b=c`d">>)` 原样返回（`/`、`=`、反引号不再被转义，B3 行为变更）
- [ ] 无需转义时 `escape/1` 返回的就是入参 binary 本身，无拷贝
- [ ] `escape/1` 对 UTF-8 多字节字符（中文、emoji）原样透传不损坏
- [ ] `escape/1` 返回 `iodata()`，生成代码可直接嵌入 iolist
- [ ] `section/4` 对 falsy 五个值全部返回 `[]`，不执行 body（特别是 `<<>>` 与 `false`）
- [ ] `section/4` 对非空 list 逐元素压栈，对 map 压栈一次，对 `true` 不压栈，对标量压栈一次
- [ ] `section/4` 的 `fun/1` 返回值递归分派，返回 list 时逐元素压栈
- [ ] `fun/1` 无限嵌套时报 `{lambda_depth_exceeded, _}` 而非栈溢出
- [ ] `fun/2` 收到的第一个参数是 `binary()`（已 `iolist_to_binary/1`），第二个是 `hd(Stack)`
- [ ] `lambda/2` 支持 `fun/1` 与 `[Fun, Value]` 两种形态，返回值不经转义
- [ ] 模块无进程、无 ets、无 persistent_term、无进程字典
- [ ] `rebar3 dialyzer` 与 `rebar3 xref` 全绿
