# T48 · extends / block / super codegen

- **阶段**：12
- **依赖**：[T47](T47.md)
- **状态**：已完成

## 目标

落地模板继承，且保住「一个模块的 forms 里只出现直接父模板」这条增量粒度不变量。

## 交付物

- `src/ai_jinja_compiler.erl` —— 继承部分
- `test/ai_jinja_inherit_tests.erl`
- `test/fixtures/jinja_inherit/` —— 多级继承的端到端小项目

## 实现要点

### 0. 这是本轮最关键的一个任务

「接近全量」这个范围选择的核心理由就是继承。同时它也是唯一一处
**架构不变量可能被悄悄破坏**的地方（[08 §5](../designs/08-jinja-architecture.md) 不变量 9）。

### 1. 生成形态

```erlang
%% 子模板 j2_page：{% extends "base.j2" %}
all_blocks()          -> maps:merge(j2_base:all_blocks(), blocks()).
render_with(V, I, B)  -> j2_base:render_with(V, I, B).
blocks()              -> #{title => fun ?MODULE:block_title/3}.
block_title(V, I, B)  -> [ ... ].

%% 父模板 j2_base 中 {% block title %}默认{% endblock %} 的调用点：
(maps:get(title, B, fun ?MODULE:block_title/3))(V, I, B)
```

`render_with/3` 把控制权完全交给父模板；子模板自己的顶层文本被丢弃
（Jinja2 语义，parser 已对此发 warning）。

### 2. 为什么不在编译期展平 block 表

[11 §2.1](../designs/11-jinja-codegen.md)：展平成字面量后，改动祖父模板的
block 集合就必须重编整条继承链，增量粒度退化。

**这条要有可观测的验收**：三级继承 `a extends b extends c`，
改 `c` 的 block 内容后重新构建，`a` 与 `b` 的 `.erl` 不得被重写
（对比 mtime 或内容 hash）。

### 3. `super()`

编译成对**直接父模板**同名 block 函数的调用：`j2_base:block_title(V, I, B)`。

多级继承时逐级向上自然成立：孙的 super 调子，子的 super 调父。
**三级继承 + 每级都调 super** 要有专项用例 —— 这是最容易写错成
「调到最顶层」或「无限递归」的地方。

`super()` 出现在非 block 上下文 → 编译错误 `{super_outside_block, Loc}`。

### 4. `scoped`

[11 §5.2](../designs/11-jinja-codegen.md)：因为 `V` 本来就是整条作用域链传进 block，
**`scoped` 在本实现里是默认行为**。`{% block x scoped %}` 与不带 `scoped` 生成相同代码。

记入差异清单（比参照实现宽松，不会让合法模板失败）。要有一条 fixture
标 `deviation` 说明这一点。

### 5. `required`

父模板中声明 `required` 的 block，若继承链下游没有实现 → **运行期**错误。
编译期无法判断（不知道谁会继承自己）。

落地：`block_x/3` 的默认实现体就是
`erlang:error({ai_jinja, {required_block_not_provided, x}})`。

### 6. 循环继承

`{% extends %}` 自环在 [T40](T40.md) 已检测。
**互相继承**（a extends b，b extends a）在单模板编译时看不出来 ——
compiler 只知道直接父模板。这属于 plugin 的跨模板校验，
在 [T52](T52.md) 里做（构建 extends 图并查环）。本任务只需在注释里指明分工。

### 7. `partials/0`

父模板要进依赖列表，供 plugin 的反向依赖表使用。

## 验收标准

- [ ] 单级继承：子模板覆盖 block，父模板的其余内容照常输出
- [ ] 未覆盖的 block 用父模板的默认实现
- [ ] 三级继承正确，每级的 block 覆盖按「最下游优先」生效
- [ ] 三级继承 + 每级 `super()` 正确逐级向上，不递归不跳级
- [ ] `super()` 在非 block 上下文报 `{super_outside_block, Loc}`
- [ ] **增量粒度验收**：改祖父模板的 block 内容后重建，子与孙的 `.erl` 未被重写
- [ ] **不变量 9 验收**：子模板生成的 forms 里只出现直接父模板的模块名（遍历 forms 断言）
- [ ] `scoped` 与不带 `scoped` 生成相同代码，且有 `deviation` fixture
- [ ] `required` block 未实现时运行期报明确错误
- [ ] 父模板进 `partials/0`
- [ ] 生成模块能过 `warnings_as_errors` 与 `dialyzer`
- [ ] fixture 中 `inherit` 组用例全部点亮
