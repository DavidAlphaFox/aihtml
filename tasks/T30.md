# T30 · 基准测试

- **阶段**：6
- **依赖**：[T26](T26.md)
- **状态**：已完成

## 目标

建立可复现的渲染基准，与重构前的 v0.3.7 对比吞吐与内存分配，验证「编译成 BEAM 模块」相对「ets 缓存 + 解释执行」的预期收益，并把结果写入 README 的 benchmark 段落。

## 交付物

- `bench/ai_mustache_bench.erl` —— 基准驱动，含预热、多轮取中位数、单进程与并发两种模式
- `bench/tpl/` —— 基准模板集（新语义版本）与其 v0.3.7 旧语义对照版本
- `bench/ctx.erl` —— 基准数据构造（三种规模）
- `bench/run.sh` —— 一键跑通：准备 v0.3.7 独立 checkout、跑两侧、输出对比表
- `bench/README.md` —— 跑法说明与结果解读（这是基准自己的说明，不算额外文档）
- `README.md` 的 benchmark 段落回填（段落骨架由 [T29](T29.md) 建立）

## 实现要点

### 1. 对照基线：v0.3.7 必须在独立 checkout 里跑

关键约束：**v0.3.7 依赖 ailib，而 ailib 已按决策 D5 彻底移除**（[designs/README.md](../designs/README.md) D5、[07 原则](../designs/07-roadmap.md)「旧代码在新构建下根本编译不过」）。因此不能在当前工作树里同时跑新旧两版，必须：

```sh
git clone https://github.com/DavidAlphaFox/aihtml.git /tmp/aihtml-v037
cd /tmp/aihtml-v037 && git checkout 82c01eb        # master 头，PROJECT_VERSION = 0.3.7
make                                                # erlang.mk 会拉 ailib v0.4.5
```

注意：**仓库里没有 `v0.3.7` 这个 git tag**（最新 tag 是 `v0.3.6`），0.3.7 只写在 `Makefile` 的 `PROJECT_VERSION` 里，由 commit `dd07a85` 引入，master 头是 `82c01eb`。基准脚本必须按 **commit 号**而不是 tag 来 checkout，并在结果表中标注该 commit。

旧版跑法（对照 `examples/complex.erl` 的现有 `start/0`）：

```erlang
application:start(ailib),
application:start(aihtml),
ai_mustache:bootstrap(#{views => BenchTplDir}),
ai_mustache:render("complex", Ctx)
```

新版跑法：`view_complex:render(Ctx)`，模板由 plugin 在 compile 阶段编译。

两侧各自输出一份机器可读的结果（如 `{Case, Mode, Iterations, WallUs, Bytes}` 的 term 文件），由 `bench/run.sh` 汇总成对比表，避免手工抄数字。

### 2. 公平性前提：先验证输出等价

数字只有在两侧渲染出**同一份内容**时才有意义。但语义已经变了，因此：

- 旧侧跑旧语义模板（`{{#items}}{{items.name}}{{/items}}`），新侧跑新语义模板（`{{#items}}{{name}}{{/items}}`），二者是同一模板的两个写法版本，放在 `bench/tpl/v037/` 与 `bench/tpl/v040/`。
- 基准开始前先各渲染一次并**逐字节比对**，不一致则中止并报告差异，绝不带着未知差异出数字。
- 已知的、必须在基准数据里**主动规避**的差异（否则永远比不平）：
  - **escape 字符集变更**（[04 §5.1](../designs/04-codegen.md)）：旧版转义 `/` `=` `` ` ``，新版不转义；旧版的 `&` 产出 `&amp`（缺分号）。→ 基准数据中的 escape 场景只用 `<` `>` `"` `'` 四个字符，避开 `&` 与 `/`；或在比对时按已知规则做归一化，并在 `bench/README.md` 中写明。
  - **partial standalone 缩进**（[03 §6](../designs/03-semantics.md)）：新版把缩进应用到每一行。→ partial 基准模板中的 `{{> x}}` 写在行首（零缩进），使两侧输出一致。
  - **多层 section 名的 B1 bug**（[01 §B1](../designs/01-current-state.md)）：旧版 `{{#a.b}}` 会丢兄弟键。→ 基准模板不使用多层 section 名。

### 3. 归因用例：每条预期收益一个能单独归因的场景

预期收益的四个来源，各设计一个把该因素放大、其它因素压到最小的用例：

| # | 收益来源 | 用例设计 |
|---|---|---|
| G1 | **BEAM literal pool 零拷贝**（替代 ets lookup 的深拷贝，[02 §2.1](../designs/02-architecture.md)） | 大体量静态文本模板（如 200 KB HTML 中只有 3 个变量）+ **多 partial**（10 层嵌套）。旧版每次首渲染都要把整棵 IR 从 ets 深拷贝到调用进程堆；新版静态文本是字面量，跨进程按引用共享 |
| G2 | **section 迭代不再 maps:merge 全量拷贝**（[04 §4](../designs/04-codegen.md) 关键点 2） | 单层 `{{#items}}`，items 为 1 / 100 / 1000 / 10000 个 map，每个 map 带 20 个键。旧版每次迭代 `maps:merge(Ctx, ...)` 全量拷贝 Ctx；新版只是 `[E \| S]` 压栈 |
| G3 | **escape 从 8 遍 re:replace 变成单遍 binary 扫描**（[01 §B3](../designs/01-current-state.md)、[04 §5.1](../designs/04-codegen.md)） | escape-heavy：200 个变量，值为 1 KB 文本，分「无需转义」与「10% 字符需转义」两组。前者验证新实现的**零拷贝返回原 binary** 快路径 |
| G4 | **输出改 iolist 避免 binary append**（[01 §P4](../designs/01-current-state.md)） | 深层嵌套 section（旧版 `run_section/7` 会重起 `<<>>` 累加器、打断 ERTS 尾部追加优化）。同时分别测新版 `render/1`（含 `iolist_to_binary`）与 `render_iolist/1`（不含），量化省下的那一次转换 |
| G5 | 真实模板综合 | `examples/complex.mustache` 及其三个 partial（[T28](T28.md) 重写后的版本，与 v0.3.7 旧语义版本一一对应），作为最贴近实际使用的综合数字 |

**G5 是主结论数字**，写进 README；G1–G4 是归因数据，放 `bench/README.md`。

### 4. 两个必测模式

- **单进程稳态**：最能反映纯 CPU 开销。
- **多进程并发**（`erlang:system_info(schedulers_online)` 个进程同时渲染同一模板）：这是 literal pool 与 ets 差距被拉开的场景 —— ets 的深拷贝是 per-process 的，进程数越多总拷贝量线性增长；literal pool 是共享引用，不随进程数增长。**这个模式的加速比预计显著高于单进程**，是本次重构最有说服力的一组数据，不能省。
- 顺带记录**常驻内存**：旧版每个 worker 进程的进程字典各持一份完整 IR 拷贝（[01 §4.2](../designs/01-current-state.md) 的「内存 N 倍放大」），用 N 个进程各渲染一次后 `erlang:memory(processes)` 的差值量化。

### 5. 冷启动 / 稳态分开测

旧版有两级缓存，第一次与后续渲染代价差异巨大：

- **冷启动**：`bootstrap` 全量扫描 + parse 的耗时（新版为 0，编译期已完成）；以及每个进程首次渲染时的 ets lookup + `template_partial/1` 递归 `maps:merge`（[01 §4.4](../designs/01-current-state.md)）。
- **稳态**：旧版走进程字典命中的路径（[01 §4.2](../designs/01-current-state.md)），这是旧版的最优情形，**必须以它作为主对比口径**，否则会高估收益、被质疑。
- 新版侧对应地记录 plugin 的编译耗时作为「构建期成本」，与旧版的 bootstrap 耗时对照，说明成本被移到了编译期。

### 6. 度量方法

- 计时用 `erlang:monotonic_time(microsecond)`，不用 `os:timestamp/0`（现有 `examples/complex.erl` 用的是后者）。
- 每个用例：预热 ≥ 1000 次 → 正式跑 N 轮（N ≥ 7），每轮固定迭代次数，**取中位数**，同时报告 min 与 p95；不报平均值（GC 会把均值拉偏）。
- 分配量用 `erlang:process_info(Pid, [garbage_collection_info, memory])` 或 `erlang:statistics(garbage_collection)` 的差值，报告「每次渲染分配字数」与 GC 次数 —— 这比时间更稳定，也更直接对应「零拷贝」的论点。
- 固定环境：记录 OTP 版本（当前基线 OTP 28 / erts 16.4.0.3）、CPU 型号、`+S` 设置、日期，写在结果表头。
- 迭代次数按用例规模自适应，保证单轮墙钟 ≥ 200 ms，避免计时精度噪声。

### 7. 构建与隔离

- `bench/` **不进 prod profile**：在 `rebar.config` 中用单独的 `bench` profile 挂 `{src_dirs, ["src", "bench"]}`，与 [T27](T27.md) 处理 `dev/` 的方式一致。
- `bench/run.sh` 要能在干净环境从零跑通（含 v0.3.7 的 clone 与 make），并在 ailib 拉取失败时给出明确报错而不是静默跳过。
- 基准不接入 CI 的必过门禁（数字受机器影响大），但脚本要能被手动一键执行。

## 验收标准

- [ ] `bench/run.sh` 在干净环境下可一键跑通，自动准备 v0.3.7 的独立 checkout（按 commit `82c01eb`，非 tag）
- [ ] 基准开始前的输出等价校验通过；已知的三类不可避免差异（escape 字符集、partial 缩进、B1）在模板/数据设计上已规避，并在 `bench/README.md` 中写明
- [ ] G1–G5 五组用例全部有数据，且每组同时给出单进程与多进程两种模式
- [ ] 多进程模式下新版相对旧版的加速比高于单进程模式（验证 literal pool 共享 vs ets per-process 深拷贝的论点）
- [ ] 冷启动与稳态分开报告，主对比口径使用旧版**稳态**（进程字典命中）而非冷启动
- [ ] 报告包含「每次渲染分配字数」与 GC 次数，不只有时间
- [ ] 报告 min / 中位数 / p95，不使用平均值作为结论
- [ ] `render/1` 与 `render_iolist/1` 分别出数，量化省掉的 `iolist_to_binary`
- [ ] 结果表头含 OTP 版本、erts 版本、CPU、日期、两侧 commit
- [ ] G5（`examples/complex.mustache` 综合场景）的数字已写入 README benchmark 段落（回填 [T29](T29.md) 建立的骨架），关闭 [07 阶段 6 验收](../designs/07-roadmap.md)「benchmark 数据写入 README」
- [ ] `rebar3 as prod compile` 产物中不含 `bench/` 下任何模块
