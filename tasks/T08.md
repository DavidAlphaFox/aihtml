# T08 · ai_mustache_parser 实现

- **阶段**：2
- **依赖**：[T06](T06.md)
- **状态**：已完成

## 目标

把 [T07](T07.md) 产出的扁平 token 流组装成带位置信息的嵌套 AST，处理块级配对与错误诊断，并在此层修掉 [B4](../designs/01-current-state.md)（带点 partial 路径崩溃）与 [B5](../designs/01-current-state.md)（`{{.}}` 隐式迭代取不到值）。

## 交付物

- `src/ai_mustache_parser.erl` —— token 流 → `[ai_mustache_node()]`，保留 bbmustache 的 MIT 版权头

## 实现要点

### 1. 接口

```erlang
-module(ai_mustache_parser).
-include("ai_mustache.hrl").
-export([parse/1, parse/2, keys/1]).

-spec parse(binary() | [ai_mustache_token()]) ->
        {ok, [ai_mustache_node()]} | ai_mustache_error().
-spec parse(binary() | [ai_mustache_token()], ai_mustache_opts()) ->
        {ok, [ai_mustache_node()]} | ai_mustache_error().
```

入参既接受原始模板 binary（内部先调 `ai_mustache_scanner:scan/2`）也接受 token 列表（便于 [T10](T10.md) 单独测 parser）。`keys/1` 导出供 `rebar3 mustache migrate` 复用。

### 2. 递归下降 + 显式块栈

用一个尾递归的 `parse_nodes/4`，状态里带**当前打开的块**：

```erlang
%% Open :: {Marker :: char(), Keys :: ai_mustache_keys(), Loc :: ai_mustache_loc()} | toplevel
parse_nodes(Tokens, Open, Acc, St) -> ...
```

- 遇到 `{tag, _, $#|$^|$+|$-, ...}` 或块级扩展 marker → 递归进入子层，子层返回 `{Body, RestTokens}` 后构造节点、继续本层。
- 遇到 `{tag, Loc, $/, Content, _}` → 与 `Open` 比对：
  - `Open =:= toplevel` → `{error, {File, Line(Loc), {mismatched_close, [], keys(Content)}}}`
  - keys 不等 → `{mismatched_close, ExpectedKeys, GotKeys}`
  - 相等 → 返回本层
- token 流耗尽而 `Open =/= toplevel` → `{unclosed_tag, ExpectedKeys}`，**Line 取该块 `{{#x}}` 的开标签行号**，不是文件末行 —— 这是错误信息可用性的关键。

累加器一律 `[N | Acc]` + `lists:reverse/1`。

### 3. token → 节点映射表

| token marker | 产出节点 |
|---|---|
| `none` | `{var, Loc, keys(Content), escape}` |
| `${` | `{var, Loc, keys(Content), raw}` |
| `$#` | `{section, Loc, keys(Content), Body}` |
| `$^` | `{inverted, Loc, keys(Content), Body}` |
| `$+` | `{has, Loc, keys(Content), Body, true}` |
| `$-` | `{has, Loc, keys(Content), Body, false}` |
| `$*` | `{lambda, Loc, keys(Content)}` （行内，无 body） |
| `$>` | `{partial, Loc, partial_name(Content), Indent}` |
| 扩展 char `C` | `{ext, Loc, C, keys(Content), Body}` （行内时 Body 为 `[]`） |
| `{text, ...}` | `{text, Loc, Bin}` |

`$!`（注释）与 `$=`（分隔符）不会到达 parser —— scanner 已消费。若仍收到，视为内部错误直接 `error/1`（编程错误，不是用户错误）。

### 4. `keys/1` —— 点分路径

```erlang
-spec keys(binary()) -> ai_mustache_keys().
```

- 先剔除**全部**空白（`\s` `\t` `\r` `\n`），与现有实现一致（`<< <<X:8>> || <<X:8>> <= Bin, X =/= $\s >>`，但要把 `\t` 等也算上）。
- 空 binary 或 `<<".">>` → `[?AI_MUSTACHE_DOT]`，即 `['.']`。这是**修 B5 的关键**：旧实现同样产出 `['.']`，但 runner 拿它去 map 里找键 `'.'`，永远取不到。新方案里 `['.']` 是哨兵，由 `ai_mustache_rt:lookup/2` 识别为「返回栈顶」（见 [T11](T11.md)）。parser 侧只需保证哨兵稳定产出。
- 其余按 `.` 切分，过滤空段，逐段 `binary_to_atom(X, utf8)`。
- **atom 表风险**：模板内容来自文件系统（构建期），不是运行期外部输入，`binary_to_atom/2` 在编译期使用是安全的；但仍要在模块注释中写明这一约束，防止后续有人把 `keys/1` 挪到运行期路径上。这与 [01 §4.5](../designs/01-current-state.md) 指出的模板名 `binary_to_atom` 风险是不同的两处，后者由 [T15](T15.md) 处理。

### 5. `partial_name/1` —— 修 B4

**partial 路径绝不能走 `keys/1`。**

```erlang
partial_name(Content) -> trim(Content).   %% 返回 binary()，保留 `/` 与 `.`
```

旧实现 `parse_partial(State0, [Tag], NextBin0, Result0)` 只匹配单元素 keys 列表，`{{> layout.default}}` 经 `keys/1` 得到 `[layout, default]` 直接 `function_clause`（[B4](../designs/01-current-state.md)）。新实现把 partial 名当**文件路径字符串**处理：

- `{{> shared/item}}` → `<<"shared/item">>`
- `{{> layout.default}}` → `<<"layout.default">>`
- 路径 → 模块名的归一化（`/` 与 `-` 转 `_`、加 prefix）是 [T09](T09.md) `resolve_partials/2` 的职责，parser 只保留原始路径。

校验：路径为空 → `{partial_not_found, <<>>}`；含 `..` 段 → 同样报错（防目录穿越，plugin 会用它拼文件路径）。

### 6. 块级配对的 keys 比较

`{{#a.b}}...{{/a.b}}` 必须能闭合，因此比较的是 `keys/1` 之后的 atom 列表而非原始 binary（`{{#a.b}}...{{/ a.b }}` 空白不同但应视为相等）。这一点旧实现已经做对（`parse_section/5` 的模式匹配复用同一 `Keys` 变量），保留该行为。

### 7. 扩展 marker 的块级 / 行内判定

`opts` 中 `extensions => [Mod]`，parser 启动时构建 `#{Char => {Mod, block | inline}}`：

- `Mod:markers()` 给出全部 marker；
- 可选回调 `Mod:block_markers()`（`erlang:function_exported/3` 判定，注意先 `code:ensure_loaded/1`）给出其中哪些是块级；
- 未导出 `block_markers/0` 时全部按行内处理。

冲突检测（与内置 marker 冲突、两个扩展抢同一 marker）在此处做，报 `{unknown_marker, C}` 之外的专门错误，与 [designs/06-parse-transform.md §2.4](../designs/06-parse-transform.md) 一致。

### 8. 不做的事

- **不做后处理**：`merge_text` / `drop_empty` / `resolve_partials` 全在 [T09](T09.md)。`parse/1` 返回的是原始 AST。这与旧实现把 `remove_empty_section` / `merge_continuous_binary` 塞进 `parse/1` 的做法相反 —— 拆开才能单独测每个 pass。
- **不做语义判断**：falsy、section 分派、转义都在编译期/运行期，parser 不碰。
- **不返回 partials 列表**：旧 `parse/1` 返回 `{IR, Partials}`，新 `parse/1` 只返回 AST；依赖列表由 `resolve_partials/2` 产出（[T09](T09.md)）。

## 验收标准

- [ ] `parse/1`、`parse/2` 返回 `{ok, AST}` 或 `{error, {File, Line, Reason}}`，**任何输入都不抛异常**
- [ ] `{{> layout.default}}` 与 `{{> shared/item}}` 均解析为 `{partial, Loc, <<"layout.default">> | <<"shared/item">>, Indent}`，不再 `function_clause`（B4 修复）
- [ ] `{{.}}` 解析为 `{var, Loc, ['.'], escape}`，`{{{.}}}` 为 `{var, Loc, ['.'], raw}`（B5 的 parser 侧修复）
- [ ] 八种 AST 节点全部可产出，且 `loc()` 指向对应 `{{` 的位置
- [ ] `{{#a}}...{{/b}}` 报 `{mismatched_close, [a], [b]}`，行号指向 `{{/b}}`
- [ ] `{{#a}}` 未闭合报 `{unclosed_tag, [a]}`，行号指向 `{{#a}}` 而非文件末行
- [ ] 顶层出现 `{{/a}}` 报错而非静默忽略
- [ ] `{{#a.b}}...{{/a.b}}` 与 `{{#a.b}}...{{/ a.b }}` 均能正确闭合
- [ ] 未注册的扩展 marker 报 `{unknown_marker, C}`
- [ ] 源码零 ailib 依赖，累加器无 `Acc ++ [X]`
- [ ] `parse/1` 的返回值中不含任何 partials 汇总列表（该职责已移交 T09）
