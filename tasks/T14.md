# T14 · ai_mustache_compiler:compile_inline/3

- **阶段**：3
- **依赖**：[T13](T13.md)
- **状态**：已完成

## 目标

实现内联模板的单表达式生成 —— 把一段 AST 编译成一个可直接嵌进调用方函数体的 Erlang abstract expression，供 parse_transform 的形态 (b) 原地展开 `ai_mustache:inline/2`。

## 交付物

- `src/ai_mustache_compiler.erl` —— 本任务负责 `compile_inline/3`（`forms/2` 见 [T13](T13.md)）

## 实现要点

### 0. 为什么不是 sigil

**Erlang 不支持自定义 sigil。** OTP 27 引入的 sigil 是固定集合（`~"..."`、`~b`、`~B`、`~s`、`~S`），编译器对未知 sigil 直接报**词法错误** —— `~mustache"..."` 根本过不了词法，parse_transform 拿不到 forms（[designs/06-parse-transform.md §0](../designs/06-parse-transform.md)）。

因此内联模板必须落在合法 Erlang 语法上：**识别特定函数调用 + 字面量参数**，即 `ai_mustache:inline(Tpl, Ctx)` 且 `Tpl` 是 binary 字面量。`compile_inline/3` 就是这个方案的编译端。

### 1. 接口

```erlang
-spec compile_inline([ai_mustache_node()],
                     CtxVar :: erl_parse:abstract_expr(),
                     ai_mustache_opts()) ->
        {ok, erl_parse:abstract_expr()} | ai_mustache_error().
```

三个参数：

- AST —— 由 scanner + parser + [T09](T09.md) 的 `postprocess/2` 产出（但 **`resolve_partials/2` 跳过**，见 §5）
- `CtxVar` —— **调用点第二参数的原始 abstract expression**，不是变量名。它可能是 `{map, L, [...]}`（`#{name => Name}`）、`{var, L, 'Ctx'}`、甚至一个函数调用。原样嵌入，**只嵌入一次**（见 §3 的求值次数问题）。
- opts —— 复用 [T13](T13.md) 的 `#cs{}`，`module` 取调用方模块名，`source` 取调用方 `.erl` 文件路径（错误诊断要指向 `.erl` 的行号，不是不存在的 `.mustache`）。

### 2. 生成形态

目标（[designs/06-parse-transform.md §3](../designs/06-parse-transform.md)）：

```erlang
greet(Name) ->
    erlang:iolist_to_binary(
      begin
          S__1 = [#{name => Name}],
          [<<"Hello ">>,
           ai_mustache_rt:escape(ai_mustache_rt:lookup([name], S__1)),
           <<"!">>]
      end).
```

要点：

- 外层是 `{block, L, [Match, Body]}`（Erlang 的 `begin ... end`），使得整个展开是**一个表达式**，可以出现在任何表达式位置（函数参数、list 元素、case 分支……）。
- `S__1` 是**卫生变量名**：必须全局唯一，不能与调用方作用域中的变量冲突。用 `'S__' ++ integer_to_list(Counter)` 且 Counter 由 transform 侧的模块级计数器提供；更稳妥的做法是 `erlang:unique_integer([positive, monotonic])` 拼进名字，或者用 `_@` 前缀（Erlang 允许 `'_@S1'` 这类由编译器生成的原子变量名，用户代码几乎不会撞）。**必须有测试证明同一函数里两次 `inline/2` 调用不会互相覆盖变量。**
- `erlang:iolist_to_binary/1` 包在最外层，因为 `ai_mustache:inline/2` 的返回类型是 `binary()`（[designs/02-architecture.md §5](../designs/02-architecture.md)）。

### 3. 没有 render_stack，所以没有辅助函数

`forms/2` 把 section body 生成为**模块级辅助函数** `sec_N/2`。`compile_inline/3` 处在表达式位置，**不能凭空往模块里加函数**（严格说 parse_transform 可以，但那会污染调用方模块的命名空间且与 `-export` 交互复杂）。两种落法：

**方案 A（推荐）：section body 编译成匿名 fun**

```erlang
begin
    S__1 = [Ctx],
    F__1 = fun(S__2, I__1) -> [ ... body ... ] end,
    [ ..., ai_mustache_rt:section(ai_mustache_rt:lookup([items], S__1), F__1, S__1, <<>>), ... ]
end
```

代价：`fun/2` 每次求值都要构造闭包，比模块级函数略慢；但内联模板本就是小模板场景，可接受。且**这样 `compile_inline/3` 与 `forms/2` 共用完全相同的 body 编译核心**，只是「怎么把 body 变成一个可调用物」的策略不同 —— 用一个 `#cs{}` 字段（`body_strategy = fun | aux_function`）区分，这是保住[架构不变量 #2](../designs/02-architecture.md)（唯一 AST → forms 实现）的关键设计。

**方案 B：section 的 case 分支就地内联**

对每个 section 都把 body 表达式复制进七个 case 分支。代价是 body 被复制多份，嵌套 section 会指数膨胀。**不采用**，但要在注释中说明为什么不采用。

**求值次数**：`CtxVar` 只在 `S__1 = [CtxVar]` 处出现一次，因此 `ai_mustache:inline(Tpl, side_effect())` 的副作用只发生一次，与运行期降级路径行为一致。这一点必须有测试。

### 4. 缩进参数

内联模板没有 partial（见 §5），因此 `I` 恒为 `<<>>`，**缩进静态化优化必然生效**（[designs/04-codegen.md §6](../designs/04-codegen.md)）：不生成任何 `I` 拼接代码，body fun 的第二参数直接是 `_I`。

### 5. 内联模板不支持 partial

`{{> x}}` 在内联模板中**报编译错误** —— 内联场景没有 views 目录上下文（[designs/06-parse-transform.md §3.3](../designs/06-parse-transform.md)）。

- `compile_inline/3` 遇到 `{partial, Loc, _, _}` 节点直接返回 `{error, {File, Line, {partial_not_found, Name}}}`，或更贴切地新增 `{partial_in_inline, Name}` 作为 Reason（若新增则同步更新 [T06](T06.md) 的 `ai_mustache_reason()`）。
- 因此调用链里**跳过 `resolve_partials/2`**（[T09](T09.md)），只跑 `merge_text/1` 与 `drop_empty/1`。
- 错误信息要明确写「内联模板不支持 partial，请改用文件模板」，这是最容易撞到的坑。
- `{partial_cycle_depth, [module()]}` 这个 Reason 在文件模板路径下用不到（跨模块调用天然支持循环），它是留给内联展开路径的 —— 但由于内联根本不支持 partial，实际上无处使用；实现时要么删掉它，要么在注释里说明它是预留。

### 6. 扩展 tag 在内联中

`{ext, ...}` 可以支持：`Mod:compile_tag/4` 返回的就是 abstract expression，直接嵌入即可。但扩展模块列表来自 `opts` 的 `extensions`，而 parse_transform 的 opts 来自 `{mustache_opts, [{extensions, [...]}]}` 编译选项（[designs/06-parse-transform.md §2.3](../designs/06-parse-transform.md)）。若未配置则任何扩展 marker 都报 `{unknown_marker, C}`。

### 7. 错误处理

同 [T13](T13.md)：`{error, {File, Line, Reason}}`，不抛异常。但**行号语义不同** —— 内联模板的 AST loc 是相对模板 binary 的行号，需要**加上 `ai_mustache:inline/2` 调用点在 `.erl` 文件中的行号偏移**，否则报出的行号会指向 `.erl` 的第 1、2 行。

具体：调用点在 `.erl` 的第 `L0` 行，模板 AST 的 loc 为 `{Ln, Col}`，则最终行号是 `L0 + Ln - 1`。这对单行模板（绝大多数内联场景）等于 `L0`，符合直觉。多行 binary 字面量（`~"...\n..."` 或 `<<"...">>` 跨行）时也能大致对上。

parse_transform 侧把这个错误转成标准 `{error, [{File, [{Line, Module, Reason}]}], []}` 并配 `format_error/1`（[designs/06-parse-transform.md §5](../designs/06-parse-transform.md)），与 erlc 诊断一致。

### 8. 与运行期降级路径的等价性

`ai_mustache:inline/2` 本身有真实实现（运行期 scanner + parser + 解释求值，见 [T15](T15.md)）。**加不加 parse_transform，语义必须完全一致**（[designs/06-parse-transform.md §3.1](../designs/06-parse-transform.md)）：

- 加了 → 编译期展开，零运行时开销
- 没加 → 照常工作，只是慢

这让「忘了加 `-compile({parse_transform, ...})`」不会变成一个难查的 bug。**必须有一个差分测试**：同一批模板 × 同一批 context，两条路径的输出逐字节相同。这是本任务最重要的验收项。

### 9. 第一参数非字面量时

`ai_mustache:inline(Tpl, Ctx)` 中 `Tpl` 是变量时，transform 原样保留调用、走运行期路径（[designs/06-parse-transform.md §3.2](../designs/06-parse-transform.md)）。这个判定在 transform 侧（阶段 5），`compile_inline/3` 只在拿到字面量时被调用 —— 但要在文档与 spec 里写清楚这个前置条件。

可选：`warnings_as_errors` 下发一条 warning 提示无法优化。

## 验收标准

- [ ] `compile_inline/3` 返回 `{ok, Expr}` 或 `{error, {File, Line, Reason}}`，不抛异常
- [ ] 返回的是**单个** abstract expression，可嵌入任何表达式位置（测试：嵌进 list 元素、case 分支、函数实参三个位置均能编译）
- [ ] 生成的表达式经 `compile:forms/2` 编译零 error 零 warning（含 `warnings_as_errors`、`warn_shadow_vars`、`warn_unused_vars`）
- [ ] 卫生变量名不与调用方作用域冲突；同一函数体内两次 `inline/2` 展开互不干扰（专项测试）
- [ ] `CtxVar` 表达式在生成代码中**只出现一次**，副作用只求值一次（专项测试）
- [ ] section body 走匿名 fun（方案 A），与 `forms/2` 共用同一 body 编译核心，`#cs{}` 中有明确的策略字段
- [ ] 嵌套 section 不导致 body 表达式复制膨胀
- [ ] `{{> x}}` 报编译错误，错误信息含「内联模板不支持 partial」
- [ ] 错误行号加了调用点偏移（`L0 + Ln - 1`），指向 `.erl` 的实际行
- [ ] 缩进静态化生效：生成代码中无任何 `I` 拼接
- [ ] 扩展 tag 在配置了 `extensions` 时可用，未配置时报 `{unknown_marker, C}`
- [ ] **差分测试**：至少 20 组（模板 × context）在「编译期展开」与「运行期降级」两条路径下输出逐字节相同，覆盖变量 / raw / section / inverted / has / lambda / `{{.}}` / 自定义分隔符
- [ ] `rebar3 dialyzer` 与 `rebar3 xref` 全绿
