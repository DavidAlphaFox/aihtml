### 1. Incompatible Changes（置顶）

沿用现有 v0.3.5 的公告体例，在 README 顶部加 v0.4.0 段落（[03 §7.4](../designs/03-semantics.md)）。必须逐条写清：

1. **模板语义改为标准 mustache context stack**（决策 D2）。v0.3.x 的「扁平 context + 全路径寻址」已移除，**无兼容开关**（[03 §7](../designs/03-semantics.md) 明确不提供 `{compat, flat}`）。给出 §7.1 的 diff 形式迁移示例，并指向 `rebar3 mustache migrate`。
2. **不再需要 bootstrap**。`ai_mustache:bootstrap/0,1` 与 `ai_mustache:reload/0` 已删除；aihtml 是 library app，不需要 `application:start(aihtml)`。
3. **不再依赖 ailib**（决策 D5）。运行期与测试期均零依赖，只依赖 OTP。
4. **escape 字符集从 8 个收窄到 5 个**：现在只转义 `&` `<` `>` `"` `'`；**移除 `/` `=` `` ` `` 的转义**，因为它们会破坏 URL（`href="/a/b"` 曾被转成 `href="&#x2F;a&#x2F;b"`）与普通文本。同时**修正 `&amp` 缺分号的 bug**（旧实现产出 `&amp` 而非 `&amp;`，见 [01 §B3](../designs/01-current-state.md)）。这两条都会改变已有页面的输出字节。
5. **partial 的 standalone 缩进行为改变**：缩进现在应用到 partial 输出的每一行（符合 spec），旧实现只缩进第一行（[03 §6](../designs/03-semantics.md)）。
6. **lambda 收到的是栈顶 frame 而非全局 context**（[03 §5](../designs/03-semantics.md)）。需要访问根 context 的场景改用 `fun/2` 显式传值。
7. **`ai_dom_node` / `ai_dom_render` 已删除**（决策 D4）。
8. **多层 section 名不再丢失兄弟键**（[B1](../designs/01-current-state.md) 已修）—— 这是修 bug，但依赖旧错误行为的模板可能表现不同。
9. 最低环境要求：OTP 27+（`json` 模块与 `float_to_binary/2` 的 `short` 选项），推荐 OTP 28。

### 2. 新架构（零进程零 ets）

写清楚这次重构的核心（[02 §1/§2](../designs/02-architecture.md)）：

- 模板在**编译期**被编译成 Erlang 模块，「缓存」从 ets 移到 BEAM code server
- 静态文本进入 BEAM 的 **literal pool**，跨进程按引用共享，**零拷贝**；对比 ets 每次 `lookup` 都是完整深拷贝
- partial 编译成**跨模块函数调用**，因此增量编译粒度天然正确、循环 partial 引用天然合法
- 运行期**零进程、零 ets、零 persistent_term、零启动顺序依赖**
- 画一张 `views/*.mustache → scanner → parser → compiler → (plugin | parse_transform)` 的流程图（照搬 [02 §1](../designs/02-architecture.md)）
- 附一段生成代码样例（[04 §4](../designs/04-codegen.md) 的 `view_complex.erl`），让读者直观看到「模板即模块」

### 4. 模板语义

照 [03 §2](../designs/03-semantics.md) 的规则表写一节，必须显式覆盖：

- **context stack 查找规则**：`{{name}}` 从栈顶向外逐层回溯；`{{a.b}}` 只有首段 `a` 回溯，`b` 严格在 `a` 内部取，不回溯
- **`{{.}}` 隐式迭代器**可用（修掉 [B5](../designs/01-current-state.md)）
- **falsy 的定义**：`undefined` · `false` · `[]` · `<<>>` · `null`
- **`0` 是 truthy** —— [03 §2.1](../designs/03-semantics.md) 点名「常见踩坑点，需在 README 显式说明」，要单独成段并给反例，`#{}` 同样是 truthy
- **section 分派表**（[03 §3](../designs/03-semantics.md)）：`[]` / 非空 list / map / `true` / `fun/2` / `fun/1` / falsy / 其它，八种情形逐行列出，标注哪几种会压栈
- **key 类型是 atom**（沿袭 v0.3.5）

### 5. `{{#}}` 与 `{{+}}` 的区别（单独成节）

[03 §4](../designs/03-semantics.md) 明确要求「保留二者是有意义的，在 README 中要讲清楚这个区分」。核心是**要不要压栈**：

```mustache
{{#user}}{{name}}{{/user}}        →  压栈，name 从 user 里取；是 with / for
{{+user}}{{user.name}}{{/user}}   →  不压栈，作用域不变；是 if
```

要写明：`{{#}}` 是「作用域进入 + 迭代」，`{{+}}` 是「纯存在性判断 / 条件渲染」，`{{-}}` 是 `{{+}}` 取反，`{{+x}}` 支持 `fun/1`。并注明 `{{+}}` / `{{-}}` 是 aihtml 扩展、不在官方 spec 中。

### 6. parse_transform 三形态

按 [06](../designs/06-parse-transform.md) 写，三形态各给可运行的代码片段：

- **(a) 扩展点注册** `-mustache_tag({$@, {my_i18n, compile_at}})` + `ai_mustache_ext` behaviour 的三个 callback
  - **必须写清 [06 §2.3](../designs/06-parse-transform.md) 的作用域约束**：`-mustache_tag` 只负责**声明与校验**，实际装配靠 `{mustache_opts, [{extensions, [...]}]}`。设计文档原话是「这一点必须在 README 里讲清楚，否则用户会误以为只写 attribute 就能生效」
  - marker 冲突规则：内置已占用 `# ^ / > ! = & { } + - *`，扩展只能用这之外的字符
- **(b) 内联模板** `ai_mustache:inline(~"Hello {{name}}!", #{...})`
  - 说明为什么**不是自定义 sigil**：OTP 27 的 sigil 是固定集合，`~mustache"..."` 过不了词法（[06 §0](../designs/06-parse-transform.md)）
  - 说明**优雅降级**：不加 parse_transform 也能跑，只是走运行期解释
  - 说明内联模板**不支持 partial**
- **(c) 编译入口** `-mustache_template({index, "views/index.mustache"})`
  - **必须标注已知成本**：改模板不会触发 `.erl` 重编，需要 plugin 的 `touch` 兜底；因此标为 plugin-recommended（[06 §4.1](../designs/06-parse-transform.md)、[07 风险表](../designs/07-roadmap.md)）
- 收尾放 [06 §6](../designs/06-parse-transform.md) 的三形态对比表

### 7. 与官方 spec 的 known deviation 清单

照搬 [03 §8](../designs/03-semantics.md) 的表格，并声明官方 spec 的六个**必选模块**（Comments / Delimiters / Interpolation / Inverted / Partials / Sections）全部通过：

| 项 | aihtml 行为 | 原因 |
|---|---|---|
| `{{+x}}` / `{{-x}}` | 非标准的 has / inverted-has | aihtml 扩展 |
| `{{*f}}` | 非标准的 lambda | aihtml 扩展 |
| key 类型 | atom（spec 用 string） | Erlang 侧 map 用 atom key 更自然 |
| lambda 返回值 | 不做二次模板解析 | 编译期方案下代价过高 |
| Dynamic Names / Blocks | 不支持 | spec 可选模块 |

清单必须与测试中标注为 deviation 的用例**一一对应**，不能各说各话（[07 阶段 3 验收](../designs/07-roadmap.md)）。
