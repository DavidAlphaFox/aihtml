# T51 · plugin engine 参数化

- **阶段**：13
- **依赖**：[T33](T33.md) · [T45](T45.md)
- **状态**：已完成

## 目标

把 `rebar3_aihtml` 的八个模块从「mustache 专用」改成「引擎参数化」，且 mustache 侧行为与产物**完全不变**。

## 交付物

- `rebar3_aihtml/include/rebar3_aihtml.hrl` —— `#mopts{}` 增加 `engine`
- `rebar3_aihtml/src/rebar3_aihtml_{opts,scan,name,emit,check,gc,stale,prv}.erl`
- `test/rebar3_aihtml_SUITE.erl` —— 参数化后的回归

## 实现要点

### 1. 改动清单

严格按 [12 §1.1](../designs/12-jinja-toolchain.md) 的表。核心是把八处写死的
mustache 调用换成 `Engine:` 调用：

| 位置 | 现在 | 改为 |
|---|---|---|
| `scan:describe/2` | `ai_mustache_compiler:source_hash/2` | `Engine:source_hash/2` |
| `scan:absorb/4` | 匹配 `mustache_source` | 匹配 `Engine:attribute()` |
| `name:module_of/2` | `ai_mustache_ast:module_name/2` | `Engine:module_name/2` |
| `emit:render/3` | `ai_mustache_parser:parse/2` + `ai_mustache_compiler:forms/2` | `Engine:parse/2` + `Engine:forms/2` |
| `opts:raw/2` | 读 `mustache_opts` | 读 `Engine:config_key()` |
| `opts:known_keys/0` | `?R3A_KNOWN_KEYS` | `Engine:known_keys()` |
| `gc` | banner 前缀 | banner 含引擎标记（§3） |
| `prv:run/2` | — | `run/3`，多一个 engine 参数 |

`rebar3_aihtml_migrate` **不动**（mustache 语义迁移专用）。

### 2. `#mopts{}`

新增 `engine :: module()`，`compiler_opts` 改名 `engine_opts`
（[12 §1.2](../designs/12-jinja-toolchain.md)）。

改名要连带改 `emit` 与 `scan` 里的引用。**改名是为了避免后来者以为它是
「Erlang 编译器选项」** —— 它其实是「模板引擎选项」。

### 3. banner 必须带引擎标记

```
%% Generated by rebar3_aihtml (mustache) from views/a.mustache -- DO NOT EDIT.
```

**这是本任务最容易漏、后果最严重的一条**（[12 §1.4](../designs/12-jinja-toolchain.md)）：
两个引擎共用 out_dir 时，gc 必须只回收自己引擎的产物，
否则两个 pre-compile hook 会互相删对方刚生成的文件，
形成一个每次构建都发生、且顺序相关的诡异 bug。

`?R3A_BANNER` 改成一个函数 `banner(Engine)`。
**旧 banner 的兼容**：已存在的产物没有引擎标记，gc 遇到旧格式 banner 时
按 mustache 处理（唯一存在过的引擎），并在下次生成时写成新格式。

### 4. 键表拆分

`?R3A_KNOWN_KEYS` 拆成 `?R3A_MUSTACHE_KEYS` 与 `?R3A_JINJA_KEYS`，
定义在 `include/ai_html.hrl`（[T33](T33.md) §2 解释了为何在那里）。

未知键的警告文案要说明是哪个引擎的配置。

### 5. 零行为变化

本任务**不新增任何功能**。mustache 的行为、产物字节（banner 除外）、
stamp 全部不变。banner 变化会让 gc 的识别逻辑改动，但不影响 stamp
（banner 不参与 `source_hash/2`），因此**不触发重编**。

这一点要实测：改动前后对同一项目跑 `rebar3 compile` 两次，
第二次的「跳过数」应等于模板总数。

## 验收标准

- [ ] 八个模块无任何写死的 `ai_mustache_*` 调用（grep 确认）
- [ ] `#mopts{}` 有 `engine` 字段，`compiler_opts` 已改名 `engine_opts`
- [ ] banner 含引擎标记；旧格式 banner 被识别为 mustache
- [ ] gc 只回收自己引擎标记的文件（专项用例：out_dir 里放另一引擎的文件，跑 gc 不删）
- [ ] 键表已拆分，未知键警告指明引擎
- [ ] `rebar3_aihtml_migrate` 未被改动（`git diff` 为空）
- [ ] **无重编验收**：改动前构建一次，改动后再构建，全部模板被跳过（banner 不进 stamp）
- [ ] `rebar3_aihtml_SUITE` 全部通过，测试数不减
- [ ] `examples/` 端到端仍然跑通
