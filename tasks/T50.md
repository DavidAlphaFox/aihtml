# T50 · compile_inline/3

- **阶段**：12
- **依赖**：[T49](T49.md)
- **状态**：已完成

## 目标

把模板编译成**单个表达式**，供 parse_transform 就地展开；并保证展开路径与运行期回退路径行为完全一致。

## 交付物

- `src/ai_jinja_compiler.erl` —— `compile_inline/3`
- `test/ai_jinja_inline_tests.erl`

## 实现要点

### 1. 接口

```erlang
-spec compile_inline([jinja_node()], erl_parse:abstract_expr(), map()) ->
        {ok, erl_parse:abstract_expr()} | ai_html_error(ai_jinja_reason()).
```

生成 `erlang:iolist_to_binary(begin ... end)`，与
`ai_mustache_compiler:compile_inline/3` 同形。

### 2. 辅助函数变成绑定的匿名 fun

展开的代码要住在别人的模块里，不能往里加函数。
沿用 mustache 的 `ref/2` → `{local, Name} | {bound, Var}` 机制：

- `{local, F}` → `{call, L, {atom, L, F}, Args}`
- `{bound, V}` → `{call, L, {var, L, V}, Args}`

宏在内联模式下编译成 `Macro__ = fun(Args, V) -> ... end` 的绑定。

**顺序很重要**：在 block 里这些是 let 绑定，被引用者必须先绑定。
mustache 侧的 `aux` 列表顺序（`[MainDef, BodyDef | Aux]`）已经处理了这一点，
Jinja 侧的宏互相调用会让这个约束更强 —— **互相递归的宏在内联模板里不可能实现**，
要报 `{mutual_macro_in_inline, Names}`。

### 3. 变量卫生

生成的变量名必须不与用户代码冲突。
沿用 mustache 的做法：alpha 重命名 + `?CTX_VAR` 占位再替换
（`ai_mustache_transform` 的 `?CTX_VAR` 机制）。

Jinja 生成的变量更多（作用域链 `V0`/`V1`/…、循环变量、loop 变量），
命名统一加 `__` 后缀，且在 module doc 里列出全部保留形态。

### 4. 拒绝的语句

[11 §8](../designs/11-jinja-codegen.md)：include / extends / import / from / block
一律报 `{target_in_inline_template, Kind}`。

### 5. 与运行期回退路径的一致性

**这是本任务最重要的验收点。**

`ai_jinja:inline/2` 在没有 parse_transform 时会在运行期编译并渲染
（[T54](T54.md)）。两条路径必须**同样地拒绝同样的东西** ——
否则一份模板加了 transform 是编译错误、不加是静默渲染成空，
而这个差异恰恰在最难注意的地方。

mustache 侧已有这个教训（`ai_mustache:inline/2` 对 partial 的处理）。
落地方式：把「哪些节点在内联模板里非法」抽成一个导出的谓词函数，
两条路径都调它。

## 验收标准

- [ ] `compile_inline/3` 产出单个表达式，求值结果为 binary
- [ ] 与 `forms/2` 共享节点编译实现（源码审查：无第二份 if/for/set 的编译逻辑）
- [ ] 宏在内联模式下编译成绑定的匿名 fun 且顺序正确
- [ ] 互相递归的宏报 `{mutual_macro_in_inline, Names}`
- [ ] 生成的变量名不与用户变量冲突（用同名用户变量的用例验证）
- [ ] 五种被拒语句各有用例
- [ ] **一致性用例**：同一批模板分别走 transform 展开与运行期回退，输出与错误逐条相同（参数化测试）
- [ ] 「内联模板里非法的节点」是一个共享谓词，两条路径都调它（源码审查）
- [ ] fixture 中标记为可内联的用例在两条路径下都通过
