# T32 · ai_html_text / ai_html_escape / ai_html_path 抽取

- **阶段**：7
- **依赖**：[T31](T31.md)
- **状态**：已完成

## 目标

抽出剩余三块与模板语言无关的基础设施：文本规范化、HTML 转义与值格式化、模板路径解析与 `.erl` 静态扫描。

## 交付物

- `src/ai_html_text.erl` —— 由 `ai_mustache_text` 迁入
- `src/ai_mustache_text.erl` —— 转发壳，标 `-deprecated`
- `src/ai_html_escape.erl` —— 由 `ai_mustache_rt` 的 `escape/1` · `to_binary/1` 迁入
- `src/ai_html_path.erl` —— 由 `ai_mustache_path` 泛化，属性名参数化
- `src/ai_mustache_path.erl` —— 转发壳
- 对应测试

## 实现要点

### 1. `ai_html_text`

现 `ai_mustache_text` 的全部内容（`template/1` `path/1` `opts/1` `source/1` `to_list/1`）
本就与 mustache 无关，整体迁入。

保留 `ai_mustache_text` 作为转发壳而非直接删除：它是 `-export` 的公开模块，
外部可能有调用方。壳里每个函数一行转发，加 `-deprecated([{F, A, "use ai_html_text"}])`。
计划在 v0.6 删除，写进 CHANGELOG。

### 2. `ai_html_escape`

`escape/1` 与 `to_binary/1` 两个函数从 `ai_mustache_rt` 迁出。
`ai_mustache_rt` 保留同名导出并转发 —— **不能删**，生成代码里写死了
`ai_mustache_rt:escape/1`，删掉会让所有已构建的模块失效。

`to_binary/1` 的两条关键行为原样保留：`float_to_binary(F, [short])`、
无法渲染的值 `error({ai_mustache, {not_renderable, T}})`。

**注意**：异常里的 `ai_mustache` 标签留在 `ai_mustache_rt` 的转发层，
`ai_html_escape` 自己抛的标签是 `ai_html`；Jinja 侧再包一层成 `ai_jinja`。
否则 Jinja 模板报错会说 "ai_mustache"，非常困惑。

因此 `ai_html_escape:to_binary/1` 的签名改为 `to_binary(Term, Tag :: atom())`，
或者更简单：`to_binary/1` 抛 `{ai_html, {not_renderable, T}}`，
两个引擎的 rt 各自 catch 并重新抛自己的标签。**选后者**，签名更干净。

### 3. `ai_html_path`

`ai_mustache_path` 的 `resolve/2` 与 `template_spec/1` 与语言无关，直接迁。
`scan/1` 扫描 `.erl` 找 `-mustache_template` attribute —— 属性名参数化成
`scan/2`：`scan(File, AttrName)`。

`ai_mustache_path:scan/1` 转发为 `ai_html_path:scan(File, mustache_template)`。

**两个消费者必须继续用同一份实现**（[T25](T25.md) 的约束）：
`ai_mustache_transform` 与 plugin 的反向依赖表。抽取不得让它们分叉。

## 验收标准

- [ ] 三个新模块只依赖 OTP，xref 依赖集合为空
- [ ] `ai_mustache_text` / `ai_mustache_path` 转发壳保留全部导出并标 deprecated
- [ ] `ai_mustache_rt:escape/1` 与 `to_binary/1` 仍然导出且行为不变（生成代码兼容）
- [ ] `to_binary/1` 对不可渲染值抛出的标签仍是 `ai_mustache`（从调用方看行为不变）
- [ ] 抽取前后生成的 `.erl` 逐字节相同
- [ ] 全套检查全绿，测试数不减
