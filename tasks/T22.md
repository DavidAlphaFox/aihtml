# T22 · ai_mustache_transform 三 pass 骨架

- **阶段**：5
- **依赖**：[T21](T21.md)
- **状态**：已完成

## 目标

实现 `ai_mustache_transform:parse_transform/2` 的三 pass 框架与统一错误上报机制，为三种形态（[T23](T23.md) / [T24](T24.md) / [T25](T25.md)）提供共同的 forms 遍历、状态收集与诊断输出基础设施。

## 交付物

- `src/ai_mustache_transform.erl` —— `parse_transform/2` · `format_error/1` · 三 pass 实现骨架
- `src/ai_mustache_transform.hrl`（或模块内 `-record`）—— 状态记录 `#st{}` 定义
- `test/ai_mustache_transform_tests.erl` —— 三 pass 框架层面的 EUnit 测试

## 实现要点

### 1. 骨架

严格照 [06 §5](../designs/06-parse-transform.md)：

```erlang
-module(ai_mustache_transform).
-export([parse_transform/2, format_error/1]).

parse_transform(Forms, Opts) ->
    St0 = #st{opts = Opts, file = file_of(Forms)},
    %% pass 1：收集 -mustache_tag / -mustache_template，校验扩展模块
    St1 = lists:foldl(fun collect/2, St0, Forms),
    %% pass 2：展开 ai_mustache:inline/2，剔除已消费的 attribute
    {Forms1, St2} = lists:mapfoldl(fun expand/2, St1, Forms),
    %% pass 3：追加 -mustache_template 生成的函数与 export
    inject(Forms1, St2).
```

三 pass 的分工必须严格保持，各形态只往对应 pass 里加分支：

| pass | 职责 | 归属任务 |
|---|---|---|
| 1 collect | 扫描 attribute，构建 `#st{}`，做纯校验（不改 forms） | [T23](T23.md) 的 `-mustache_tag`、[T25](T25.md) 的 `-mustache_template` |
| 2 expand | 就地改写 forms：展开 inline、剔除已消费 attribute | [T24](T24.md) 的 `ai_mustache:inline/2` |
| 3 inject | 追加新 form：生成函数、补 export | [T25](T25.md) 的 `-mustache_template` 函数 |

### 2. 状态记录 `#st{}`

```erlang
-record(st, {
    file       :: file:filename_all(),        %% 来自 -file attribute
    module     :: module() | undefined,       %% 来自 -module attribute
    opts       :: [term()],                   %% parse_transform 的第二参数（compile options）
    ext_tags   = [] :: [{char(), {module(), atom()}, Line :: integer()}],  %% T23
    templates  = [] :: [{atom(), file:filename_all(), Line :: integer()}], %% T25
    counter    = 0  :: non_neg_integer(),     %% 生成变量/函数名的唯一序号
    errors     = [] :: [{integer(), module(), term()}],
    warnings   = [] :: [{integer(), module(), term()}]
}).
```

要点：

- `file` 必须**动态跟踪**而不是只取第一个 `-file`：include 展开后 forms 中会出现多个 `{attribute, L, file, {Path, Line}}`，诊断的 File 必须是当前 form 所在的真实文件。做法是在每个 pass 的遍历中遇到 `file` attribute 就更新 `#st.file`，因此 pass 1 用 `foldl`、pass 2 用 `mapfoldl` 而非无状态的 `map` 正是为此。
- `counter` 用于生成不与用户代码冲突的变量名与函数名。命名约定：变量 `'S__1'` / `'S__2'`（[06 §3](../designs/06-parse-transform.md) 的展开示例已用这个形态），函数 `'-mustache-inline-1-'`（带连字符的 atom 用户写不出来，天然无冲突）。**绝不使用可能与用户标识符重名的裸名**。
- `opts` 里可能有 `{mustache_opts, ...}`（通过 `erl_opts` 传给编译器），[T23](T23.md) / [T25](T25.md) 需要从中读 `views` / `extensions` 等。提供 `mopt(Key, Default, St)` 统一读取，且 rebar3 传入的形态与用户手写 `erlc` 的形态都要能读。

### 3. 错误与警告上报

[06 §5](../designs/06-parse-transform.md)：

> 错误通过标准 `{error, [{File, [{Line, ?MODULE, Reason}]}], []}` 返回，配合 `format_error/1` 输出可读诊断，与 erlc 一致。

实现细节：

- 正确的返回形状是 `{error, ErrorList, WarningList}`，其中 `ErrorList :: [{File, [{Line, Module, Reason}]}]`。**必须按 File 分组**，不能把不同文件的诊断塞进同一组，否则 erlc 打出的路径是错的。
- 只有警告时返回 `{warning, Forms, WarningList}`（保留 Forms 继续编译）；无诊断时直接返回新 Forms 列表。
- 三个 pass 全部跑完**再**统一决定返回值：一个模块里有多处错误时要一次报全，不能第一处就 throw 出去。因此 pass 内部遇到错误是往 `#st.errors` 累积并让该处 form 保持原样（或替换成一个安全占位），而不是中断。
- `errors` / `warnings` 累积时是逆序的，返回前 `lists:reverse/1` 并按 Line 稳定排序。
- `format_error/1` 覆盖所有 Reason，文案要求：说清**哪里错了**与**怎么改**。至少覆盖：
  - `{ext_module_not_found, M}` / `{not_an_ext_module, M}` / `{ext_missing_callback, M, {F, A}}` / `{marker_reserved, C}` / `{marker_conflict, C, Ms}`（[T23](T23.md)，文案与 [T21](T21.md) 的 `ai_mustache_ext_reg` 保持一致）
  - `{bad_mustache_tag, Term}` —— attribute 形状不对
  - `{inline_partial_unsupported, Name}`（[T24](T24.md)，[06 §3.3](../designs/06-parse-transform.md)）
  - `{inline_not_literal}` —— 第一参数非字面量的 warning（[T24](T24.md)）
  - `{template_not_found, Path, SearchedDirs}`（[T25](T25.md)），错误信息里**要列出实际搜过的目录**，否则用户无从下手
  - `{bad_mustache_template, Term}`
  - 模板编译错误 `{File, Line, Reason}` 的透传：模板的错误行号是**模板文件里的行号**，而诊断的 File 也应是模板路径，不是 `.erl` 路径。因此把它作为独立的一组塞进 `ErrorList`（`{TemplatePath, [{TplLine, ?MODULE, Reason}]}`），这样编辑器能直接跳到 `.mustache` 的出错行。
- 提供 `-compile({parse_transform, ai_mustache_transform})` 未生效时的正确行为：形态 (a) 丢失校验、形态 (b) 降级为运行期、形态 (c) 编译报错（未定义函数）—— 见 [06 §6](../designs/06-parse-transform.md) 的对比表，这一行为差异要在测试中固定。

### 4. forms 遍历的深度

pass 2 需要下钻到函数体内部找 `ai_mustache:inline/2` 调用（[T24](T24.md)），因此 `expand/2` 不能只在顶层 form 上做模式匹配，必须做**完整的 abstract format 递归遍历**。

选型：

- **推荐自己写递归遍历**，逐个 form 类型手工下钻（`function` → `clause` → 表达式树）。理由：需要精确控制哪些位置可以替换（表达式位置可以，pattern 位置与 guard 位置不可以 —— 在 guard 里出现 `ai_mustache:inline/2` 是非法代码，替换成 `begin ... end` 会产出更离谱的错误），`erl_syntax_lib:map/2` 无法区分这些上下文。
- 若用 `erl_syntax` 做遍历，注意 `erl_syntax:revert/1` 后的 forms 与原始 `erl_parse` forms 在注解上有差异，容易丢行号。手工遍历更可控。
- 遍历必须覆盖：函数子句体、`case` / `if` / `try` / `receive` 的各分支、list comprehension 的模板与限定符、`fun` 表达式（含 named fun）、`begin...end` block、二进制构造的表达式段、map 构造与更新的 key/value、record 构造与更新的字段。**遗漏任何一处都会让 inline 静默降级为运行期**，这类 bug 极难发现，所以要有针对性的测试逐一覆盖。
- 遍历时保持行号注解不变：替换生成的新表达式一律用被替换节点的行号，这样堆栈仍指回用户源码的正确行。

### 5. 与 compiler 的关系

[架构不变量 #2](../designs/02-architecture.md)：

> `ai_mustache_compiler` 是唯一的 AST → forms 实现，plugin 与 parse_transform 都不得旁路它。

因此 transform 的三个形态都只能通过 `ai_mustache_compiler:compile_inline/3`（形态 b）或 `ai_mustache_compiler:forms/2`（形态 c）产出代码，**不得**在 transform 里另写一套 forms 构造。transform 本身只负责：找到位置、准备 opts、调 compiler、把结果嵌回去、翻译错误。

编译期依赖：`ai_mustache_transform` 在**编译用户模块时**运行，所以它以及它调用的 scanner / parser / compiler 必须在编译期的 code path 上。rebar3 中 aihtml 作为 dep 时天然满足；用 `erlc` 手工编译时需要 `-pa`。这个前提要写进 README。

### 6. 幂等与重入

- `parse_transform/2` 对同一份 forms 跑两遍应产出相同结果（第二遍时 `-mustache_tag` 等 attribute 已被剔除，inline 已被展开，因此自然是无操作）。加一条测试。
- 与其它 parse_transform 共存：`-compile({parse_transform, X})` 可以有多个，执行顺序按声明顺序。`ai_mustache_transform` 不得假设自己是第一个或最后一个；特别是不能假设 forms 中一定有 `-module` 在最前（其它 transform 可能已经插入了 form）。取 module 名用「遍历找第一个 `{attribute, _, module, M}`」而非取 `hd(Forms)`。

## 验收标准

- [ ] `parse_transform/2` 的三 pass 结构与 [06 §5](../designs/06-parse-transform.md) 的骨架一致，各 pass 职责不混淆
- [ ] 无任何 mustache attribute / inline 调用的普通模块经过 transform 后 forms **逐字节等价**（无副作用）
- [ ] 一个模块中有多处错误时，一次编译报出全部错误，而非只报第一处
- [ ] 诊断按 File 正确分组：include 文件中的 attribute 报出的路径是该 include 文件而非 `.erl`
- [ ] 模板文件内的编译错误报出的 File 是 `.mustache` 路径、Line 是模板行号，编辑器可跳转
- [ ] `format_error/1` 覆盖所有 Reason，`{template_not_found, ...}` 的文案包含实际搜索过的目录列表
- [ ] 只有警告时返回 `{warning, Forms, Ws}` 且编译继续；无诊断时返回裸 Forms 列表
- [ ] pass 2 的表达式遍历覆盖 case / if / try / receive / list comprehension / fun / block / 二进制段 / map / record 各种位置，每种位置各有一条测试
- [ ] 替换后的表达式保留原节点行号（可通过异常堆栈行号断言）
- [ ] 与另一个 parse_transform 共存时（前后两种顺序）都能正确工作
- [ ] 对同一 forms 连跑两遍 transform 结果相同
- [ ] transform 不包含任何 AST → forms 的构造逻辑，全部委托给 `ai_mustache_compiler`
