# T20 · plugin 端到端测试

- **阶段**：4
- **依赖**：[T17](T17.md)、[T18](T18.md)、[T19](T19.md)
- **状态**：已完成

## 目标

用 `test/fixtures/` 下的真实小项目对 plugin 做端到端验证：`rebar3 compile` 全流程跑通、增量行为可观测、各类错误能报出可读诊断，并把「改 partial 不重编父模板」作为一条硬性可观测断言固定下来。

## 交付物

- `test/fixtures/plugin_basic/` —— 最小示例项目（rebar.config + views + 一个调用生成模块的测试模块）
- `test/fixtures/plugin_umbrella/` —— umbrella 项目，验证 per-app 配置与跨 app 重名 warning
- `test/fixtures/plugin_errors/` —— 各类错误场景（撞名、未闭合 tag、partial 缺失、非法模块名字符）
- `test/rebar3_aihtml_tests.erl` —— 单元级 EUnit：命名、冲突检测、opts 解析、改写规则
- `test/rebar3_aihtml_SUITE.erl` —— CT：驱动 fixture 项目跑 rebar3 并断言产物与输出
- `test/rebar3_aihtml_incr_SUITE.erl` —— CT：增量与幂等性专项
- `test/rebar3_aihtml_migrate_SUITE.erl` —— CT：migrate 的 diff / `--write` / 幂等性
- `test/rebar3_aihtml_test_lib.erl` —— fixture 复制、rebar3 子进程调用、mtime/hash 快照工具

> 测试框架分工照 [07 原则](../designs/07-roadmap.md)：本仓默认用 **EUnit**，**CT 只用于本任务的端到端场景**（需要起 rebar3 子进程、需要 `priv_dir` 隔离目录）。单元级部分走 EUnit。

## 实现要点

### 1. 测试驱动方式

两条路线，实现时**两条都要有**，各管一段：

**(A) 单元级（快，覆盖算法，EUnit）** —— 直接调 plugin 内部模块，不起 rebar3 进程：

- `rebar3_aihtml_name:module_of/2` 的映射表驱动测试
- `rebar3_aihtml_check` 的冲突检测、交叉校验（输入是构造好的路径集合与 partials 列表）
- `rebar3_aihtml_opts` 的默认值、app 级覆盖、未知 key warning
- stamp 计算的稳定性与敏感性（[T17](T17.md) §3）
- `rebar3_aihtml_rewrite` 的改写规则（[T19](T19.md) §2）

**(B) 端到端（慢，覆盖集成，CT）** —— 把 fixture 项目 `rebar_file_utils:cp_r/2` 复制到 CT 的 `priv_dir`，在副本里执行 rebar3：

- 用 `rebar_api` 的进程内 API 会污染 CT 进程的 state，**推荐起子进程**：`rebar3_aihtml_test_lib:run(Dir, Args) -> {ExitCode, Output}`，内部走 `open_port({spawn_executable, Rebar3}, [{cd, Dir}, {args, Args}, exit_status, stderr_to_stdout, binary])`。
- rebar3 可执行文件路径通过 `os:find_executable("rebar3")` 找；找不到时 `{skip, "rebar3 not on PATH"}`，不要让测试硬失败。
- fixture 的 `rebar.config` 用 `{plugins, [{rebar3_aihtml, {path, "..."}}]}`，路径在复制到 `priv_dir` 时由测试代码用 `code:lib_dir/1` 算出绝对路径写入 —— 不要在 fixture 里写死相对路径。同理 `{deps, [{aihtml, {path, "..."}}]}`。
- 每个 case 用独立的 `priv_dir` 副本，保证互不干扰、可并行。
- 设置 `REBAR_CACHE_DIR` / `REBAR_GLOBAL_CONFIG_DIR` 指向 `priv_dir` 下的临时目录，避免污染开发者的 `~/.cache/rebar3`，也避免 CI 上的缓存串味。

### 2. `plugin_basic` fixture 内容

```
test/fixtures/plugin_basic/
├── rebar.config          {provider_hooks, [{pre, [{compile, mustache}]}]} + mustache_opts + src_dirs 含 _gen
├── src/plugin_basic.app.src
├── src/pb_render.erl     调用 view_complex:render/1
└── views/
    ├── complex.mustache        引用 shared/item 与 shared/user
    ├── static.mustache         纯静态文本，验证常量折叠（04 §6）
    └── shared/
        ├── item.mustache
        └── user.mustache
```

模板按**新语义**（context stack）写，不是 v0.3.x 的扁平写法。

### 3. 端到端断言清单

**基础流程**

- `rebar3 compile` 退出码 0；`_gen/view_complex.erl` / `view_shared_item.erl` / `view_shared_user.erl` / `view_static.erl` 都存在
- 每个生成文件首行含 `Generated by rebar3_aihtml` 与 `DO NOT EDIT`，且含 `-mustache_source(#{...})`
- `_build/*/lib/plugin_basic/ebin/view_complex.beam` 存在
- 在 fixture 项目里跑 `rebar3 eval 'io:format("~s", [view_complex:render(#{...})])'`，输出与期望 HTML 完全一致（含 partial 的 standalone 缩进，见 [03 §6](../designs/03-semantics.md)）
- `view_complex:partials()` 返回 `[view_shared_item, view_shared_user]`
- `view_static:render_iolist/1` 的实现是单个 binary 字面量（常量折叠，[04 §6](../designs/04-codegen.md)）—— 断言方式：读生成的 `.erl` 文本，确认 `render_iolist` 子句体是一个 `<<"...">>`
- `rebar3 compile` 后不需要 `application:start(aihtml)` 即可渲染（[02 §2.4](../designs/02-architecture.md) 的 library app 性质）

**增量与幂等（对应 [T17](T17.md)）**

- 连跑两次 `rebar3 mustache`，第二次全部 skip：断言 `_gen/*.erl` 的 mtime 集合前后相同
- `touch views/complex.mustache`（内容不变）后重跑，仍全部 skip —— **这是「不用 mtime」的关键断言**
- 改模板内容（哪怕只加一个空格）后重跑，只有该模板对应的 `.erl` mtime 变化
- 改 `mustache_opts` 的 `line_map` 后重跑，所有 `.erl` mtime 变化
- 只改 `out_dir` 名字（同时改 `src_dirs`）不应导致内容差异 —— 生成文本逐字节相同
- `--force` 全量重编，但内容未变的文件 mtime 不变（[T17](T17.md) §4 的「内容相同不写盘」）
- 把 `_gen/view_complex.erl` 截断成半截后重跑，能自动重新生成且退出码 0

**改 partial 不重编父模板（[05 §3.2](../designs/05-rebar3-plugin.md) 的核心验收点，[07 阶段 4 验收](../designs/07-roadmap.md) 明确要求「可被观测验证」）**

- 记录 `_gen/view_complex.erl` 的 mtime + 内容 hash
- 修改 `views/shared/item.mustache` 的内容
- 重跑 `rebar3 mustache`
- 断言：`view_shared_item.erl` 被重写；`view_complex.erl` 的 mtime 与内容 hash **完全未变**
- 再跑一次渲染，输出反映了新的 partial 内容 —— 证明跨模块调用使新内容自动生效，无需重编父模板

**孤儿清理与冲突（对应 [T18](T18.md)）**

- 删掉 `views/static.mustache` 后重跑：`_gen/view_static.erl` 与 `ebin/view_static.beam` 都被删除，日志含 `removing orphan`
- 手工在 `_gen/` 放一个无生成标记的 `hand_written.erl`，重跑后它仍在，且有 warning
- 新增 `views/shared_item.mustache`（与 `views/shared/item.mustache` 撞名）后重跑：退出码非 0，stderr 同时含两个路径，且 `_gen/` 内容未被改动
- 删掉 `views/shared/item.mustache` 后重跑：退出码非 0，错误信息为 partial not found 且带 `views/complex.mustache` 的行号（证明父模板被强制重编后由 compiler 报错）
- 相互引用的两个 partial 能编译并渲染（无环检测误报）

**错误诊断格式**

- 未闭合 tag：输出精确匹配 `views/bad.mustache:3: unclosed tag {{#items}}` 的形状（`Path:Line: message`）
- 多个模板同时有错时，一次运行报出全部错误（断言输出中错误条数等于坏模板数）
- `warnings_as_errors` 为 true 时，未知配置 key 导致退出码非 0

**umbrella（`plugin_umbrella` fixture）**

- 两个 app 各自的 `views/` 被独立编译到各自的 `_gen/`
- app 级 `mustache_opts` 覆盖 project 级（如 app_b 用 `prefix = "b_"`）
- 两个 app 都有 `views/index.mustache` 且 prefix 相同时发出跨 app 重名 warning；配不同 prefix 后 warning 消失

**形态 c 的 staleness 兜底（[T17](T17.md) §6，与 [T25](T25.md) 交叉）**

- fixture 中放一个带 `-mustache_template({index, "views/index.mustache"})` 的模块
- 改该模板后跑 `rebar3 compile`，断言该 `.erl` 的 mtime 被更新且模块被重编（渲染输出反映新模板）
- 模板未变时该 `.erl` mtime 不变（否则每次 compile 都会重编，是回归）

**migrate（对应 [T19](T19.md)）**

- `plugin_legacy` fixture 用 v0.3.x 扁平写法；`rebar3 mustache migrate` 输出 diff 且不改文件
- `--write` 后文件按预期改写，改写后的模板能被 `rebar3 mustache` 编译且渲染结果与迁移前语义等价
- 对已迁移的模板再跑一次 migrate 产出零改动

### 4. CI 与运行时间

- 端到端 case 每个要起一次 rebar3 子进程，秒级开销。(A) 走 `rebar3 eunit`（本地开发默认只跑这一档），(B) 走 `rebar3 ct`（CI 跑全部）。`scripts/check.sh` 中把两者串起来。
- CT 套件设 `{timetrap, {minutes, 5}}`。
- **端到端测试跑的 rebar3 子进程会在 fixture 副本里再次编译本 plugin**，注意别让内层 rebar3 继承外层的 `REBAR_*` 环境变量导致递归或缓存冲突；显式清掉不需要的变量。
- fixture 项目的 `_build/` 与 `_gen/` 必须在 `.gitignore` 中，且测试跑在 `priv_dir` 的副本上，源 fixture 目录始终干净 —— 加一条 case 在套件末尾断言源 fixture 目录无 `_build` / `_gen`。

## 验收标准

- [ ] `rebar3 eunit`（单元级）与 `rebar3 ct`（端到端）都全绿，退出码 0
- [ ] 单元级用 EUnit、端到端用 CT，分工与 [07 原则](../designs/07-roadmap.md) 一致
- [ ] 「改 partial 不重编父模板」有一条独立的、断言 mtime 与内容 hash 均未变的 case
- [ ] 「touch 模板但内容不变 → 全部 skip」有独立 case（证明不依赖 mtime）
- [ ] 撞名、未闭合 tag、partial 缺失、非法模块名字符四类错误各有一条 case，均断言退出码非 0 且输出为 `Path:Line: message` 格式
- [ ] 孤儿清理、手写文件保护各有一条 case
- [ ] umbrella fixture 验证 app 级配置覆盖与跨 app 重名 warning
- [ ] `-mustache_template` staleness 兜底有正反两条 case（模板变 → touch；模板不变 → 不 touch）
- [ ] migrate 的 diff / `--write` / 幂等性各有一条 case
- [ ] `examples/` 目录能用 plugin 全流程跑通（[07 阶段 4 验收](../designs/07-roadmap.md)）
- [ ] 找不到 rebar3 可执行文件时端到端组 skip 而非 fail
- [ ] 测试运行后源 fixture 目录无 `_build` / `_gen` 残留
