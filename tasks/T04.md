# T04 · spec 驱动 CT suite

- **阶段**：1
- **依赖**：T03
- **状态**：已完成

## 目标

把 136 个官方 spec case 逐一暴露为独立命名的测试，成为阶段 2/3 的 TDD 回归网。

## 交付物

- `test/ai_mustache_spec_tests.erl` —— spec 驱动的 EUnit 测试

## 实现要点

### 为什么是 EUnit 而不是 Common Test

CT 的 testcase 名必须是模块中**静态导出**的函数，无法从 spec 数据动态生成 136 个；变通做法（代码生成一个 suite 源文件、或把一个 spec 模块塞进一个 testcase 里循环断言）要么引入衍生代码，要么让一个失败掩盖其余、看不出通过率。

EUnit 的 generator（`*_test_/0` 返回 `{Title, Fun}` 列表）天生就是数据驱动测试的形态，每个 case 有独立标题和独立失败报告。**本项目的测试全部是纯函数验证，EUnit 是合适的默认选择**；CT 留给真正需要它的场景（[T20](T20.md) 的 plugin 端到端测试要起 rebar3 子进程）。

### 每个 spec case 一个具名测试

```erlang
module_tests(Mod) ->
    Cases = ai_mustache_test_lib:load_spec(Mod),
    Names = ai_mustache_test_lib:name_to_atoms([maps:get(name, C) || C <- Cases]),
    [{atom_to_list(Name), fun() -> exec(Case) end}
     || {Name, Case} <- lists:zip(Names, Cases)].
```

外层按 spec 模块分组：`[{atom_to_list(Mod), module_tests(Mod)} || Mod <- required_specs()]`。

### 失败信息必须可调试

断言要把 template 一起带进去，否则只看到两个 binary 不等，无从下手：

```erlang
exec(#{template := T, data := Data, partials := P, expected := Expected}) ->
    Ctx = ai_mustache_test_lib:to_ctx(Data),
    Got = ai_mustache:render_string(T, Ctx, #{partials => P}),
    ?assertEqual({Expected, T, Ctx, P}, {Got, T, Ctx, P}).
```

把 template/ctx/partials 放进 `?assertEqual` 的两侧（两侧都放，保证只在渲染结果不同时才失败），EUnit 的 diff 输出里就能直接看到是哪个模板挂了。

### 阶段 1：inventory 真跑，conformance 挂起

一致性测试在未实现时**不生成**，代之以一条标题明确写着 PENDING 的空测试。但同时要有一组**真正会跑**的 inventory 测试，验证 vendoring 与加载器本身：

- 6 个必选模块的 case 数分别为 12 / 14 / 42 / 22 / 12 / 34
- 总数为 136
- 3 个可选模块可加载且非空
- 每个模块内 `name_to_atoms/1` 归一后无重名

这样阶段 1 的绿是**真实的绿**（确实验证了东西），而不是靠空转换来的。vendoring 被截断、JSON 解析出错、归一函数写错，都会在这里立刻暴露。

### 可选模块不纳入验收

`optional-dynamic-names` / `optional-inheritance` / `optional-lambdas` 只做「可加载且非空」的 inventory 断言，不做一致性断言。它们对应 designs/03 第 8 节的 known deviation。

## 验收标准

- [ ] `rebar3 eunit --module ai_mustache_spec_tests` 退出码为 0
- [ ] inventory 测试真实运行并通过（不是空转）
- [ ] 6 个必选模块的 case 数断言分别为 12 / 14 / 42 / 22 / 12 / 34，总数 136
- [ ] 每个模块内归一后的用例名无重名，有断言保护
- [ ] 一致性测试在未实现时显示为 PENDING 且不报失败
- [ ] 人为构造一个失败时，输出中能看到出问题的 template
