## 实现要点

### 扩展语法的测试范围

官方 spec 不覆盖以下 aihtml 扩展，必须自建用例（designs/03 第 2 节与第 8 节）：

**`{{+x}}` has section** —— 纯布尔判定，**不压栈不迭代**：
- `x` 为 `true` / 非空 binary / 非空 map / 非空 list 时执行 body
- `x` 为 `undefined` / `false` / `[]` / `<<>>` / `null` 时不执行
- `x` 为 `fun/1` 时调 `F(CurrentFrame)`，返回 `true` 才执行
- **关键断言：body 内的作用域不变**。`{{+user}}{{user.name}}{{/user}}` 能取到值，而 `{{+user}}{{name}}{{/user}}` 取不到 —— 这正是 `{{+}}` 与 `{{#}}` 的区别

**`{{-x}}` inverted has** —— 上述逻辑取反

**`{{*f}}` lambda**：
- `fun/1` 形态：`#{yield => fun(Frame) -> ... end}`
- `fun/2` + 值形态：`#{yield => [fun f/2, <<"index">>]}`
- 返回值可以是 `binary()` 或 `iolist()`
- **不做转义** —— lambda 的用途就是产出 HTML，用例要断言返回的 `<b>` 不被转义

**section 分派表**（designs/03 第 3 节）逐行覆盖：`[]` / 非空 list / map / `true` / `fun/2` / `fun/1` / falsy / 其它标量，共 8 条分支。

**falsy 定义**（designs/03 第 2.1 节）：`undefined` / `false` / `[]` / `<<>>` / `null` 为假；**`0` 和 `#{}` 为真** —— `0` 为真是常见踩坑点，必须有专门用例锁死。

**escape 字符集**（designs/04 第 5.1 节）：断言 `& < > " '` 五个被转义，且 `/` `=` 反引号 **不被**转义。这是相对 v0.3.7 的行为变更（旧实现转义 8 个字符，会把 `href="/a/b"` 破坏成 `href="&#x2F;a&#x2F;b"`），必须有用例锁死新行为。同时断言 `&` 转成 `&amp;` 而非旧实现的 `&amp`（bug B3）。

### 组织成用例表

把用例写成 `{Title, Template, Context, Expected}` 四元组的分组表，行为测试与表本身解耦：

```erlang
all_cases() ->
    [{"has", has_cases()}, {"has scope", has_scope_cases()},
     {"inverted has", inverted_has_cases()}, {"lambda", lambda_cases()},
     {"section dispatch", section_dispatch_cases()}, {"falsy", falsy_cases()},
     {"escape", escape_cases()}, {"number", number_cases()}].
```

### 阶段 1 的形态

与 [T04](T04.md) 一样：行为测试在未实现时不生成，代之以标题写明 PENDING 的空测试；但**表的良构性检查真跑** —— 每个 case 的 template 非空 binary、expected 是 binary、标题全局唯一。这样阶段 1 的绿仍然验证了东西（表写错会立刻暴露），而不是空转。

用例本身按**新语义**写，阶段 3 实现完成后直接点亮，不需要回头改任何一行。

### ai_mustache_test_lib 的自测

支撑库自己也要有测试，否则 spec 全绿可能只是转换写错了：
- `to_ctx/1` 对裸整数 `85`、`null`、`1.21`、嵌套 map/list 的转换
- `name_to_atom/1` 的归一与重名处理
- `load_spec/1` 对 6 个必选模块的 case 数断言（12/14/42/22/12/34）

这个 suite **不 skip**，阶段 1 就应该全绿。

### scripts/check.sh

```sh
#!/bin/sh
set -e
rebar3 compile
rebar3 as test compile
rebar3 eunit
rebar3 xref
rebar3 dialyzer
```

dialyzer 放最后：它首次运行要建 PLT，耗时数分钟，前面的快速检查先失败能省时间。脚本里要有一行提示说明这一点。
