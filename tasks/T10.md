# T10 · parser / scanner 单元测试

- **阶段**：2
- **依赖**：[T07](T07.md)、[T08](T08.md)、[T09](T09.md)

## 目标

为词法、语法、后处理三层建立单元测试网，覆盖全部 tag 类型与边界情形，并把阶段 2 声称修掉的 bug（B4 / B5）与性能问题（P1 / P2 / P3）逐条转成可执行的回归用例。

## 交付物

- `test/ai_mustache_scanner_tests.erl` —— 词法层测试
- `test/ai_mustache_parser_tests.erl` —— 语法层测试
- `test/ai_mustache_ast_tests.erl` —— 后处理三 pass 测试

## 实现要点

### 1. 框架与组织

**用 EUnit，不用 CT**（[designs/07-roadmap.md](../designs/07-roadmap.md) 原则段：CT 的 testcase 名必须静态导出，EUnit 的 generator 天生适配数据驱动测试；CT 留给 plugin 端到端）。文件名沿用阶段 1 已确立的 `*_tests.erl` 约定，`rebar3 eunit` 自动发现。

用**表驱动 + generator**，一张表一个 `_test_()`：

```erlang
-include_lib("eunit/include/eunit.hrl").
-include("ai_mustache.hrl").

tags_test_() ->
    [{Title, ?_assertEqual(Expected, strip_loc(scan(Input)))}
     || {Title, Input, Expected} <- tag_cases()].
```

每个 case 带独立标题，失败报告能直接指出是哪一条。

断言直接比对 AST / token term（`?assertEqual`），不做字符串比对 —— 阶段 2 还没有渲染能力，AST 就是唯一可观测输出。写 `strip_loc/1` 辅助函数把 `loc()` 抹成 `{0, 0}`，只在位置专项里才比对真实位置。三个文件共用的辅助函数放进阶段 1 已有的 `test/ai_mustache_test_lib.erl`，不要各写一份。

### 2. scanner：token 流

对每类 tag 至少一个用例，断言 token 列表：

- `{{x}}` → `{tag, _, none, <<"x">>, <<>>}`
- `{{ x }}` → 内容已 trim 为 `<<"x">>`
- `{{{x}}}` 与 `{{&x}}` → 都归一为 `${` marker
- `{{#x}}` / `{{^x}}` / `{{/x}}` / `{{>x}}` / `{{+x}}` / `{{-x}}` / `{{*x}}`
- `{{!comment}}` → **不产 token**
- `{{! multi\nline\ncomment }}` → 不产 token，但**后续 token 的行号要 +2**
- `{{=<% %>=}}` → 不产 token，后续用新分隔符
- 相邻文本可以是多个 `{text, ...}`（scanner 不合并，合并是 T09 的事）

### 3. scanner：standalone 矩阵

最容易写错、也最值得堆用例的一组。每个 marker × 每种上下文做矩阵：

| 上下文 | 期望 |
|---|---|
| `"a\n  {{#x}}\nb\n  {{/x}}\nc\n"` | 两个 tag 行整行消失，文本为 `a\nb\nc\n` |
| `"a{{#x}}\n"` | 前面有非空白，**不是** standalone，`\n` 保留 |
| `"  {{#x}}  y\n"` | 后面有非空白，**不是** standalone |
| `"  {{#x}}  \r\n"` | 是 standalone，`\r\n` 一并吃掉 |
| `"  {{#x}}  "`（EOF 无换行） | 是 standalone |
| `"  {{x}}  \n"` | 变量 tag **永不** standalone，空白与换行全保留 |
| `"  {{{x}}}  \n"` | 同上 |
| `"  {{*f}}  \n"` | lambda **永不** standalone |
| `"  {{!c}}  \n"` | 注释是 standalone |
| `"  {{=<% %>=}}  \n"` | 分隔符是 standalone |
| `"    {{> p}}\n"` | standalone，且 token 的 `Indent =:= <<"    ">>` |
| `"x {{> p}}\n"` | 非 standalone，`Indent =:= <<>>` |
| `"  {{+x}}\ny\n  {{/x}}\n"` | `+` / `-` 参与 standalone（旧实现此处行为混乱，见 [T07](T07.md) §6） |

单独的 `\r`（不跟 `\n`）不算换行，要有用例。

### 4. scanner：自定义分隔符

- `{{=<% %>=}}` 之后 `<%x%>` 生效
- 任意长度分隔符：`( )`、`|| ||`、`<% %>` 三组各一例
- 切回：`<%={{ }}=%>` 之后 `{{x}}` 生效
- section 内切换分隔符，出 section 后**仍然是新分隔符**（mustache 的分隔符是流式状态，不随块作用域回滚）
- 错误：`{{=<% %>}}`（尾部缺 `=`）、`{{=a=b c=}}`（含 `=`）、`{{= x =}}`（只有一段）→ `{invalid_delimiter, _}`

### 5. scanner：位置信息

对一段多行模板逐 token 断言 `{Line, Col}`：

- 首行首列是 `{1, 1}`
- 跨 `\n` 后 Line +1、Col 重置为 1
- `\r\n` 只算一次换行
- 多行注释、多行 section body 之后的行号仍准确
- 分隔符切换之后的行号仍准确
- tag 的 loc 指向 `{{` 而非内容首字符

### 6. parser：错误诊断

**全部错误必须以 `{error, {File, Line, Reason}}` 返回，不得抛异常**，用例要显式 `?assertMatch({error, {_, _, _}}, ...)` 并断言 Reason 与 Line：

| 输入 | Reason | Line 断言 |
|---|---|---|
| `"{{#a}}"` | `{unclosed_tag, [a]}` | 指向 `{{#a}}` 所在行，**不是**末行 |
| `"{{#a}}{{/b}}"` | `{mismatched_close, [a], [b]}` | 指向 `{{/b}}` |
| `"{{/a}}"` | `{mismatched_close, [], [a]}` | 指向 `{{/a}}` |
| `"{{x"` | `{unclosed_tag, _}` | 指向 `{{` |
| `"{{@k}}"`（未注册 `@`） | `{unknown_marker, $@}` | 指向 tag |
| `"{{> }}"` | `{partial_not_found, <<>>}` | 指向 tag |
| `"{{> ../x}}"` | 路径穿越报错 | 指向 tag |
| `"{{=a b c=}}"` | `{invalid_delimiter, _}` | 指向 tag |

嵌套三层未闭合时，报的是**最内层还是最外层**要有明确用例固化行为（建议：报最内层未闭合的那个块，信息最贴近出错点）。

### 7. parser：节点形状

token → 节点映射表（[T08](T08.md) §3）逐行一个用例，断言产出的 AST 节点 tag 与字段：`var`（escape / raw 两种）、`section`、`inverted`、`has`（`true` / `false` 两种）、`lambda`、`partial`、`ext`、`text`。

嵌套用例：`{{#a}}{{#b}}{{x}}{{/b}}{{/a}}` 的三层结构、`{{#a.b}}...{{/ a.b }}`（空白不同仍闭合）。

### 8. 回归用例：bug 编号对应

每个用例的标题里写明修的是哪个编号，方便日后回看：

- **B4** —— `"{{> layout.default}}"` 解析成功，节点为 `{partial, _, <<"layout.default">>, <<>>}`；`"{{> shared/item}}"` 同理。旧实现在这里 `function_clause`。
- **B5** —— `"{{.}}"` 解析为 `{var, _, ['.'], escape}`；`"{{{.}}}"` 为 `{var, _, ['.'], raw}`；`"{{#a}}{{.}}{{/a}}"` 中内层节点同样是 `['.']`。
- **P2** —— `"{{+x}}a{{! c }}b{{/x}}"` 经 `merge_text/1` 后，`has` 的 body 是**单个** `{text, _, <<"ab">>}`。旧实现在 `{has, ...}` 内不合并。对 `inverted` 与 `ext` 的 body 各补一个同型用例。
- **P3** —— `"{{#a}}{{#b}}{{/b}}{{/a}}"` 经 `drop_empty/1` 后，内层空 section 的处置符合 [T09](T09.md) §4 表格；且断言 `drop_empty/1` 确实下钻（旧实现只处理顶层）。
- **P1** —— 不测行为测规模：生成 5000 个交替的 `{{!c}}` 与文本片段，断言 `merge_text/1` 在 1 秒内完成（`timer:tc/1`）。O(n²) 实现在这个量级会明显超时。阈值放宽到 CI 机器也能过，目的是抓住数量级退化而非精确耗时。该用例包在 `{timeout, 30, ...}` 里防止 EUnit 默认 5 秒超时误杀。

### 9. 后处理三 pass

- `merge_text/1` 合并后 `loc()` 取首片段
- `merge_text/1` 幂等
- `drop_empty/1` 对 `section` / `inverted` / `has` / `ext` 四类的处置符合 [T09](T09.md) §4 表格
- `resolve_partials/2` 的模块名归一化：`shared/item` → `view_shared_item`、`layout/default` → `view_layout_default`、`a-b/c` → `view_a_b_c`
- Deps 去重且排序
- 嵌套在 section 内的 partial 进入 Deps
- 自定义 `prefix` 生效
- `postprocess/2` 幂等（`term_to_binary/1` 比对）
- **确定性**：同一模板连续 postprocess 100 次，结果 `term_to_binary/1` 全部相同（增量编译 hash 的前提）

### 10. 与 spec 测试的分工

`test/ai_mustache_spec_tests.erl`（阶段 1 建立）走**端到端渲染**，阶段 2 结束时一致性用例仍全部挂起。本任务的三个文件是**结构断言**，即便渲染尚未可用也必须全绿真跑。二者互不替代：spec 保证语义正确，本组保证 AST 形状与错误诊断正确。

本任务的用例**一律真跑，不允许出现挂起**（`{skip, ...}` / `?_test(ok)` 占位）—— 阶段 2 的实现就是它们的被测对象。

### 11. 零依赖

测试代码不得引入任何外部库；断言用 `eunit/include/eunit.hrl`，计时用 `timer:tc/1`。
