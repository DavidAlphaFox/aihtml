# T47 · if / for / set / with / filter / do codegen

- **阶段**：12
- **依赖**：[T46](T46.md)
- **状态**：已完成

## 目标

实现第一档语句的代码生成，含作用域串行穿引与 `for` 的两种生成形态。

## 交付物

- `src/ai_jinja_compiler.erl` —— 语句编译部分
- `test/ai_jinja_stmt_codegen_tests.erl`

## 实现要点

### 1. `if`

[11 §4.1](../designs/11-jinja-codegen.md)。扁平 elif 链编译成嵌套 `case`。

**作用域逃逸**：`if` 不是作用域，分支内的 `set` 要逃逸到 case 之后
（[10 §2.4](../designs/10-jinja-semantics.md)）。因此当任一分支推进了作用域变量时，
所有分支统一返回 `{Iolist, Scope}` 元组，case 的结果匹配成 `{E__, V1}`。

**没有分支含 set 时退化为普通 case**（绝大多数情况），编译期可判定。
这个优化要有用例证明生成的 forms 里确实没有多余的元组。

### 2. `for`

[11 §4.2](../designs/11-jinja-codegen.md)。三种生成形态，按需选择：

| 条件 | 形态 |
|---|---|
| 无 `loop` 引用、无 else、无 namespace 累加 | list comprehension |
| 需要 `loop` | `lists:foldl/3` 带索引 |
| `recursive` | 命名 fun `fun Rec__/2` |

「body 是否引用 loop」由遍历 body 的 AST 判定 —— **要下钻到嵌套的 if/with 里**，
但**不下钻到嵌套的 for**（内层 for 的 `loop` 是它自己的）。这条容易做错。

`{% for %}...{% else %}`：外层包 `case Items__ of [] -> <Else>; _ -> <Loop> end`。
`Items__` 只求值一次。

内联 filter `{% for x in xs if C %}`：list comprehension 加一个 filter 限定符；
foldl 形态里加一个 `case`。**注意 `loop.index` 计的是过滤后的序号**（Jinja2 语义）。

解构 `{% for k, v in m.items() %}`：generator 的 pattern 是 `{K__, V__}`。

**循环体的作用域不逃逸**（[10 §2.4](../designs/10-jinja-semantics.md)）：
list comprehension 与 foldl 都天然满足，只需保证循环后继续用循环前的作用域变量。

### 3. `set`

```erlang
%% {% set a = E %}
V1 = ai_jinja_rt:bind(V0, a, <E>)
```

推进作用域变量。这是唯一（连同 `set_block`）会推进它的节点。

块形式 `{% set a %}B{% endset %}` 把 body 包成 `{safe, [<B>]}`
（[11 §4.3](../designs/11-jinja-codegen.md)）。

namespace 赋值 `{% set ns.x = E %}`：v1 报
`{namespace_assignment_unsupported, Loc}`（[13 §5](../designs/13-jinja-roadmap.md)
的第一个可裁剪项）。若实现，按 [10 §2.5](../designs/10-jinja-semantics.md)
把外层 for 降级为 foldl 并把 namespace 作为累加器穿过迭代。

### 4. `with` / `filter` / `do`

```erlang
%% {% with a = E %}B{% endwith %}
begin V1 = ai_jinja_rt:push(V0, #{a => <E>}), [<B>] end     % V1 不逃逸

%% {% filter f %}B{% endfilter %}
ai_jinja_filters:f({safe, [<B>]}, #{})

%% {% do E %}
begin _ = <E>, [] end
```

`{% do %}` 求值并丢弃。生成 `_ = <E>` 而非裸表达式，避免 unused 警告。

### 5. 缩进

沿用 mustache 的 bol 跟踪（[11 §6](../designs/11-jinja-codegen.md)）。
条件块之后的 bol 状态是「进入前的状态 AND body 结束时的状态」——
块可能不执行，只有两者一致才能确定。这条直接抄 `ai_mustache_compiler` 的注释与逻辑。

## 验收标准

- [ ] `if` 的 elif 链正确；分支内 `set` 逃逸到 case 之后
- [ ] 无 set 时不生成元组穿引（检查生成的 forms）
- [ ] `for` 的三种形态按条件正确选择，各有用例
- [ ] 「body 引用 loop」的判定下钻 if/with 但不下钻内层 for（专项用例）
- [ ] `{% for %}{% else %}` 的 `Items__` 只求值一次（带副作用的 filter 计数验证）
- [ ] 内联 filter 时 `loop.index` 计过滤后的序号
- [ ] 解构 `k, v` 正确
- [ ] 循环体内的 `set` 不逃逸到循环外
- [ ] `if` 内的 `set` 逃逸（与上一条成对）
- [ ] `{% set %}` 块与 `{% filter %}` 块不二次转义（[T42](T42.md) 的回归用例在此点亮）
- [ ] namespace 赋值报明确错误（或实现并有用例）
- [ ] `{% do %}` 不产出输出且无 unused 警告
- [ ] fixture 中 `if` / `for` / `set` 组用例全部点亮
