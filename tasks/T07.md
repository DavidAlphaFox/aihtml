# T07 · ai_mustache_scanner 实现

- **阶段**：2
- **依赖**：[T06](T06.md)
- **状态**：已完成

## 目标

从现有 `ai_mustache_parser` 中拆出纯词法层 `ai_mustache_scanner`，产出带 `loc()` 的扁平 token 流，并在词法层一次性解决 standalone、自定义分隔符、三花括号三件事。

## 交付物

- `src/ai_mustache_scanner.erl` —— 模板 binary → `[ai_mustache_token()]`，保留 bbmustache 的 MIT 版权头

## 实现要点

### 1. 接口

```erlang
-module(ai_mustache_scanner).
-include("ai_mustache.hrl").
-export([scan/1, scan/2]).

-spec scan(binary()) -> {ok, [ai_mustache_token()]} | ai_mustache_error().
-spec scan(binary(), Opts :: ai_mustache_opts()) -> {ok, [ai_mustache_token()]} | ai_mustache_error().
```

scanner **不做嵌套、不做配对**，`{{/x}}` 也只是一个 `{tag, Loc, $/, <<"x">>, Indent}`。嵌套结构完全交给 [T08](T08.md)。这样职责边界清晰，两边都能单独测。

### 2. 内部状态

```erlang
-record(st, {
    start      = ?AI_MUSTACHE_START :: binary(),
    stop       = ?AI_MUSTACHE_STOP  :: binary(),
    line       = 1                  :: pos_integer(),
    col        = 1                  :: pos_integer(),
    standalone = true               :: boolean(),   %% 当前位置之前本行是否只有空白
    markers    = []                 :: [char()]     %% 扩展 marker，来自 opts 的 extensions
}).
```

`start` / `stop` 是**可变**的（`{{=<% %>=}}`），所有匹配都必须读 `#st.start` / `#st.stop`，不得硬编码 `<<"{{">>`。

### 3. 位置跟踪

`loc()` 是 `{Line, Col}`，每消费一段 binary 就更新：

- 扫描该段中 `\n` 的个数 `N`；`N =:= 0` 时 `Col := Col + byte_size(Seg)`，否则 `Line := Line + N`、`Col := 最后一个 \n 之后的字节数 + 1`。
- 用 `binary:matches(Seg, <<"\n">>)` 一次拿到全部换行位置，不要逐字节递归。
- Col 按**字节**计而非 codepoint，文档中说明这一点；模板通常是 UTF-8，字节列号对定位仍然够用，且避免在热路径上做 unicode 解码。

token 的 `loc()` 一律取该 token **起始字符**的位置。tag 的 loc 取 `{{` 的位置，不是内容的位置 —— 错误信息里指回 `{{` 更符合直觉。

### 4. `split_tag/2` 的移植与去依赖

现有 `ai_mustache_parser:split_tag/2`（`attic/ai_mustache_parser.erl:207` 起）的三花括号处理逻辑是正确且经过验证的，**原样移植**，但必须做两处改造：

1. **去掉 `ai_function:while/2`** —— 项目已决定零依赖（决策 D5，[designs/02-architecture.md §6](../designs/02-architecture.md)）。原代码用它向前推进以吃掉连续的 `{`，改写成模块内的尾递归：

   ```erlang
   shift(Bin, Pos, Limit, StartTag, Len) when Pos =< Limit ->
       case binary:part(Bin, Pos, Len) =:= StartTag of
           true  -> shift(Bin, Pos + 1, Limit, StartTag, Len);
           false -> Pos
       end;
   shift(_, Pos, _, _, _) -> Pos.
   ```

2. **`[PreTag, Tag0]` 两元素返回值改为报错** —— 原实现在缺 `}}` 时返回两元素列表，由 `parse2/3` 的兜底子句 `error({incorrect_format, unclosed_tag})` 处理。新实现直接返回 `{error, {File, Line, {unclosed_tag, ...}}}`，不要 `error/1` 抛异常（编译期错误要能被 plugin 收集并批量报告，见 [designs/04-codegen.md §7](../designs/04-codegen.md)）。

保留 `repeatedly_binary/2` 与 `part/3` 两个辅助函数（判断 `{{{`/`}}}` 的对称补偿量 `S` / `E`）。

### 5. marker 识别

对切出的 tag 内容 `B`，先 `trim` 首部的空白（`\s` `\t`），再取首字符判定 marker：

| 首字符 | marker | 说明 |
|---|---|---|
| `$&` 或 `${` | `${`（统一归一为 raw） | `{{&x}}` 与 `{{{x}}}` 语义相同 |
| `$#` | `$#` | section |
| `$^` | `$^` | inverted |
| `$/` | `$/` | close |
| `$>` | `$>` | partial |
| `$!` | `$!` | comment，**scanner 直接吃掉不产 token** |
| `$=` | `$=` | delimiter，**scanner 内部消费，不产 token** |
| `$+` / `$-` | `$+` / `$-` | has / inverted has（aihtml 扩展） |
| `$*` | `$*` | lambda（aihtml 扩展） |
| 在 `#st.markers` 中 | 该字符 | 用户扩展 tag，产 `{tag, Loc, C, Rest, Indent}` |
| 其它 | `none` | 普通变量 `{{x}}` |

注意归一化的顺序：`{{&x}}` 与 `{{{x}}}` 在 `split_tag/2` 之后**内容形态不同**（前者内容是 `&x`，后者是 `{x`），两者都要映射到 raw。

**未注册的非字母 marker**：若首字符落在 `?AI_MUSTACHE_BUILTIN_MARKERS` 之外且不在 `#st.markers` 中，不能贸然当成变量名的一部分 —— 但也不能对所有符号报错（`{{x-y}}` 里的 `-` 不在首位不受影响，而 `{{@k}}` 未注册 `@` 时应报 `{unknown_marker, $@}`）。实现策略：只对**标点类首字符**（非字母、非数字、非 `_`、非 `.`）报 `{unknown_marker, C}`，其余按 `none` 处理。

内容尾部的空白用 `trim` 去掉；tag 内容中间的空白由 [T08](T08.md) 的 `keys/1` 处理。

### 6. standalone 处理

这是 scanner 里最容易写错的部分，规则（沿用现有 `standalone/3` 且补齐）：

**判定**：一个 tag 是 standalone，当且仅当

- 它的 marker 属于 `# ^ / > ! =` 与扩展块级 marker（`+` `-` 以及注册为 block 的扩展）之一 —— 普通变量 `{{x}}`、raw `{{{x}}}`、lambda `{{*x}}` **永不** standalone；
- 且该 tag 之前、本行行首之后只有空白（`\s` / `\t`）；
- 且该 tag 之后到行尾（含 `\n` 或 `\r\n`，或 EOF）也只有空白。

> 现有实现把 `{{+x}}` / `{{-x}}` 走 `State#state{standalone = false}` 传给 `parse_has/5`（`attic/ai_mustache_parser.erl:97`），随后 `parse_has` 又调 `standalone/3` —— 这条路径在旧代码里是混乱的。新实现里 `+` / `-` 是块级 marker，**参与 standalone 判定**，与 `#` / `^` 一致。

**动作**：

- 从前一个 `{text, ...}` token 尾部剥掉该行的前导空白；
- 从后续输入中吃掉行尾空白与紧随的 `\r\n` 或 `\n`；
- 剥掉的前导空白**作为 `Indent` 字段挂在该 tag token 上**（只有 partial 会用到，其它 marker 忽略即可）。

EOF 情形：tag 后只剩空白无换行，仍算 standalone，吃掉尾部空白。

`\r\n` 与 `\n` 都要处理；单独的 `\r` 不视为换行。

### 7. 分隔符切换

`{{=<% %>=}}`：内容形如 `=<% %>=`，去掉首尾 `=` 后按空白切成两段。

- 两段之外的任何形态（0 段、1 段、3 段以上）→ `{invalid_delimiter, Bin}`；
- 任一段中含 `=` → `{invalid_delimiter, Bin}`（沿用 `delimiters_may_not_contain_equals`）；
- 切换成功后更新 `#st.start` / `#st.stop`，且该 tag 参与 standalone 处理，**不产出 token**。

新分隔符可以是任意 binary（spec 的 Delimiters 模块用到 `<%` `%>`、`(` `)`、`||` 等），实现不得假设长度为 2。

### 8. 输出 token 流的形态

- 相邻 `{text, ...}` 允许存在（旧实现在遇到 `\n` 时会切段），合并由 [T09](T09.md) 的 `merge_text/1` 负责，scanner 不必自己合并。
- 空的 `{text, _, <<>>}` **不产出**（对应旧代码的 `?ADD` 宏语义）。
- 累积结果用 `[Token | Acc]` + 末尾一次 `lists:reverse/1`，禁止 `Acc ++ [X]`（这是 [P1](../designs/01-current-state.md) 的根因，不要在新代码里重现）。

### 9. 换行切段的取舍

现有 `parse1/3` 在 `binary:match(Bin, [StartTag, <<"\n">>])` 里把 `\n` 也当匹配点，目的是维护 standalone 标志。新实现由于要跟踪 `loc()`，本来就得扫描换行，可以保留同样的做法；但 `binary:matches/2` 一次批量取位置比逐段 `binary:match/2` 更省。二者选其一即可，关键是**不要逐字节递归**。

## 验收标准

- [ ] `scan/1`、`scan/2` 导出，返回 `{ok, [ai_mustache_token()]}` 或 `{error, {File, Line, Reason}}`，**不抛异常**
- [ ] 源码不引用 `ai_function` / `ai_string` / `ai_maps` 等 ailib 模块，`rebar3 xref` 无 `undefined_function_calls`
- [ ] `{{x}}` / `{{{x}}}` / `{{&x}}` / `{{#x}}` / `{{^x}}` / `{{/x}}` / `{{>x}}` / `{{!c}}` / `{{+x}}` / `{{-x}}` / `{{*x}}` / `{{=<% %>=}}` 十二类 tag 全部能切出
- [ ] 注释 token 与分隔符 token 不出现在输出流中
- [ ] 每个 token 的 `loc()` 与手工计算的 `{Line, Col}` 一致（含多行文本、`\r\n`、分隔符切换后的行号）
- [ ] standalone 的三条判定与两条动作在 `{{#}}` / `{{^}}` / `{{/}}` / `{{>}}` / `{{!}}` / `{{=}}` / `{{+}}` / `{{-}}` 上一致生效
- [ ] `{{x}}` 独占一行时**不**被当作 standalone（该行空白与换行必须保留）
- [ ] standalone partial 的 `Indent` 字段等于该行前导空白，非 standalone partial 的 `Indent` 为 `<<>>`
- [ ] 自定义分隔符支持任意长度（至少覆盖 `<% %>`、`( )`、`|| ||` 三组）
- [ ] 缺 `}}`、`=` 数量不对、分隔符含 `=` 时返回结构化错误而非 crash
- [ ] 累加器全部走 `lists:reverse/1`，全文件 grep 不到 `++ [`
