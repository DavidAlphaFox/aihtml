# T13 · ai_mustache_compiler:forms/2

- **阶段**：3
- **依赖**：[T09](T09.md)、[T11](T11.md)、[T12](T12.md)
- **状态**：已完成

## 目标

实现 AST → Erlang abstract forms 的完整模块生成，产出可被 `erl_prettypr:format/1` 打印成 `.erl`、也可被 `compile:forms/2` 直接编译的模块，落地标准 context stack 语义与 partial 缩进。

## 交付物

- `src/ai_mustache_compiler.erl` —— 本任务负责 `forms/2` 与共享的 body 编译核心（`compile_inline/3` 见 [T14](T14.md)）

## 实现要点

### 0. 唯一性约束

`ai_mustache_compiler` 是**唯一的 AST → forms 实现**，rebar3 plugin 与 parse_transform 都不得旁路它（[架构不变量 #2](../designs/02-architecture.md)）。因此 `forms/2` 与 [T14](T14.md) 的 `compile_inline/3` 必须共用同一套 body 编译逻辑，只是外层包装不同。本任务要先把这个「共用核心」的边界划清楚。

### 1. 接口

```erlang
-module(ai_mustache_compiler).
-include("ai_mustache.hrl").
-export([forms/2, compile_inline/3]).

-spec forms([ai_mustache_node()], ai_mustache_opts()) ->
        {ok, [erl_parse:abstract_form()], Deps :: [module()]} | ai_mustache_error().

-spec source_hash(Body :: binary(), ai_mustache_opts()) -> binary().
```

`source_hash/2` 见 §11 —— 它是 hash 的**唯一计算入口**，plugin 与 dev 都只调它。

> **设计文档不一致**：[designs/04-codegen.md §3](../designs/04-codegen.md) 的 `-export` 行写的是 `forms/3`，但紧接的 `-spec` 是 `forms([node()], opts())`（两参），[designs/07-roadmap.md](../designs/07-roadmap.md) 阶段 3 也写 `forms/2`。**以 `forms/2` 为准**。同一 export 行里的 `compile/3` 在两处 spec 中都没有定义，本阶段不实现（它属于 plugin 侧的「读文件 → 写文件」便利函数，若需要则放 [T15](T15.md)）。

### 2. 编译器状态

```erlang
-record(cs, {
    opts      :: ai_mustache_opts(),
    file      :: binary(),          %% 源模板路径，用于错误 tuple
    line_map  :: boolean(),         %% 默认 true
    counter=0 :: non_neg_integer(), %% sec_N / lam_N / inv_N 的序号
    aux  = [] :: [erl_parse:abstract_form()],  %% 反序累积的辅助函数 forms
    exts = #{}:: #{char() => module()}
}).
```

序号计数器全局单调递增（不是每层重置），保证函数名唯一且生成结果确定。辅助函数用 `[F | Aux]` 累积、最后 `lists:reverse/1`。

### 3. 生成的模块骨架

目标形态见 [designs/04-codegen.md §4](../designs/04-codegen.md)，逐项落地：

```erlang
-module(view_complex).

-mustache_source(#{path  => <<"views/complex.mustache">>,
                   hash  => <<...>>,
                   mtime => 1757203845,
                   vsn   => 1,
                   opts  => #{views => <<"views">>, prefix => <<"view_">>,
                              extensions => [], line_map => true}}).

-export([render/1, render_iolist/1, render_stack/1, render_stack/2, partials/0]).

render(Ctx)        -> erlang:iolist_to_binary(render_stack([Ctx], <<>>)).
render_iolist(Ctx) -> render_stack([Ctx], <<>>).
render_stack(S)    -> render_stack(S, <<>>).
partials()         -> [view_shared_item, view_shared_user].

render_stack(S, I) -> [ ... ].
```

要点：

- **`render/1` 的 Ctx 类型是 `term()` 而非 `map()`**，栈初始化为 `[Ctx]`。根 context 可以是裸整数 `85`（[designs/02-architecture.md §6.3](../designs/02-architecture.md)）。生成的 `-spec` 必须写 `term()`，且**不得**加 `when is_map(Ctx)` 守卫。
- `partials/0` 返回 `resolve_partials/2` 给出的 Deps，供 plugin 做缺失 partial 的交叉校验（[designs/05-rebar3-plugin.md §3.2](../designs/05-rebar3-plugin.md)）。
- `-mustache_source/1` 是**强制** attribute（[架构不变量 #5](../designs/02-architecture.md)），含 `path` / `hash` / `mtime` / `vsn` / `opts` **五**个键。`mtime` 由调用方（plugin）通过 opts 传入，compiler 不自己 stat 文件；`hash` 由 compiler 自己的 `source_hash/2` 算（见 §11）；`vsn` 取 `?AI_MUSTACHE_VSN`；`opts` 是**规范化后**的编译选项。
- **`opts` 字段不是冗余**（[designs/04-codegen.md §4 关键点 6](../designs/04-codegen.md)）：增量判断算的是「内容 + 编译选项 + compiler 版本」的组合 hash，dev 热重载（T27）要忠实复现 plugin 当初的编译，二者都需要 `views` / `prefix` / `extensions` / `line_map`。缺了它，改 `mustache_opts` 不会触发重编，dev 重编出来的模块也会和 plugin 产物不一致。
- 生成的模块**只依赖 `ai_mustache_rt` 与其它生成模块**（[架构不变量 #3](../designs/02-architecture.md)）—— 生成完成后跑一次自检，扫描 forms 里所有 `{remote, _, {atom,_,M}, _}`，`M` 不在 `[ai_mustache_rt | Deps]` 中就是实现 bug。

### 4. 节点 → forms 的映射

**`{text, _, Bin}`** → 字面量 `{bin, L, [{bin_element, L, {string, L, ...}, default, [binary]}]}`。用 `erl_parse:abstract(Bin)` 最省事且保证正确。**静态文本必须是字面量，不得在运行期拼接构造**（[架构不变量 #4](../designs/02-architecture.md)）—— 这样它们进 BEAM 的 literal pool，跨进程按引用共享，这正是替代 ets 深拷贝（[01 §4.1](../designs/01-current-state.md)）的核心收益。

**`{var, _, Keys, escape}`** → `ai_mustache_rt:escape(ai_mustache_rt:lookup(Keys, S))`

**`{var, _, Keys, raw}`** → `ai_mustache_rt:to_binary(ai_mustache_rt:lookup(Keys, S))`

**`{section, Loc, Keys, Body}`** → 生成 `sec_N/2` 与 `sec_N_body/2` 两个辅助函数，主 body 处放 `sec_N(S, I)` 调用。`sec_N/2` 的 case 分支**在编译期全部展开**（[designs/04-codegen.md §4](../designs/04-codegen.md) 关键点 5），照抄文档给出的七个子句：

```erlang
sec_N(S, I) ->
    case ai_mustache_rt:lookup(Keys, S) of
        []                       -> [];
        L when is_list(L)        -> [sec_N_body([E | S], I) || E <- L];
        M when is_map(M)         -> sec_N_body([M | S], I);
        true                     -> sec_N_body(S, I);
        F when is_function(F, 2) -> F(erlang:iolist_to_binary(sec_N_body(S, I)), hd(S));
        F when is_function(F, 1) -> ai_mustache_rt:section(F(hd(S)), fun sec_N_body/2, S, I);
        V                        -> ai_mustache_rt:section(V, fun sec_N_body/2, S, I)
    end.
```

子句顺序不可调换（`[]` 必须在 `is_list` 之前）。兜底两条走 [T12](T12.md) 的 `section/4`，那里再做 falsy 判定（`<<>>` / `false` / `undefined` / `null` 都落在兜底 `V` 子句）。

**list comprehension 是关键**：`[sec_N_body([E | S], I) || E <- L]` 干净高效，**不构造新 context map**。对比旧 `run_section/7` 每次迭代 `maps:merge(Ctx, ai_maps:put(Name, H, #{}))` 全量拷贝 —— 同时修掉 [B1](../designs/01-current-state.md)：`maps:merge` 是浅合并，`{{#a.b}}` 时 `Name = [a,b]` 会把 `Ctx` 里 `a` 下的所有兄弟键整体顶掉。压栈方案下这个 bug 结构性不存在。

**`{inverted, Loc, Keys, Body}`** → 生成 `inv_N/2`：

```erlang
inv_N(S, I) ->
    case ai_mustache_rt:truthy(ai_mustache_rt:lookup(Keys, S)) of
        false -> inv_N_body(S, I);
        true  -> []
    end.
```

**永不压栈**（[designs/03-semantics.md §2](../designs/03-semantics.md)）。

**`{has, Loc, Keys, Body, Positive}`** → 生成 `has_N/2`：

```erlang
has_N(S, I) ->
    V = case ai_mustache_rt:lookup(Keys, S) of
            F when is_function(F, 1) -> F(hd(S));
            X                        -> X
        end,
    case ai_mustache_rt:truthy(V) of
        Positive -> has_N_body(S, I);
        _        -> []
    end.
```

**不压栈不迭代** —— `{{+}}` 是条件渲染（if），`{{#}}` 是作用域进入 + 迭代（with / for），二者的差别就是压不压栈（[designs/03-semantics.md §4](../designs/03-semantics.md)）。`Positive` 在编译期已知，直接生成对应的字面 `true` / `false` 模式。

**`{lambda, Loc, Keys}`** → `ai_mustache_rt:lambda(ai_mustache_rt:lookup(Keys, S), hd(S))`。行内，无 body，**不转义**。

**`{partial, Loc, Mod, Indent}`** → 跨模块调用：

- `Indent =:= <<>>` → `Mod:render_stack(S, I)`
- 否则 → `Mod:render_stack(S, <<I/binary, Indent/binary>>)`，其中 `Indent` 是字面量

这实现了 spec 要求的 partial 多行缩进（[designs/03-semantics.md §6](../designs/03-semantics.md)）：`I` 逐层向下传递，每一层把自己的 standalone 缩进追加上去。旧实现只把 Indent 当普通文本插在 partial 前面，只缩进第一行。

**`I` 真正生效的地方**：`render_stack/2` 生成的 iolist 中，每个 `\n` 之后要插入 `I`。实现方式是把静态文本字面量在编译期按 `\n` 切分，生成 `[<<"line1\n">>, I, <<"line2\n">>, I, ...]`。当 `I` 在编译期可证明为 `<<>>` 时整个机制退化掉（见 §6 缩进静态化）。

**`{ext, Loc, Marker, Keys, Body}`** → 先把 `Body` 编译成 forms 列表，再调 `Mod:compile_tag(Marker, Keys, BodyForms, Opts)`（[designs/06-parse-transform.md §2.1](../designs/06-parse-transform.md)）。`Mod` 来自 `opts` 的 `extensions`。返回的表达式求值结果必须是 `iodata()`；marker 未注册报 `{unknown_marker, Marker}`。

### 5. 行号映射

`line_map => true`（默认）时，forms 中每个节点的 `Line` 直接用 AST 的 `loc()` 行号，模板出错时堆栈能指回 `.mustache` 的原始行。

- abstract forms 的 line 字段可以是整数或 `erl_anno:anno()`；用 `erl_anno:new(Line)` 更规范。
- 辅助函数上方生成注释 `%% {{# items}} —— views/complex.mustache:3`。**注释不进 abstract forms**（`erl_prettypr` 不打印它们）—— 需要注释就得在 forms 序列化成文本之后插入，或者改用 `erl_pp` + 自己拼接。实现时二选一，plugin 侧（阶段 4）会用到；本任务至少保证行号正确，注释是加分项。
- `line_map => false` 时全部用 `0`。

### 6. 编译期优化

[designs/04-codegen.md §6](../designs/04-codegen.md) 五项，本任务落地其中三项（其余两项与 [T14](T14.md) 一并在 [T15](T15.md) 收口）：

| 优化 | 本任务的落点 |
|---|---|
| 相邻字面量合并 | 已由 [T09](T09.md) `merge_text/1` 完成，compiler 只需不重新拆散 |
| 空 section 消除 | 已由 [T09](T09.md) `drop_empty/1` 完成 |
| **escape 静态化** | 静态文本在编译期已确定不需转义，**不生成任何 `escape/1` 调用**。这是天然成立的（`{text, ...}` 直接出字面量），但要写进测试：生成的 forms 里 `escape` 调用次数 === 模板中 `{{x}}` 的个数 |
| **缩进静态化** | 整个模板不含 standalone partial 时，`I` 恒为 `<<>>`：省掉按 `\n` 切分插入 `I` 的全部代码，`render_stack/2` 的第二参数生成为 `_I`。这是最有价值的一项 —— 大部分模板都吃到 |
| 常量折叠 | 整个模板无动态 tag 时，`render_iolist/1` 直接 `return` 单个 binary 字面量，`render/1` 同样返回字面量（省掉 `iolist_to_binary/1`）。见 [T15](T15.md) |

### 7. 输出是 iolist

生成代码全程构造 iolist，**只在 `render/1` 的最外层做一次 `iolist_to_binary/1`**。这修掉 [P4](../designs/01-current-state.md)：旧 runner 全程 `<<Acc/binary, X/binary>>`，且 `run_section/7` 与 lambda 分支重起 `<<>>` 累加器打断 ERTS 的尾部追加优化。`render_iolist/1` 可直接喂给 cowboy `Body`，省掉一次转换（[designs/02-architecture.md §5](../designs/02-architecture.md)）。

例外：`fun/2` 形态的 section lambda 必须收 `binary()`，那里显式 `erlang:iolist_to_binary/1`。

### 8. 错误处理

统一 `{error, {File :: binary(), Line :: pos_integer(), Reason}}`（[designs/04-codegen.md §7](../designs/04-codegen.md)）。本阶段 compiler 侧可能产出的 Reason：`{unknown_marker, Char}`、`{partial_not_found, Name}`（若 [T09](T09.md) 没拦住）。**不抛异常** —— plugin 要能收集多个错误批量报告。

### 9. 确定性

同一 AST + 同一 opts 必须生成**逐字节相同**的 forms（`term_to_binary/1` 可比对）。这是增量编译 hash 可靠的前提：序号计数器按遍历顺序分配、Deps 已排序（[T09](T09.md)）、不使用 `maps:to_list/1` 之类无序遍历（若必须遍历 map，先 `lists:sort/1`）。

### 11. `source_hash/2` —— hash 的唯一入口

[designs/04-codegen.md §4.1](../designs/04-codegen.md)：hash 必须由 **aihtml 侧**导出，plugin（[designs/05-rebar3-plugin.md §3.1](../designs/05-rebar3-plugin.md)）与 `ai_mustache_dev`（T27）都调它。

**绝不能让 plugin 自己算一份、dev 再算一份** —— 两侧口径一旦漂移，dev 会认为模块永远陈旧从而无限重编，plugin 会认为永远新鲜从而不重编。

计算输入固定为三项，缺一不可：

1. 模板内容 `Body`
2. **规范化后**的编译选项
3. `?AI_MUSTACHE_VSN`

**选项规范化也在这个函数里做**，规则：

- 只保留影响产物的项：`views` / `prefix` / `extensions` / `line_map`。`module` / `source` / `mtime` / `hash` 不进 hash（`module` 由文件路径唯一决定，`mtime` 天然抖动）。
- 缺省值显式补齐（`prefix` 缺省 `<<"view_">>`、`line_map` 缺省 `true`），否则「显式写了默认值」与「没写」会算出不同 hash。
- 路径归一为 binary，`extensions` 列表排序去重。
- 规范化结果转成有序的 proplist 再 `term_to_binary/1`（**不要**直接对 map 做 `term_to_binary/1` —— map 的内部顺序在不同 OTP 版本间不保证稳定）。

摘要算法用 `crypto:hash(sha256, ...)`；`crypto` 是 OTP 自带 application，不违反零依赖。返回 32 字节 binary。

同时导出规范化函数本身（如 `normalize_opts/1`），供 `-mustache_source` 的 `opts` 字段写入 —— attribute 里存的必须是**规范化后**的选项，dev 才能拿它原样复现编译。

### 10. 自检

生成 forms 后跑一次 `compile:forms(Forms, [return_errors, return_warnings])`（内存中，不落盘）作为自检，任何 error / warning 都说明 compiler 有 bug。这个自检在测试里跑，生产路径上由 plugin 的实际编译承担。

## 验收标准

- [ ] `forms/2` 返回 `{ok, Forms, Deps}` 或 `{error, {File, Line, Reason}}`，不抛异常
- [ ] 生成的 forms 经 `compile:forms/2` 编译**零 error 零 warning**（含 `warnings_as_errors`）
- [ ] 生成模块导出 `render/1`、`render_iolist/1`、`render_stack/1`、`render_stack/2`、`partials/0` 五个函数
- [ ] `render/1` 的 spec 中 Ctx 为 `term()`，无 `is_map` 守卫；根 context 为裸整数 `85` 时 `{{.}}` 渲染为 `85`
- [ ] 生成模块带 `-mustache_source/1` attribute，含 `path` / `hash` / `mtime` / `vsn` / `opts` 五个键，`opts` 是规范化后的选项
- [ ] `source_hash/2` 导出；输入相同时 hash 相同，改模板内容 / 改 `prefix` / 改 `extensions` / 改 `line_map` / bump `?AI_MUSTACHE_VSN` 五者任一都使 hash 变化
- [ ] `source_hash/2` 对「显式写默认值」与「不写该项」算出**相同** hash
- [ ] `source_hash/2` 不对 map 直接 `term_to_binary/1`（用有序 proplist），跨进程 / 跨次运行结果稳定
- [ ] `mtime` 变化但内容不变时 hash **不变**（git checkout / CI 缓存场景）
- [ ] `partials/0` 返回去重排序的依赖模块列表
- [ ] 生成 forms 中的 remote 调用只出现 `ai_mustache_rt` 与 Deps 中的模块（自检脚本可验证）
- [ ] 静态文本全部是 binary 字面量，forms 中不含运行期字符串拼接
- [ ] section 的七个 case 子句按文档顺序展开，`[]` 在 `is_list` 之前
- [ ] `{{#a.b}}` 嵌套 section 内可正确访问 `a` 的兄弟键（**B1 回归用例**）
- [ ] `{{^x}}` 与 `{{+x}}` 生成的代码不含压栈操作（forms 中无 `[_ | S]` 构造）
- [ ] standalone partial 生成 `Mod:render_stack(S, <<I/binary, "  ">>)` 形态，多行 partial 输出每行都带缩进
- [ ] 无 standalone partial 的模板不生成任何 `I` 拼接代码（缩进静态化生效）
- [ ] 生成 forms 中 `ai_mustache_rt:escape/1` 的调用次数等于模板中 `{{x}}` 的个数（escape 静态化）
- [ ] `line_map => true` 时 forms 的行号与模板行号一致；`false` 时全为 0
- [ ] 同一 AST 两次 `forms/2` 的 `term_to_binary/1` 结果一致
- [ ] `rebar3 eunit` 下 `ai_mustache_spec_tests` 的六个必选模块（Comments / Delimiters / Interpolation / Inverted / Partials / Sections，共 136 个 case）在编译执行路径下**全部由挂起转为通过**
