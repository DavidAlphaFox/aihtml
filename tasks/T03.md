# T03 · mustache 官方 spec vendoring 与测试支撑库

- **阶段**：1
- **依赖**：T01
- **状态**：已完成

## 目标

把 mustache 官方 spec 测试集固化进仓库，并提供零依赖的加载与转换支撑库，作为整个重构的回归基线。

## 交付物

- `test/spec/*.json` —— vendoring 的官方 spec 数据
- `test/spec/VERSION` —— 记录 vendoring 时的 spec commit
- `test/ai_mustache_test_lib.erl` —— spec 加载、数据转换、skip 判定

## 实现要点

### vendoring 范围

来源 <https://github.com/mustache/spec>，`specs/` 目录。

**必选模块**（6 个，共 136 个 case，必须全部通过）：

| 文件 | case 数 |
|---|---|
| `comments.json` | 12 |
| `delimiters.json` | 14 |
| `interpolation.json` | 42 |
| `inverted.json` | 22 |
| `partials.json` | 12 |
| `sections.json` | 34 |

**可选模块**（3 个，`~` 前缀，仅备查，不纳入验收）：`~dynamic-names.json`、`~inheritance.json`、`~lambdas.json`。文件名的 `~` 前缀在落盘时改为 `optional-` 前缀，避免 shell 与工具链对 `~` 的歧义。

只 vendoring `.json` 不要 `.yml` —— OTP 自带 JSON 解析，不自带 YAML。

`test/spec/VERSION` 记录来源 URL 与 commit SHA，便于日后同步上游。

### 零依赖的 JSON 解析

**OTP 27+ 的 stdlib 自带 `json` 模块**，直接 `json:decode/1`，不需要任何依赖：

```erlang
json:decode(<<"{\"a\":[1,1.21,true,null]}">>).
%% => #{<<"a">> => [1, 1.21, true, null]}
```

### ai_mustache_test_lib 接口

```erlang
-module(ai_mustache_test_lib).

-export([load_spec/1, spec_files/0, required_specs/0]).
-export([to_ctx/1, name_to_atom/1]).
-export([skip_unless_implemented/1]).

%% 读 test/spec/<Name>.json，返回该模块的全部 case
-spec load_spec(atom()) -> [#{name := binary(), desc := binary(),
                              data := term(), template := binary(),
                              partials := #{binary() => binary()},
                              expected := binary()}].
```

### 数据转换：binary key 转 atom

spec 的 data 用 string key，aihtml 用 atom key（这是 designs/03 第 8 节列明的 known deviation）。`to_ctx/1` 做递归转换：

- map 的 key：`binary_to_atom(K, utf8)`
- map 的 value、list 元素：递归
- 其它标量：**原样保留**（binary 保持 binary，integer/float 保持数值，`true`/`false`/`null` 保持 atom）

用 `binary_to_atom/2` 而非 `binary_to_existing_atom/2` —— spec 数据是仓库内固定内容，不是外部输入，且这些 atom 在模板解析时也会被创建。

### 三个必须处理的数据形态

1. **根 context 可以不是 map**。`interpolation.json` 的 `Implicit Iterators - Basic Integer Interpolation` 的 `data` 是裸整数 `85`。`to_ctx/1` 必须能处理非 map 的顶层输入，不能假设是 map。
2. **`null` 会出现**（6 处）。JSON `null` 解码为 atom `null`，属于 falsy 集合（designs/03 第 2.1 节），原样保留即可。
3. **浮点数**。`1.21`、`1.1`、`2.2` 等，必须原样保留为 Erlang float，由 T11 的 `to_binary/1` 用 `float_to_binary(F, [short])` 渲染成 `1.21` 而非 `1.21000000000000000000e+00`。

### 阶段判定

阶段 1 时 `ai_mustache` 尚未实现，spec 一致性测试必须能跑但不报失败：

```erlang
-spec implemented() -> boolean().
implemented() ->
    _ = code:ensure_loaded(ai_mustache),
    erlang:function_exported(ai_mustache, render_string, 3).
```

调用方据此决定是否生成一致性用例。随着阶段 2/3 落地，这个判定自动失效，测试自然点亮，**不需要回头改任何测试代码**。

> `render_string/3` 是给 spec 测试用的直接渲染入口（模板字符串 + context + 选项，选项里带 `partials`），不走文件与模块生成。它属于 [T15](T15.md) 的交付物。
