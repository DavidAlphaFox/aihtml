# T15 · ai_mustache 门面与编译期优化

- **阶段**：3
- **依赖**：[T13](T13.md)、[T14](T14.md)
- **状态**：已完成

## 目标

重写 `ai_mustache` 门面模块（去掉 ets / gen_server / 进程字典缓存的全部痕迹），实现 `inline/2` 的运行期降级路径，并收口 [designs/04-codegen.md §6](../designs/04-codegen.md) 中尚未落地的两项编译期优化。

## 交付物

- `src/ai_mustache.erl` —— 新门面：`render/2`、`render_iolist/2`、`inline/2`
- `src/ai_mustache_compiler.erl` —— 补齐常量折叠与缩进静态化两项优化（在 [T13](T13.md) / [T14](T14.md) 的基础上）

## 实现要点

### 1. 门面的新形态

```erlang
-module(ai_mustache).
-export([render/2, render_iolist/2, inline/2]).

-spec render(module(), term())        -> binary().
-spec render_iolist(module(), term()) -> iolist().
-spec inline(binary(), term())        -> binary().

render(Mod, Ctx)        -> Mod:render(Ctx).
render_iolist(Mod, Ctx) -> Mod:render_iolist(Ctx).
```

**`Ctx` 的类型是 `term()` 而非 `map()`。** 根 context 可以是非 map 的裸值（spec 的 `interpolation.json` 里 `Implicit Iterators - Basic Integer Interpolation` 的 data 就是整数 `85`，[designs/02-architecture.md §6.3](../designs/02-architecture.md)）。不得加 `when is_map(Ctx)` 守卫，dialyzer spec 也不能收窄成 `map()` —— 否则那条 spec case 直接挂。

门面存在的意义：**模板名在运行期才确定的场景**（如按路由派发布局模板）。实现就是一次 `Mod:render(Ctx)` 调用，**无查表开销**（[designs/02-architecture.md §5](../designs/02-architecture.md)）。

### 2. 必须删掉的旧行为

对照旧门面 `attic/ai_mustache.erl`（阶段 1 已移入 `attic/`），以下全部移除，一个不留：

- **`erlang:get/1` + `erlang:put/2` 的进程字典二级缓存**（现 `ai_mustache.erl:19-26`）。这是 [01 §4.2](../designs/01-current-state.md) 的核心问题：`reload/0` 对长生命周期进程（cowboy handler pool、gen_server）完全失效、每个 worker 各持一份 IR 拷贝导致内存 N 倍放大、ets 的 `read_concurrency` 优化白费。而且 key 直接用模板名，与调用方自己的进程字典**命名空间冲突**。
- **`bootstrap/0`、`bootstrap/1`、`reload/0`** 三个导出。它们全是 `ai_mustache_loader` 的转发；loader 已删（[designs/02-architecture.md §4](../designs/02-architecture.md)），aihtml 退化为 library app，**使用方不再需要 `application:start(aihtml)`**。
- **`ai_mustache_runner:render/2` 的调用** —— 解释器已被生成代码取代。

`bootstrap/1` 的 `view_path` / `suffix` 配置去哪了：搬到 `{mustache_opts, [...]}` 编译选项（[designs/05-rebar3-plugin.md §1](../designs/05-rebar3-plugin.md)），编译期消费。这顺带修掉 [01 §4.3](../designs/01-current-state.md) —— 旧实现里 loader 崩溃会让 `bootstrap/1` 设的配置静默回退到 `init/1` 默认值。

**模板名不再 `binary_to_atom`**：旧 `ai_mustache_loader.erl:35` 对模板名做 `binary_to_atom/2`，模板名来自 HTTP 路由等外部输入时是 atom 表耗尽的 DoS 面（[01 §4.5](../designs/01-current-state.md)）。新门面的第一参数**就是 `module()`**，由调用方在编译期写死或从一个白名单里选，门面**不做任何字符串 → atom 转换**。这一点要在 module doc 中显式写明：「不要用 `binary_to_atom/2` 把外部输入转成模块名再传进来」。

### 3. `inline/2` 的运行期降级实现

`ai_mustache:inline/2` 必须**有真实实现**，不能只是给 parse_transform 用的占位符（[designs/06-parse-transform.md §3.1](../designs/06-parse-transform.md)）：

- **加了 parse_transform** → [T14](T14.md) 的 `compile_inline/3` 在编译期展开，零运行时开销
- **没加** → `inline/2` 的运行期实现照常工作，只是慢

**语义必须完全一致**。这让「忘了加 `-compile({parse_transform, ai_mustache_transform})`」不会变成一个难查的 bug。

实现路径：`scan → parse → postprocess（跳过 resolve_partials）→ 解释求值`。

**关键决策：解释器怎么来？** 有两条路：

- **方案 A（推荐）：编译并缓存一个匿名 fun。** `compile_inline/3` 产出 abstract expression → 包成一个 `fun(Ctx) -> ... end` 的 form → `erl_eval:expr/2` 或 `compile:forms/2` + `code:load_binary/3`。但这需要缓存，而缓存需要 ets / persistent_term —— **违反[架构不变量 #1](../designs/02-architecture.md)**（运行期不使用 ets / persistent_term）。**不采用。**
- **方案 B（采用）：写一个小解释器，直接消费 AST。** 复用 `ai_mustache_rt` 的 `lookup/2` / `escape/1` / `to_binary/1` / `truthy/1` / `section/4` / `lambda/2`，对 AST 做递归求值。零状态、零缓存、零进程，完全符合架构不变量。代价是每次调用都重新 scan + parse —— 但这条路径本来就是「忘了加 transform」的降级路径，慢是可接受的、甚至是**有意的**（让人有动力去加 transform）。

方案 B 的解释器**不是**旧 `ai_mustache_runner` 的复活：它消费的是新 AST、走 context stack、输出 iolist、复用 rt 的分派表。约 80 行。可以放在 `ai_mustache.erl` 内部（不导出），或独立成 `ai_mustache_eval.erl`。

**`{{> x}}` 在 inline 中报错**（[designs/06-parse-transform.md §3.3](../designs/06-parse-transform.md)），运行期实现同样要报，错误信息与 [T14](T14.md) 的编译期错误一致。

**差分测试是本任务与 [T14](T14.md) 共同的核心验收项**：同一批模板 × 同一批 context，编译期展开与运行期降级两条路径输出逐字节相同。

### 4. 补齐：常量折叠

[designs/04-codegen.md §6](../designs/04-codegen.md)：**整个模板无动态 tag 时，`render_iolist/1` 直接返回单个 binary 字面量。**

判定：`postprocess/2` 之后的 AST 是 `[]` 或 `[{text, _, Bin}]`（`merge_text/1` 已保证连续文本合并成一个节点，所以这个判定是精确的）。

生成：

```erlang
render(_Ctx)        -> <<"...">>.
render_iolist(_Ctx) -> <<"...">>.
render_stack(_S)    -> <<"...">>.
render_stack(_S, _I)-> <<"...">>.
```

- `render/1` 也直接返回字面量，**省掉 `iolist_to_binary/1` 调用**。
- 参数全部下划线前缀，避免 `warn_unused_vars`。
- **例外**：模板含 standalone partial 时 `I` 有意义，但纯文本模板不可能含 partial，所以这个例外不存在。
- 空模板（AST 为 `[]`）折叠成 `<<>>`。

收益：布局片段、静态页这类模板的渲染退化为一次字面量返回，进 literal pool 跨进程零拷贝。

### 5. 补齐：缩进静态化

[designs/04-codegen.md §6](../designs/04-codegen.md)：**`I` 在编译期可确定为 `<<>>` 时（非 standalone partial），直接省掉参数传递。**

判定：AST 中递归查找，**不存在** `{partial, _, _, Indent}` 且 `Indent =/= <<>>` 的节点。

生效时：

- 所有辅助函数的第二参数生成为 `_I`（保留 arity 以维持 `render_stack/2` 的对外契约与跨模块调用形态一致，但函数体不使用它）。
- **不生成按 `\n` 切分插入 `I` 的代码** —— 这是真正省下来的部分。静态文本直接作为单个 binary 字面量输出，而不是被切成 `[<<"line1\n">>, I, <<"line2\n">>, I, ...]`。
- partial 调用生成 `Mod:render_stack(S, I)` 而非 `Mod:render_stack(S, <<I/binary, Indent/binary>>)`。

**大部分模板都吃得到这项优化** —— standalone partial 只在有意做多行缩进对齐的模板里出现。

注意：这是**本模板**的局部判定。被调用的 partial 模块自己可能含 standalone partial，它有自己的判定；`I` 参数照传，跨模块契约不变。

### 6. 与 `ai_mustache_dev` 的边界

[designs/02-architecture.md §5](../designs/02-architecture.md) 已修订为：

```erlang
ai_mustache_dev:check()           -> ok | {stale, [module()]}.
ai_mustache_dev:reload(Mod | all) -> ok | {error, term()}.
```

**`ai_mustache_dev` 没有「开关」** —— 架构不变量禁止 ets / persistent_term / 进程，因此无处存放启用状态。`check/0` 是一次性自检，`reload/1` 是显式重编重载，**触发必须由调用方显式发起**。

本任务**不实现** `ai_mustache_dev`（它在阶段 6 / T27）。但门面里**不得**埋任何「dev 模式自动检查」的钩子 —— 那会在热路径上加一次 `module_info(attributes)` 调用，且引入 prod 对 dev 模块的依赖。门面 `render/2` 永远只是 `Mod:render(Ctx)`，一行。

### 7. module doc 要写清楚的三件事

`ai_mustache` 是用户的第一入口，doc 里必须讲明：

1. **推荐直接调生成模块** `view_index:render(Ctx)`，门面只在模板名运行期才确定时用。
2. **`render_iolist/2` 是纯收益** —— 可直接喂给 cowboy `Body`，省掉一次 `iolist_to_binary/1`。
3. **不要把外部输入转成模块名**（见 §2）。

### 8. 架构不变量自检

本任务是阶段 3 的收口，顺便把[架构不变量](../designs/02-architecture.md)转成可执行检查（放进 `scripts/check.sh`）：

- 不变量 1：`src/` 下 grep 不到 `ets:` / `persistent_term:` / `gen_server` / `erlang:put(` / `erlang:get(`（`ai_mustache_dev` 除外，且它不在 prod profile）
- 不变量 2：`ai_mustache_compiler` 之外无 `erl_syntax` / abstract forms 构造代码
- 不变量 3：生成模块的 remote 调用只落在 `ai_mustache_rt` 与其它生成模块
- 不变量 4：生成 forms 中静态文本全是字面量
- 不变量 5：每个生成模块带 `-mustache_source/1`

## 验收标准

- [ ] `ai_mustache` 只导出 `render/2`、`render_iolist/2`、`inline/2` 三个函数
- [ ] `bootstrap/0`、`bootstrap/1`、`reload/0` 已移除，README 与 examples 中无残留引用
- [ ] 新的 `src/ai_mustache.erl` 中无 `erlang:get/1`、`erlang:put/2`、无 ets、无 `ai_mustache_loader` / `ai_mustache_runner` 引用
- [ ] `render/2` 与 `render_iolist/2` 的 spec 中 Ctx 为 `term()`，无 `is_map` 守卫
- [ ] 门面不做任何字符串 → atom 转换，module doc 中有「不要用 `binary_to_atom/2` 转外部输入」的警示
- [ ] `render/2` 的实现体是单次 `Mod:render(Ctx)` 调用，无查表、无缓存、无 dev 钩子
- [ ] `inline/2` 有真实运行期实现，走方案 B（AST 解释器），不使用 ets / persistent_term / 进程字典
- [ ] `inline/2` 遇 `{{> x}}` 报错，错误信息与 [T14](T14.md) 编译期一致
- [ ] **差分测试**：至少 20 组（模板 × context）在「编译期展开」与「运行期降级」两条路径下输出逐字节相同
- [ ] 纯文本模板生成的 `render/1` 直接返回 binary 字面量，forms 中无 `iolist_to_binary/1` 调用（常量折叠）
- [ ] 空模板折叠为 `<<>>`，且 `warnings_as_errors` 下无 unused variable 告警
- [ ] 无 standalone partial 的模板生成代码中无任何 `I` 拼接、无按 `\n` 切分的静态文本（缩进静态化）
- [ ] 有 standalone partial 的模板仍生成 `<<I/binary, Indent/binary>>` 形态，多行 partial 每行都带缩进
- [ ] `scripts/check.sh` 中新增五条架构不变量检查，全部通过
- [ ] aihtml 是 library app（`.app.src` 无 `mod` 项），使用方无需 `application:start(aihtml)`
- [ ] `rebar3 eunit`、`rebar3 dialyzer`、`rebar3 xref` 全绿
- [ ] mustache 官方 spec 六个必选模块全部通过，known deviation 清单与实际一致
