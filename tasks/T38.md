# T38 · ai_jinja_expr —— 表达式语法分析

- **阶段**：9
- **依赖**：[T37](T37.md)
- **状态**：已完成

## 目标

把表达式 token 流解析成 `expr()` AST，严格实现 [09 §3.2/§3.3](../designs/09-jinja-syntax.md) 的优先级与文法。

## 交付物

- `src/ai_jinja_expr.erl`
- `test/ai_jinja_expr_tests.erl`

## 实现要点

### 1. 接口

```erlang
-spec parse([jinja_expr_token()]) -> {ok, expr(), Rest :: [jinja_expr_token()]}
                                   | {error, ai_jinja_reason()}.
-spec parse_all([jinja_expr_token()]) -> {ok, expr()} | {error, ai_jinja_reason()}.
-spec parse_args([jinja_expr_token()]) -> {ok, args(), Rest} | {error, ...}.
```

`parse/1` 解析一个表达式并返回剩余 token，供 `{% for x in xs if C %}` 这类
一个语句里有多个表达式的场景使用。

### 2. 优先级实现

递归下降，每级一个函数，严格对齐 [09 §3.3](../designs/09-jinja-syntax.md) 的 EBNF：

```
condexpr → or_expr → and_expr → not_expr → compare
         → math → term → power → filtered → signed → postfix → primary
```

**三个最容易写错的点，各要有专项用例：**

1. **`**` 是左结合**（[09 §3.2](../designs/09-jinja-syntax.md)）：`2**3**2` = `(2**3)**2`。
   与 Python 相反。用 while 循环左折叠，不要写成右递归。
2. **filter 挂在 `signed` 之外、`power` 之内**：
   `a + b|upper` = `a + (b|upper)`；`2**3|abs` = `2 ** (3|abs)`；`-a|abs` = `(-a)|abs`。
3. **比较不链式**：`compare` 最多消费一个比较运算符。
   若消费后下一个 token 还是比较运算符 → 报 `{chained_comparison, Loc}`
   （[10 §9](../designs/10-jinja-semantics.md) J3），**不要**静默折叠成 `(a<b)<c`。

### 3. `is` 的右侧是 test 名

`x is divisibleby(3)`。这是文法里唯一需要切换「名字空间」的地方：
`is` 之后期待一个 NAME（可选带参数表），而不是一个表达式。
`is not` 是两个 token，要一起消费。

### 4. `and` / `or` 与 `binop` 分开

短路语义在 codegen 层要求不同的生成形态（[11 §3.2](../designs/11-jinja-codegen.md)），
因此在 AST 层就用独立的节点类型 `{'and', ...}` / `{'or', ...}`，
不要塞进 `{binop, _, 'and', ...}`。

### 5. 括号、元组、列表、字典

- `(a)` = `a`，**不是**单元素元组；`(a,)` 与 `(a, b)` 才是元组。
- 列表与字典允许尾随逗号。
- 字典 key 是表达式（Jinja2 允许 `{x: 1}`），不限于字符串。

### 6. 参数表

`arglist` 支持位置参数、`name=expr` 关键字参数、`*expr`、`**expr`。
**关键字参数之后不允许位置参数** → `{unexpected_token, ...}`。

### 7. 相邻字符串拼接

`primary = ... | STRING+`：连续的字符串 token 合并成一个 `{lit, Loc, Binary}`。
Loc 取第一个的。

### 8. 位置信息

每个 `expr()` 节点带 loc，取该节点**最左 token** 的位置，
但 filter / test 节点取 **filter 名本身** 的位置（[09 §6](../designs/09-jinja-syntax.md)）——
这样 `{{ a|f1|f2|f3 }}` 中 `f2` 未知时能精确指到 `f2`。

## 验收标准

- [ ] `2**3**2` 解析为 `(2**3)**2`（左结合），有专项断言
- [ ] `a + b|upper` / `2**3|abs` / `-a|abs` 三条绑定紧度断言通过
- [ ] `1 < x < 3` 报 `{chained_comparison, Loc}`，Loc 指向第二个比较符
- [ ] `x is divisibleby(3)` 与 `x is not none` 正确解析
- [ ] `and` / `or` 产出独立节点类型
- [ ] `(a)` ≠ 元组，`(a,)` 与 `(a, b)` 是元组
- [ ] 列表/字典的尾随逗号被接受
- [ ] 关键字参数后跟位置参数报错
- [ ] `"a" "b"` 合并为一个字面量
- [ ] filter / test 节点的 loc 指向 filter/test 名而非表达式起点
- [ ] 每级优先级至少一条「与相邻级组合」的用例
- [ ] fixture 中 `expr` 组用例点亮
