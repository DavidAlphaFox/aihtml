# T18 · 模块命名、冲突检测、孤儿清理与 partial 交叉校验

- **阶段**：4
- **依赖**：[T17](T17.md)
- **状态**：已完成

## 目标

实现模板路径到模块名的映射规则、全量重名冲突检测、`out_dir` 中孤儿 `.erl` 的清理，以及 partial 从「存在」变「不存在」时的全量交叉校验。

## 交付物

- `rebar3_aihtml/src/rebar3_aihtml_name.erl` —— 路径 → 模块名映射与反向推导
- `rebar3_aihtml/src/rebar3_aihtml_check.erl` —— 重名冲突检测、partial 交叉校验
- `rebar3_aihtml/src/rebar3_aihtml_gc.erl` —— 孤儿 `.erl` 清理
- `rebar3_aihtml_prv.erl` 编译主循环中接入以上三段

## 实现要点

### 1. 模块命名规则

照 [05 §4](../designs/05-rebar3-plugin.md)：

```
views/index.mustache          →  view_index
views/shared/item.mustache    →  view_shared_item
views/layout/default.mustache →  view_layout_default
```

规则：**去掉 `views/` 前缀与 `suffix` 后缀，路径分隔符 `/` 与 `-` 归一为 `_`，加 `prefix`。**

实现细节：

- 输入是相对 `views_dir` 的路径（`rel_path`），不含 `views/` 本身，所以「去掉前缀」在扫描阶段就完成了。
- 归一化字符集：`/`（`filename:split/1` 后用 `_` 拼接）、`-`、`.`（除了 suffix 之外的点，例如 `a.b.mustache` 中的 `.`）、空格，全部映射为 `_`。
- 结果必须是合法 Erlang atom 的裸写形式：首字符为小写字母（`prefix` 保证了这一点），其余为 `[a-zA-Z0-9_@]`。出现其它字符（中文、`+`、`%` 等）时**报错**而不是静默转义 —— 静默转义会制造第二类撞名来源。
- 用 `list_to_atom/1` 而非 `list_to_existing_atom/1`（模块此时尚不存在）。atom 数量有界（来自文件系统而非用户输入），见 [07 风险表](../designs/07-roadmap.md)。
- `prefix` 为空字符串时允许，但此时模板名本身必须以小写字母开头，否则报错。
- 提供反向函数 `module_to_out_file/2`（`view_shared_item` → `_gen/view_shared_item.erl`）供孤儿清理使用。注意**反向推导模块名到模板路径是不可能的**（`_` 无法区分是来自 `/` 还是 `-`），所以孤儿清理必须走「正向集合差集」而不是反向推导，见 §3。

### 2. 全量重名冲突检测

[05 §4](../designs/05-rebar3-plugin.md) 明确要求：

> **冲突检测**：`shared/item.mustache` 与 `shared_item.mustache` 会撞名，plugin 必须在扫描后做一次全量重名检查并报错，而不是静默覆盖。

实现：

- 时机在**扫描完成后、任何编译开始前**。理由：撞名时先编译的会被后编译的覆盖，产出是不确定的，必须在动手前拦住。
- 数据结构：`#{module() => [rel_path()]}`，用 `maps:groups_from_list/2`（OTP 25+）或 `lists:foldl` 累积；取出所有 value 长度大于 1 的项。
- 错误信息必须**列出全部冲突模板路径**，不能只报一对：

  ```
  views/shared_item.mustache:0: module name conflict: view_shared_item is also generated from views/shared/item.mustache
  ```

  报告时对每组冲突按路径排序后输出，保证可复现。
- 冲突检测是 **per-app** 的：umbrella 项目里两个 app 各自的 `views/index.mustache` 都映射到 `view_index`，这是**真实的全局冲突**（Erlang 模块名是全局的），但两个 app 的 `mustache_opts` 可以配不同 `prefix` 来解决。处置：per-app 检测必须做（硬错误）；跨 app 的同名做一次 warning 提示用户配不同 prefix，`warnings_as_errors` 下升级为 error。跨 app 检测需要在所有 app 都扫描完后再做，因此把「收集阶段」与「校验阶段」在 `do/1` 中分开。
- 冲突还有第三个来源：生成的模块名与项目里已有的手写模块撞名。检测方式是查 `out_dir` 之外的源目录里是否存在同名 `.erl`，命中则报错。

### 3. 孤儿 `.erl` 清理

定义：`out_dir` 中存在、但本次扫描的模板集合不再产出的生成文件。

- **正向集合差集**：`Orphans = 本次 out_dir 中的所有 .erl - 本次模板映射出的所有 out_path`。不做反向路径推导（见 §1 的说明）。
- **只删自己生成的文件**。判定依据是文件头的 `%% Generated by rebar3_aihtml` 标记 **或** 存在 `-mustache_source` attribute。二者任一命中才删。用户手工放进 `out_dir` 的 `.erl` 一律不动，并发一条 warning 说明「`out_dir` 应只放生成物」。
- 同时删除对应的编译产物残留：`_build/*/lib/<app>/ebin/<Mod>.beam` 如果存在也应删除，否则旧 beam 会一直被 code path 找到，模板都删了渲染还能成功，这是难查的坑。用 `rebar_app_info:ebin_dir/1` 定位。
- `.tmp` 残留文件（[T17](T17.md) §4 的原子化写盘中途失败留下的）在清理阶段一并删除。
- 每删一个打一条 `rebar_api:info("mustache: removing orphan ~s", [Rel])` —— 删文件是破坏性操作，用 info 而不是 debug。
- `rebar3 clean` 的语义：plugin 不额外注册 clean provider；`out_dir` 整体在 `.gitignore` 中，用户可直接删目录。若要更完整，可在 `init/1` 里给 `clean` 挂 hook 清空 `out_dir`，作为可选项实现。

### 4. partial 缺失的交叉校验

这是 [05 §3.2](../designs/05-rebar3-plugin.md) 指出的**唯一需要跨模板校验的场景**：

> 因为 partial 编译成跨模块调用，改 partial 不需要重编父模板，plugin 不需要维护模板依赖图。
>
> 唯一例外：partial 从「存在」变为「不存在」时，父模板的编译应报错。由 `resolve_partials/2` 在编译期检查，且父模板未重编时错误不会被发现 —— 处置：plugin 在扫描阶段先建立一次全量 partial 名集合，对所有已生成模块的 `partials()` 做交叉校验，缺失时报错并强制重编该父模板。

实现算法：

1. 扫描阶段建立 `Available :: sets:set(module())` —— 本次全部模板映射出的模块名集合。
2. 对 `out_dir` 中**每一个**生成的 `.erl`（包括本次 skip 的），读出它的 `partials()` 返回值。读取方式与 [T17](T17.md) §3 读 `-mustache_source` 一致：轻量解析 `.erl` 源文件，找 `partials() -> [view_a, view_b].` 这个函数子句的字面量列表。**不加载 beam**，因为 beam 可能是上一次构建的旧产物。
   - 生成代码里 `partials/0` 返回的是编译期确定的字面量列表（[04 §4](../designs/04-codegen.md)），所以从源文本静态解析是可行且可靠的。
3. `Missing = Deps -- Available`，非空则：
   - 报错 `views/complex.mustache:0: partial not found: view_shared_item (referenced from generated view_complex.erl)`；
   - 同时**强制重编该父模板**（把它从 skip 列表移回编译列表），这样父模板的 `resolve_partials/2` 会在编译期报出带准确行号的 `{partial_not_found, Name}`，诊断质量更好。所以真正对用户可见的错误来自 compiler，交叉校验的职责是**触发重编**而非自己报错。
   - 顺序上：交叉校验必须在 hash 判定之后、编译循环之前跑，才能把 skip 转回 compile。
4. 反向情况（partial 从不存在变存在）不需要处理 —— 父模板此前编译就已失败，本来就没有生成物。
5. `partials()` 解析失败（生成物损坏）时按「需要重编」处理，与 [T17](T17.md) §3 的容错策略一致。

### 5. 循环 partial

[02 §2.2](../designs/02-architecture.md) 指出 partial 编译成跨模块调用后**循环引用天然合法**（`a` 引用 `b`、`b` 引用 `a` 在模块互调下没问题）。因此：

- 交叉校验**不做**环检测，也不因为环而报错。
- [04 §7](../designs/04-codegen.md) 里的 `{partial_cycle_depth, [module()]}` 是 compiler 侧针对**自引用展开深度**的保护，不是 plugin 的职责，plugin 只负责把它格式化输出。

## 验收标准

- [ ] `views/index.mustache` / `views/shared/item.mustache` / `views/layout/default.mustache` 分别映射到 `view_index` / `view_shared_item` / `view_layout_default`
- [ ] `views/a-b.mustache` 映射到 `view_a_b`；含非法字符（如中文、`+`）的模板名报可读错误而不是静默转义
- [ ] `prefix` 改成 `"tpl_"` 后模块名随之变化，且旧的 `view_*` 生成物被当作孤儿清理掉
- [ ] `shared/item.mustache` 与 `shared_item.mustache` 同时存在时报错，错误信息同时列出这两个路径，且**在编译开始前**报出（`_gen/` 中没有产生任何新文件）
- [ ] 生成模块名与项目中已有手写模块同名时报错
- [ ] umbrella 中两个 app 的模板映射到同一模块名时发出 warning 并建议配 prefix
- [ ] 删掉一个模板后重跑，对应 `.erl` 与 `ebin/*.beam` 被删除并打 info 日志
- [ ] 用户手工放在 `out_dir` 的 `.erl`（无生成标记）不被删除，且发出 warning
- [ ] 删掉一个被引用的 partial 后重跑：引用它的父模板被强制重编，并报出带模板行号的 `partial not found` 错误
- [ ] 相互引用的两个 partial（`a` 引 `b`、`b` 引 `a`）能正常编译并渲染，不报环错误
