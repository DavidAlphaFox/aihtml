# T40 · ai_jinja_ast —— AST 后处理

- **阶段**：10
- **依赖**：[T39](T39.md)
- **状态**：已完成

## 目标

四个纯 pass：文本合并、常量折叠与死分支消除、目标解析（模板名 → 模块名）、依赖收集。每个 pass 可独立测试。

## 交付物

- `src/ai_jinja_ast.erl`
- `test/ai_jinja_ast_tests.erl`

## 实现要点

### 0. 单一遍历入口

与 `ai_mustache_ast:map_body/2` 同样的手法：**一个知道「哪些节点带 body」的函数**，
所有 pass 都经它下钻。新增节点类型时只改这一处。

Jinja 的带 body 节点比 mustache 多得多：`if`（多个分支 + else）、`for`（body + else）、
`with` `filter` `block` `macro` `call` `set_block`。**`if` 的每个分支都要下钻** ——
mustache 侧的 P2 bug（`{{+x}}` 内的文本没被合并）就是这类遗漏，
Jinja 的分支更多，更容易漏。

### 1. pass 1 · 文本合并

相邻 `{text, _, _}` 合并成一个字面量，进 literal pool。
累积用 `[X | Acc]` + `lists:reverse/1`，不用 `Acc ++ [X]`（mustache 侧 P1）。

### 2. pass 2 · 常量折叠与死分支消除

- `{binop, _, Op, {lit,_,A}, {lit,_,B}}` → `{lit, _, Result}`，
  **调用 `ai_jinja_rt:Op/2` 求值**，不另写一份（[11 §3.3](../designs/11-jinja-codegen.md)）。
  求值抛异常时**不折叠**，保留原节点，让运行期报出带位置的错误。
- `{'if', _, [{{lit,_,C}, Body} | _], Else}` → C 真则 Body，假则继续看下一分支。
  全部为假且无 else → 该节点整体删除。
- `{unop, _, 'not', {lit,_,V}}` → `{lit, _, not truthy(V)}`。
- `{cond, _, {lit,_,C}, T, E}` → T 或 E。

折叠后要**重跑 pass 1**：死分支消除可能让两段文本变成相邻。

### 3. pass 3 · 目标解析

`include` / `extends` / `import` / `from` 的 Target：`binary()` → `module()`。

- 非字面量目标（`expr()`）→ `{dynamic_target_unsupported, Loc}`
  （[11 §5.3](../designs/11-jinja-codegen.md)）。
- 存在性检查：与 mustache 的 `ai_mustache_ast:exists/2` 同样，
  只在配置了 views 根时做，且 `views_abs` 优先于 `views`。
  `include ... ignore missing` **跳过检查**（[11 §4.4](../designs/11-jinja-codegen.md)）。
- 模块名映射 `module_name/2`：前缀 + 路径中的 `/` `-` `.` 转 `_`。
  可直接复用 `ai_mustache_ast:module_name/2` 的算法，但默认前缀是 `<<"j2_">>`。
  **两个引擎的 `module_name/2` 保持独立实现**（各自的默认前缀不同），
  但算法逐字相同，注释里互相指认。

**不做环检测**：include/extends 编译成跨模块调用，互相引用合法
（[02 §2.2](../designs/02-architecture.md)）。注意 `{% extends %}` 的自环
（模板继承自己）会在运行期无限递归 —— 这一条**要检测并报错**，
因为它不像 include 那样有条件终止。

### 4. pass 4 · 依赖收集

产出 `[module()]`，进生成模块的 `partials/0`（[08 §3](../designs/08-jinja-architecture.md)
解释了为何仍叫 partials）。`lists:usort/1` 去重。

### 5. pass 顺序

```
merge_text → fold_constants → merge_text → resolve_targets → collect_deps
```

`resolve_targets` 放最后（它是唯一会失败的 pass，放前面会丢掉前面的工作）。
`merge_text` 跑两遍，理由见 §2。

## 验收标准

- [ ] 每个 pass 单独导出并单独有测试
- [ ] `if` 的每个分支、`for` 的 body 与 else、`macro`/`block`/`with`/`filter`/`call` 的 body 全部被下钻（各有专项用例）
- [ ] `{{ 1 + 2 }}` 折叠为字面量；`{{ 1 / 0 }}` **不**折叠且不在编译期抛出
- [ ] `{% if false %}X{% endif %}` 整体消失，且前后文本被合并
- [ ] 折叠走 `ai_jinja_rt` 的实现（改 rt 的行为，折叠结果同步变化，有测试锁定）
- [ ] 动态目标报 `{dynamic_target_unsupported, Loc}`
- [ ] `{% extends %}` 自环报错
- [ ] `include ... ignore missing` 跳过存在性检查
- [ ] `partials/0` 的依赖列表去重且排序稳定
- [ ] 文本合并使用 `[X|Acc]` + reverse（代码审查项，且有 10000 节点的性能用例）
