# T27 · ai_mustache_dev 开发期热重载

- **阶段**：6
- **依赖**：[T13](T13.md), [T17](T17.md)
- **状态**：已完成

## 目标

提供开发期热重载模块 `ai_mustache_dev`：读生成模块的 `-mustache_source` attribute，与磁盘上的 `.mustache` 内容 hash 比对，发现变化就重新走 scanner → parser → compiler → `code:load_binary/3` 热加载。整个过程不引入任何额外状态。

## 交付物

- `dev/ai_mustache_dev.erl` —— 开发期热重载模块，只在 dev / test profile 编译，不进 prod
- `rebar.config` —— 新增 dev profile 的 `{src_dirs, ["src", "dev"]}`，prod profile 明确不含 `dev/`
- `test/ai_mustache_dev_SUITE.erl` —— 改文件后重载生效、未改文件时不重编的用例
- `src/ai_mustache_compiler.erl`（小幅扩展）—— 暴露 source hash 与 opts 的计算入口，供 plugin 与 dev 共用同一份实现

## 实现要点

### 1. 核心约束：不引入任何额外状态

依据 [designs/02-architecture.md](../designs/02-architecture.md) 第 2.3 节「开发期热重载不需要任何额外状态」与第 7 节架构不变量第 1 条：

- **不使用 ets**
- **不使用 persistent_term**
- **不启动任何进程**（无 gen_server、无 file monitor、无定时器）
- 不写 cache 文件

理由是 **BEAM code server 本身就是缓存**：模块已加载即是「已编译」，模块的 `-mustache_source` attribute 即是「缓存键」，磁盘文件即是「源」。三者齐全，任何额外的表都是重复状态。这也正是编译期方案相对旧 `ai_mustache_loader`（gen_server + ets + 进程字典三级缓存，见 [01 §4.2](../designs/01-current-state.md)）的结构性优势，实现时不能把旧的缓存思路又搬回来。

### 2. 公开 API

对齐 [02 §5 公开 API](../designs/02-architecture.md)：

```erlang
-module(ai_mustache_dev).
-export([enable/0, reload/1, reload/2, stale/1]).

-spec enable() -> ok | {error, term()}.
-spec reload(module() | all) -> ok | {error, term()}.
-spec reload(module(), Opts :: map()) -> ok | {error, term()}.
-spec stale(module()) -> boolean() | {error, term()}.
```

`enable/0` 的定位需要写清楚：由于不允许持有全局状态，它**不是一个开关**，而是一次性的环境自检 —— 确认 `dev/` 已进构建路径、`views` 根目录可达、`ai_mustache_compiler` 可用，然后返回 `ok`。真正的触发点由使用方显式调用：cowboy 的 dev middleware、`sync`/`rebar3 auto` 的回调，或渲染入口处的 `ai_mustache_dev:reload(Mod)`。这一点必须在模块 doc 与 README（[T29](T29.md)）中写明，否则用户会以为调了 `enable/0` 就自动生效。

### 3. staleness 判定

生成模块自带（[04 §4](../designs/04-codegen.md)）：

```erlang
-mustache_source(#{path  => <<"views/index.mustache">>,
                   hash  => <<...>>,
                   mtime => 1757203845,
                   vsn   => 1}).
```

判定流程：

1. `lists:keyfind(mustache_source, 1, Mod:module_info(attributes))` 取出（attribute 的值在 `module_info` 中被包成 list，注意解包）；取不到则该模块不是生成模块，直接返回 `{error, not_a_template_module}`。
2. `vsn` 与 `?AI_MUSTACHE_VSN` 不等 → 直接 stale（compiler 生成形态变了，所有模块都该重编）。
3. `file:read_file/1` 读内容，调 `ai_mustache_compiler:source_hash/2` 重算 stamp，与 attribute 中的 `stamp` 比对。相同 → not stale（例如 `touch` 过但内容没改）；不同 → stale。

> **实现修正：不要用 mtime 做前置过滤。** 原设计写的是「mtime 一致即判定 not stale，不读文件」，这条不成立：POSIX mtime 只有**秒级精度**，而「编辑后立刻 reload」正是本模块存在的场景 —— 同一秒内的修改 mtime 不变，会被误判为未过期，表现为「改了没生效」。这在实现时被测试抓到（`t_same_second/1`）。读文件加算 md5 只要几微秒，不值得为此引入一个会给错答案的优化。attribute 里的 `mtime` 只作诊断保留。

### 4. hash 口径必须与 plugin 共享一份实现

[05 §3.1](../designs/05-rebar3-plugin.md) 规定增量判断的 hash 是「模板内容 hash + 编译选项 hash + compiler 版本号」三者的组合。plugin（`rebar3_aihtml`，独立 app）与 dev（`aihtml` 内）必须算出同一个值，否则 dev 会把 plugin 刚编好的模块判定为 stale 而无限重编。

实现要求：把该函数放在 `aihtml` 侧（例如 `ai_mustache_compiler:source_meta(Bin, Opts) -> #{hash := binary(), vsn := pos_integer()}`），plugin 反过来调用它。**不允许两边各写一份。** 这是 [02 §7](../designs/02-architecture.md) 架构不变量第 2 条（compiler 是唯一实现）的自然延伸。

> **需要与 [T13](T13.md) / [T17](T17.md) 协调的字段扩展**：[04 §4](../designs/04-codegen.md) 给出的 `-mustache_source` 只有 `path` / `hash` / `mtime` / `vsn` 四个字段，**不含重编所需的编译选项**（`views` 根、`prefix`、`extensions`、`line_map`）。缺了它们，dev 无法忠实复现 plugin 当初的编译。处置二选一，需在 T13/T17 落地前定稿：
> - (A) 在 `-mustache_source` 中增加 `opts => #{...}` 字段（推荐：生成物自描述，与 [05 §3.1](../designs/05-rebar3-plugin.md)「不需要额外的 cache 文件」的思路一致）；
> - (B) 由调用方通过 `reload/2` 显式传入 opts，`reload/1` 只在 opts 可从 attribute 推导时可用。
>
> 无论选哪个，`vsn` 都应参与 hash 组合，使 compiler 升级后所有模块自动判定为 stale。

### 5. 重编与热加载

```
stale(Mod) = true
  → file:read_file(Path)
  → ai_mustache_scanner:scan/2
  → ai_mustache_parser:parse/2          %% 产出带 loc() 的 AST
  → ai_mustache_compiler:forms/2        %% 复用唯一的 AST → forms 实现
  → compile:forms(Forms, [return_errors, debug_info, ...])
  → code:soft_purge(Mod) / code:purge(Mod)
  → code:load_binary(Mod, SrcPath, Bin)
```

要点：

- **必须走 `ai_mustache_compiler`**，不得旁路（架构不变量第 2 条）。dev 与 plugin 的唯一差别是「forms 交给 `compile:forms/2` 还是 `erl_prettypr:format` 落盘 `.erl`」。
- `code:load_binary/3` 的第二参数传 `.mustache` 的路径（而非生成的 `.erl`），使异常堆栈与 `code:which/1` 都指回模板源文件；配合 `line_map` 选项，行号也指回模板原始行（[04 §1](../designs/04-codegen.md)）。
- purge 顺序：先 `code:soft_purge/1`，返回 `false`（仍有进程在跑旧代码）时给出明确 warning 再 `code:purge/1`，不要静默杀进程。
- 编译错误按 [04 §7](../designs/04-codegen.md) 的 `{error, {File, Line, Reason}}` 统一格式返回，并格式化为 `views/index.mustache:12: unclosed tag {{#items}}`，与 erlc 诊断一致。**重编失败时保持旧模块继续可用**，不要卸载已加载的版本。

### 6. `reload(all)` 与 partial

- `reload(all)` 的枚举方式：`code:all_loaded/0` 过滤出带 `mustache_source` attribute 的模块，逐个 `reload/1`。**只覆盖已加载模块**，这是无状态设计的直接后果，可接受 —— 没被加载过的模板在首次调用时由 code server 自动从 `_gen/` 的 beam 加载，本就是最新的。这一限制要在文档中写明。
- partial 是跨模块调用（[02 §2.2](../designs/02-architecture.md)），因此**改 partial 不需要重载父模块**；`reload(all)` 覆盖 partial 自身即可。这一点应作为测试用例显式验证。
- 若模板新增了一个此前不存在的 partial，目标模块可能尚未生成。此时 `resolve_partials/2` 会报 `{partial_not_found, Name}`（[04 §7](../designs/04-codegen.md)）；dev 可选地按 `views` 根 + `prefix` 递归先编译缺失的 partial 再编父模板，失败则原样报错。
- 循环 partial 引用在模块互调下天然合法（[02 §2.2](../designs/02-architecture.md)），dev 不需要做环检测。

### 7. 不得进入 prod profile

- 物理隔离：模块放 `dev/ai_mustache_dev.erl`，只有 dev / test profile 通过 `{erl_opts, [{src_dirs, ["src", "dev"]}]}` 纳入编译。
- **`src/` 下的任何模块不得引用 `ai_mustache_dev`**（否则 prod 的 xref `undefined_function_calls` 会红），调用方向只能是「用户代码 → ai_mustache_dev」。
- `src/aihtml.app.src` 的 `modules` 由构建工具生成，需确认 prod 产物中不含该模块。
- dev / test profile 下 xref 与 dialyzer 仍要覆盖它，不能靠「不编译」来回避静态检查。

## 验收标准

- [ ] `dev/ai_mustache_dev.erl` 中不出现 `ets:`、`persistent_term:`、`spawn`、`gen_server`、`erlang:put/get`、任何定时器
- [ ] `enable/0` / `reload/1` / `reload/2` / `stale/1` 均有 spec，且模块 doc 说明了 `enable/0` 不是全局开关
- [ ] `stale/1` 在 `touch` 但内容未变时返回 `false`（mtime 变、hash 不变）
- [ ] `stale/1` 在内容变更后返回 `true`
- [ ] 用例：渲染 → 改模板文件 → `reload/1` → 再渲染，输出反映新内容，且**没有重启任何进程**
- [ ] 用例：改 partial 模板 → 只 reload partial 模块 → 父模板渲染输出已更新（验证跨模块调用的增量粒度）
- [ ] 用例：模板写成语法错误 → `reload/1` 返回 `{error, {File, Line, Reason}}` 格式化后可读，且旧模块仍可正常渲染
- [ ] dev 侧与 plugin 侧对同一模板算出的 hash 一致（用例直接比对两个入口的返回值）
- [ ] `rebar3 as prod compile` 后 `_build/prod/lib/aihtml/ebin/ai_mustache_dev.beam` 不存在
- [ ] `rebar3 as prod xref` 全绿（证明 `src/` 无人引用 dev 模块）
- [ ] `rebar3 do dialyzer, xref` 在 dev / test profile 下全绿
