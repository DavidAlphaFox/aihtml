# T16 · rebar3_aihtml plugin 骨架与 provider 注册

- **阶段**：4
- **依赖**：[T13](T13.md)
- **状态**：已完成

## 目标

在本仓 `rebar3_aihtml/` 子目录建立 rebar3 plugin 子项目，注册 `mustache` 与 `mustache migrate` 两个 provider，并把 `mustache_opts` 配置解析成规范化的内部选项记录，供 [T17](T17.md)、[T18](T18.md)、[T19](T19.md) 复用。

## 交付物

- `rebar3_aihtml/rebar.config` —— plugin 子项目构建配置，零依赖
- `rebar3_aihtml/src/rebar3_aihtml.app.src` —— plugin 的 app 描述
- `rebar3_aihtml/src/rebar3_aihtml.erl` —— `init/1`，串联注册所有 provider
- `rebar3_aihtml/src/rebar3_aihtml_prv.erl` —— compile provider 骨架（`init/1` · `do/1` · `format_error/1`）
- `rebar3_aihtml/src/rebar3_aihtml_opts.erl` —— `mustache_opts` 解析与规范化，含默认值与校验
- `rebar3_aihtml/include/rebar3_aihtml.hrl` —— 内部选项记录与常量定义
- 主仓 `rebar.config` 的 `test` profile 增加 `{plugins, [{rebar3_aihtml, {path, "rebar3_aihtml"}}]}`
- `.gitignore` 增补 `_gen/`

## 实现要点

### 1. 子项目布局与零依赖约束

按 [02 §3](../designs/02-architecture.md) 的目录结构，plugin 独立成 `rebar3_aihtml/` 子项目，使用方通过 `{subdir, "rebar3_aihtml"}` 引用（见 [05 §1](../designs/05-rebar3-plugin.md)）。

- 决策 D5 要求**零依赖**：`rebar3_aihtml/rebar.config` 的 `{deps, []}` 必须为空，plugin 只能调用 rebar3 自身导出的 API（`rebar_state` / `rebar_app_info` / `rebar_api` / `rebar_utils` / `rebar_file_utils` / `providers`）与 OTP。**不得**引入 ailib 或任何第三方库。
- plugin 需要调用 `ai_mustache_scanner` / `ai_mustache_parser` / `ai_mustache_compiler`，这些模块属于 `aihtml` 主 app。plugin 与主 app 分属不同的 rebar3 加载域（plugin 在 build 期加载，dep 在 target 期加载），因此 `rebar3_aihtml/rebar.config` 中要把 aihtml 的 `src/` 通过 `{extra_src_dirs, ...}` 或在 plugin 的 `rebar.config` 中声明对 aihtml 源的引用，使 plugin 进程内能 `code:ensure_loaded/1` 到 compiler。落实方案：plugin 的 `rebar.config` 写 `{erl_opts, [...]}` 并加 `{src_dirs, ["src", "../src"]}` 把主仓 compiler 相关模块一并编入 plugin，或在 `do/1` 里先做 `code:ensure_loaded(ai_mustache_compiler)` 并在失败时用 `rebar_api:abort/2` 给出明确诊断。二者选其一，在实现中明确注释理由。
- `rebar3_aihtml.app.src` 的 `applications` 只列 `kernel` / `stdlib`。

### 2. `rebar3_aihtml:init/1`

严格照 [05 §2](../designs/05-rebar3-plugin.md) 的骨架：

```erlang
-module(rebar3_aihtml).
-export([init/1]).

init(State) ->
    lists:foldl(fun(M, {ok, S}) -> M:init(S) end, {ok, State},
                [rebar3_aihtml_prv, rebar3_aihtml_migrate]).
```

注意 `foldl` 的函数子句只匹配 `{ok, S}`，任一 provider 的 `init/1` 返回非 `{ok, _}` 会直接 badmatch。实现时保留这个形态（rebar3 provider 的 `init/1` 约定必然返回 `{ok, State}`），但要在 `rebar3_aihtml_prv:init/1` 内部保证不抛异常。`rebar3_aihtml_migrate` 的实现属于 [T19](T19.md)，本任务只需保证模块存在且 `init/1` 能注册成功（可先注册 provider 但 `do/1` 返回未实现错误）。

### 3. `rebar3_aihtml_prv:init/1` 的 provider 描述

照 [05 §2](../designs/05-rebar3-plugin.md) 的 `providers:create/1` 落地：

```erlang
init(State) ->
    P = providers:create([
          {name,       mustache},
          {module,     ?MODULE},
          {namespace,  default},
          {bare,       true},
          {deps,       [app_discovery]},
          {example,    "rebar3 mustache"},
          {opts,       [{force, $f, "force", boolean, "忽略缓存，全量重新编译"}]},
          {short_desc, "Compile mustache templates to Erlang modules"},
          {desc,       "扫描 views 目录，将 .mustache 编译为 .erl 放入 out_dir"}]),
    {ok, rebar_state:add_provider(State, P)}.
```

要点：

- `{namespace, default}` + `{bare, true}` 使 `rebar3 mustache` 可直接调用，同时可被 `{provider_hooks, [{pre, [{compile, mustache}]}]}` 挂在 compile 前。
- `{deps, [app_discovery]}` 保证 `rebar_state:project_apps/1` 在 `do/1` 里已经填好。
- `--force` 通过 `rebar_state:command_parsed_args/1` 取，返回 `{Args, _Rest}`，用 `proplists:get_value(force, Args, false)` 读。

### 4. `do/1` 骨架与错误返回契约

本任务只搭骨架，真正的编译流程在 [T17](T17.md)：

```erlang
do(State) ->
    Force = ...,
    Apps  = rebar_state:project_apps(State),
    try
        lists:foreach(fun(App) -> process_app(App, State, Force) end, Apps),
        {ok, State}
    catch throw:{?MODULE, Reason} ->
        {error, {?MODULE, Reason}}
    end.
```

- 所有可预期错误用 `throw({?MODULE, Reason})` 上抛，在 `do/1` 一处收敛为 `{error, {?MODULE, Reason}}`，rebar3 会调用 `format_error/1`。
- `format_error/1` 必须把 [04 §7](../designs/04-codegen.md) 的 `{error, {File, Line, Reason}}` 渲染成 `views/index.mustache:12: unclosed tag {{#items}}` 这样的 erlc 风格诊断（文件路径相对项目根，冒号分隔，便于编辑器跳转）。本任务定义 `format_error/1` 的分派框架与 `unclosed_tag` / `mismatched_close` / `partial_not_found` / `unknown_marker` / `invalid_delimiter` / `partial_cycle_depth` 六种 Reason 的文案，具体触发点由后续任务填。
- 多条诊断时不要只报第一条：收集成列表，逐条 `rebar_api:error/2` 打印，最后统一 abort。

### 5. `mustache_opts` 解析（`rebar3_aihtml_opts`）

配置来源与优先级：**app 级 `rebar_app_info:opts/1` 覆盖 project 级 `rebar_state:opts/1`**（[05 §3](../designs/05-rebar3-plugin.md)）。用 `rebar_opts:get/3` 分别取两层再合并（app 层的 key 逐个覆盖 project 层）。

支持的 key、类型与默认值：

| key | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `views` | `string()` | `"views"` | 模板根目录，相对 app 目录 |
| `suffix` | `string()` | `".mustache"` | 模板扩展名 |
| `out_dir` | `string()` | `"_gen"` | 生成 `.erl` 的目录，相对 app 目录 |
| `prefix` | `string() \| binary()` | `"view_"` | 模块名前缀 |
| `extensions` | `[module()]` | `[]` | 扩展模块列表，见 [06 §2](../designs/06-parse-transform.md) 与 [T23](T23.md) |
| `line_map` | `boolean()` | `true` | forms 的 line 是否用模板行号 |
| `warnings_as_errors` | `boolean()` | `false` | 警告升级为错误 |

规范化输出一个记录（`include/rebar3_aihtml.hrl`）：

```erlang
-record(mopts, {
    app_dir    :: file:filename_all(),
    views_dir  :: file:filename_all(),   %% 已 filename:join(AppDir, Views) 绝对化
    out_dir    :: file:filename_all(),   %% 已绝对化
    suffix     :: string(),
    prefix     :: binary(),
    extensions :: [module()],
    line_map   :: boolean(),
    wae        :: boolean(),
    compiler_opts :: map()               %% 见下，直接喂给 compiler 与 source_hash/2
}).
```

校验：

- 未知 key → 发 warning（`warnings_as_errors` 为真时升级为 error），列出可用 key，避免用户拼错静默失效。
- `prefix` 必须是合法 Erlang atom 首段（`[a-z][a-zA-Z0-9_]*` 或空），否则报错。
- `views` 目录不存在时**不报错**，直接跳过该 app（很多 app 没有模板）；但 `out_dir` 在有模板时按需 `filelib:ensure_dir/1` 创建。
- `extensions` 中每个模块做 `code:ensure_loaded/1`，失败时报错并提示需要把扩展模块放在 plugin 可见的编译路径上。marker 冲突检测本身属于 [T23](T23.md)，本任务只负责把列表带到 `#mopts{}` 里。

### 6. `compiler_opts` —— 交给 compiler 的规范化选项

增量判断需要「模板内容 hash + 编译选项 hash + compiler 版本号」的组合（[05 §3.1](../designs/05-rebar3-plugin.md)），但**这个 hash 不由 plugin 计算**。[04 §4.1](../designs/04-codegen.md) 明确了归属：

> hash 必须由 **aihtml 侧**导出一个函数，plugin 与 dev 模块都调它：`ai_mustache_compiler:source_hash(Body :: binary(), opts()) -> binary()`。
>
> 绝不能让 plugin 自己算一份、dev 再算一份 —— 两侧口径一旦漂移，dev 会认为模块永远是陈旧的从而无限重编，而 plugin 会认为永远是新鲜的从而不重编。

因此本任务的职责收窄为：**把 `mustache_opts` 规范化成 compiler 认识的 `opts()` map**，`#mopts.compiler_opts` 即：

```erlang
#{prefix     => <<"view_">>,
  views      => ViewsDir,
  extensions => lists:usort(Exts),
  line_map   => true}
```

要点：

- **`out_dir` / `suffix` / `warnings_as_errors` 不进 `compiler_opts`** —— 它们不影响生成代码，混进去会让改 `out_dir` 也触发全量重编。
- `module` 与 `source` 两个必填字段是 per-template 的，由 [T17](T17.md) 在编译每个模板时补上；`compiler_opts` 只存 per-app 的公共部分。
- 选项排序与去掉无关项的**规范化本身也在 `source_hash/2` 里做**（[04 §4.1](../designs/04-codegen.md)），plugin 侧的 `lists:usort/1` 只是为了让 `compiler_opts` 自身可比较，不承担 hash 的确定性责任。
- compiler 版本号是 aihtml 侧的 `?COMPILER_VSN` 宏，plugin **不得**定义自己的版本常量。
- 该 map 同时会被原样写入生成物的 `-mustache_source` 的 `opts` 字段（[04 §4](../designs/04-codegen.md) 关键点 6），供 `ai_mustache_dev`（[T27](T27.md)）忠实复现 plugin 当初的编译。所以 `compiler_opts` 中的路径应写成**相对 app 目录的形式**再入 attribute，否则生成物带上开发机的绝对路径，既不可复现也会让 CI 与本地产出不同的文件。

### 7. 边界情况

- umbrella 项目：`project_apps/1` 返回多个 app，每个 app 独立解析自己的 `mustache_opts` 与 `views` / `out_dir`，互不干扰；模块重名检测的作用域也是 per-app（见 [T18](T18.md)）。
- plugin 被作为 dep 的 plugin 加载时（`DEP_PLUGINS` / erlang.mk 路径，[05 §7](../designs/05-rebar3-plugin.md)）`project_apps/1` 语义不变，无需特殊处理。
- `do/1` 必须幂等：连续跑两次第二次应全部 skip（由 [T17](T17.md) 保证），本任务保证 `do/1` 不产生副作用性状态。

## 验收标准

- [ ] `rebar3_aihtml/` 子项目可独立 `rebar3 compile`，`{deps, []}` 为空
- [ ] 主仓 `test` profile 通过 `{path, "rebar3_aihtml"}` 加载 plugin，`rebar3 as test help mustache` 能打印出 short_desc 与 `--force` 选项
- [ ] `rebar3 mustache` 可以直接执行（`bare = true`），且能被 `{provider_hooks, [{pre, [{compile, mustache}]}]}` 触发
- [ ] `rebar3_aihtml_opts` 对全部 7 个配置项有默认值，app 级配置能覆盖 project 级，有对应单测
- [ ] 未知配置 key 会产生 warning，`warnings_as_errors` 为真时变成 error
- [ ] `views` 目录不存在的 app 被静默跳过，不报错也不创建 `out_dir`
- [ ] `format_error/1` 对 [04 §7](../designs/04-codegen.md) 列出的 6 种 Reason 都有可读输出，格式为 `Path:Line: message`
- [ ] `#mopts.compiler_opts` 只含 `prefix` / `views` / `extensions` / `line_map`，不含 `out_dir` / `suffix` / `warnings_as_errors`
- [ ] plugin 中**没有任何自行计算 source hash 的代码**，全部走 `ai_mustache_compiler:source_hash/2`；也没有自定义的 compiler 版本常量
- [ ] `compiler_opts` 中的路径是相对 app 目录的形式，生成物的 `-mustache_source` 中不出现开发机绝对路径
- [ ] `.gitignore` 含 `_gen/`
