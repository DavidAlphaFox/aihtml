# T28 · examples 按新语义重写

- **阶段**：6
- **依赖**：[T19](T19.md), [T20](T20.md)
- **状态**：已完成

## 目标

把 `examples/` 下全部模板从旧的「扁平 context + 全路径寻址」语义改写为 [designs/03-semantics.md](../designs/03-semantics.md) 定稿的标准 context stack 语义，并把 `complex.erl` 的 bootstrap 调用改成新 API，使 examples 成为 rebar3 plugin 的端到端可运行样例。

## 交付物

- `examples/complex.mustache` —— 主模板，改用标准语义，补上 `{{#}}` / `{{^}}` / partial 的完整演示
- `examples/shared/item.mustache` —— section body 内剥掉 `items.` 前缀
- `examples/shared/user.mustache` —— section body 内剥掉 `user.` 前缀
- `examples/shared/level.mustache` —— 同上，并接入 `complex.mustache`（当前是无人引用的孤儿）
- `examples/complex.erl` —— 去掉 ailib / bootstrap，改为直调生成模块
- `examples/rebar.config` —— 让 examples 成为可独立 `rebar3 compile` 的样例工程
- `examples/dom_render.erl` —— 阶段 1 已移到 `attic/dom_render.erl`，由 [T26](T26.md) 随 attic 一并删除，本任务不重写

## 实现要点

### 0. 语义变更总纲

依据 [03 §7.1](../designs/03-semantics.md)：**在 section `{{#X}}` 的 body 内部，把以 `X.` 开头的引用剥掉这层前缀。** 现有四个模板全部命中这条规则。

同时注意两处会改变输出字节的连带变化，改写时要一并核对：

1. **partial 的 standalone 缩进**（[03 §6](../designs/03-semantics.md)）：`{{> shared/item}}` 独占一行时，该行缩进要应用到 partial 输出的**每一行**；旧实现只缩进第一行。`complex.mustache` 中该行有 4 个空格缩进，而 `item.mustache` 每行自带 4 个空格，因此新输出中这些行是 8 个空格开头。这是符合 spec 的预期变化。
2. **escape 字符集收窄到 5 个**（[04 §5.1](../designs/04-codegen.md)）：`/` `=` `` ` `` 不再转义。`item.mustache` 中的 `href="{{url}}"`、context 中的 `"#Red"` 之类的值在旧实现下会被转义成 `&#x2F;` 形态，新实现原样输出。

### 1. `examples/shared/item.mustache`

当前（旧语义，`{{+ items.current }}` / `{{ items.name }}` 是全路径寻址）：

```mustache
    {{+ items.current }}
      <li><strong>{{ items.name }}</strong></li>
      <li> 中文 </li>
      {{!这里是注释}}
    {{/ items.current }}

    {{+ link}}
      <li><a href="{{url}}">{{name}}</a></li>
      {{- not_found}}
        <li>此处应该显示</li>
      {{/ not_found}}
      {{+ not_found}}
        <li>此处应不该显示</li>
      {{/ not_found}}
    {{/ link}}
```

改为：

```mustache
    {{+ current }}
      <li><strong>{{ name }}</strong></li>
      <li> 中文 </li>
      {{!这里是注释}}
    {{/ current }}

    {{+ link}}
      <li><a href="{{url}}">{{name}}</a></li>
      {{- not_found}}
        <li>此处应该显示</li>
      {{/ not_found}}
      {{+ not_found}}
        <li>此处应不该显示</li>
      {{/ not_found}}
    {{/ link}}
```

改法说明：

- `items.current` → `current`、`items.name` → `name`：本文件被 `{{# items}}` 内的 partial 引入，渲染时当前元素已在栈顶（partial「以当前栈渲染」，[03 §2](../designs/03-semantics.md)），直接写裸键即可。
- `{{+ link}}` / `{{- not_found}}` / `{{+ not_found}}` 三处**不需要改写**，它们本来就是裸键。但要注意它们现在是**沿栈回溯**查找：`link` 会先在 item frame 找、找不到再到根 context 找。
- 保留 `{{+}}` / `{{-}}` 的用法，因为它们正是 [03 §4](../designs/03-semantics.md) 要在文档中讲清的「不压栈的条件渲染」—— `{{+ current}}` 内部仍然写 `{{name}}`（从 item frame 取），而不是进入 `current` 的作用域。这个文件天然就是 `{{#}}` 与 `{{+}}` 区别的活样例。
- 建议在 `complex.erl` 的每个 item 中补 `link => true`（见 §4），让 `{{+ link}}` 分支真正被执行 —— 当前 context 里根本没有 `link` 键，这一大段是死代码，`{{-}}` 从未被验证过。

### 2. `examples/shared/user.mustache`

```diff
- {{#user}}
-     {{user.name}}
- {{/user}}
+ {{#user}}
+     {{name}}
+ {{/user}}
```

`user` 是 map，`{{#user}}` **压栈**执行一次 body（[03 §3](../designs/03-semantics.md) 分派表），因此 body 内写 `{{name}}`。

### 3. `examples/shared/level.mustache`

```diff
- {{#level}}
-     {{level.name}}
- {{/level}}
+ {{#level}}
+     {{name}}
+ {{/level}}
```

另外：**该文件当前是孤儿** —— `complex.mustache`、`item.mustache`、`user.mustache` 都没有 `{{> shared/level}}`，而 `complex.erl` 的 context 里却有 `level => #{name => <<"VIP User">>}`。处置：在 `complex.mustache` 中加一行 `{{> shared/level}}`（见 §5），让它被真正渲染，同时也让 plugin 的模块命名（`view_shared_level`）与 partial 交叉校验（[05 §3.2](../designs/05-rebar3-plugin.md)）有更多样例覆盖。

### 4. `examples/complex.erl`

需要改的四处：

**(a) context 补 `link`**，激活 `item.mustache` 的第二段：

```erlang
A = #{name => "red",   current => true,  url => "#Red",   link => true},
B = #{name => "green", current => true,  url => "#Green", link => true},
C = #{name => "blue",  current => false, url => "#Blue",  link => true},
```

顺带把 `maps:from_list([{...}])` 直接写成 map 字面量，可读性更好。注意 `name` 的值是 string（`"red"`），`ai_mustache_rt:to_binary/1` 需要能处理 —— 若 T13 的实现只接受 binary/number/atom，这里应改成 binary 字面量，二选一但要显式确认。

**(b) 删除 bootstrap 与 application 启动**。当前：

```erlang
start() ->
  code:add_patha("../ebin"),
  code:add_patha("../deps/ailib/ebin"),
  application:start(ailib),
  application:start(aihtml),
  {ok,CWD} = file:get_cwd(),
  ai_mustache:bootstrap(#{views => CWD}),
  Output = ai_mustache:render("complex",context()),
  ...
```

改为：

```erlang
start() ->
  %% aihtml 是 library app：无 application:start，无 bootstrap，无 ets，无进程。
  %% 模板由 rebar3_aihtml 在 compile 阶段编译成 view_complex 模块。
  Output = view_complex:render(context()),
  io:format("~ts~n", [Output]),
  ...
```

理由：[02 §2.4](../designs/02-architecture.md) 运行期退化为 library application，使用方不需要 `application:start(aihtml)`；ailib 依赖已按决策 D5 彻底移除；`code:add_patha` 由 rebar3 的 code path 接管。

**(c) 演示门面 API**。再加一个 `start_via_facade/0`，展示模板名运行期才确定时的用法（[02 §5](../designs/02-architecture.md)）：

```erlang
start_via_facade() ->
  Mod = view_complex,                       %% 运行期决定
  io:format("~ts~n", [ai_mustache:render(Mod, context())]).
```

并补一个 `render_iolist/0` 的样例，说明可直接喂给 cowboy 的 `Body`，省一次 `iolist_to_binary`。

**(d) `yield/2` 的语义变更注释**。依据 [03 §5](../designs/03-semantics.md)，lambda 的 fun 现在收到的是**栈顶 frame** `hd(Stack)` 而非旧的扁平全局 Ctx。`{{*yield}}` 在 `complex.mustache` 里位于顶层，此时 `hd(S)` 恰好就是根 context，`maps:get(header, Ctx)` 仍然可用 —— 但这是位置巧合，必须加注释点明；若把 `{{*yield}}` 挪进某个 section，`header` 就取不到了。

**(e) 基准循环**。现有 `render/2` 的 500 次计时循环保留，但改为调用 `view_complex:render/1`；同时在注释中指明**正式基准由 [T30](T30.md) 负责**，这里只是冒烟性质的耗时打印，不作为性能结论来源。

### 5. `examples/complex.mustache`

当前：

```mustache
<h1>{{header}}</h1>
<ul>
  {{# items}}
    {{> shared/item}}
  {{/ items}}
</ul>
{{> shared/user}}
|
{{#boolean}}
{{/boolean}}
|
{{*yield}}
```

改为：

```mustache
<h1>{{header}}</h1>
<ul>
  {{# items}}
    {{> shared/item}}
  {{/ items}}
</ul>
{{> shared/user}}
{{> shared/level}}
{{#list}}
<p>list is true —— 执行一次 body，不压栈</p>
{{/list}}
{{^empty}}
<p>empty 为 falsy —— inverted section 执行，不压栈</p>
{{/empty}}
{{*yield}}
```

改法说明：

- `{{header}}`、`{{# items}}` 本来就是裸键，不改。
- 加 `{{> shared/level}}`，消除 level.mustache 的孤儿状态（见 §3）。
- 删掉 `{{#boolean}}{{/boolean}}` 这一段：`boolean` 键在 context 中根本不存在，且 body 为空，会被 `drop_empty/1`（[04 §2](../designs/04-codegen.md)）直接消除，留着没有演示价值。连同上下两行的 `|` 分隔符一并删除。
- 新增 `{{#list}}` 与 `{{^empty}}`：context 里已有 `list => true` 与 `empty => false`，此前**从未被任何模板使用**。补上后正好覆盖 [03 §3](../designs/03-semantics.md) 分派表中的 `true`（执行一次、不压栈）与 falsy + inverted 两条规则。
- 若想额外演示 `0` 是 truthy 这个踩坑点（[03 §2.1](../designs/03-semantics.md)），可在 context 加 `count => 0` 并写 `{{#count}}count 是 0，但仍然 truthy：{{.}}{{/count}}`，顺带演示 `{{.}}` 隐式迭代器（修掉的 [B5](../designs/01-current-state.md)）。

### 6. `examples/rebar.config`

examples 需要能被 plugin 端到端编译，这也是 [07 阶段 4](../designs/07-roadmap.md) 的验收项「examples 用 plugin 全流程跑通」。新增：

```erlang
{deps, [{aihtml, {path, ".."}}]}.
{plugins, [{rebar3_aihtml, {path, "../rebar3_aihtml"}}]}.
{provider_hooks, [{pre, [{compile, mustache}]}]}.
{mustache_opts, [{views, "."}, {suffix, ".mustache"},
                 {out_dir, "_gen"}, {prefix, "view_"}, {line_map, true}]}.
{erl_opts, [{src_dirs, ["src", "_gen"]}]}.
```

配套：

- 模块命名结果（[05 §4](../designs/05-rebar3-plugin.md)）：`complex.mustache` → `view_complex`，`shared/item.mustache` → `view_shared_item`，`shared/user.mustache` → `view_shared_user`，`shared/level.mustache` → `view_shared_level`。
- `complex.erl` 目前在 `examples/` 根目录，按 rebar3 约定应移到 `examples/src/`（或在 `src_dirs` 中加 `"."`）。移动更规范，但会改变仓库既有布局，需在实现时确认取舍。
- 根 `.gitignore` 增补 `_gen/`（[07 阶段 1](../designs/07-roadmap.md) 已列，此处复核 `examples/_gen/` 被覆盖）。

### 7. 输出核对

改写完成后，人工核对一次完整渲染输出，重点确认：

- `items` 三个元素中 `blue` 的 `current => false`，其 `{{+ current}}` 段不输出
- `{{+ link}}` 段在补了 `link => true` 后输出，且内部 `{{- not_found}}` 输出「此处应该显示」、`{{+ not_found}}` 不输出
- partial 缩进为「外层 4 空格 + 文件内 4 空格 = 8 空格」
- `{{*yield}}` 输出 `Test is Colors`

建议把这份输出存为 fixture 供 CT 复用（可选，不作为本任务的硬性交付）。
