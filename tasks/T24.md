# T24 · 形态 b：内联模板与运行期降级（ai_mustache:inline/2）

- **阶段**：5
- **依赖**：[T22](T22.md)、[T14](T14.md)
- **状态**：已完成

## 目标

在 parse_transform 的 pass 2 中把第一参数为 binary 字面量的 `ai_mustache:inline/2` 调用在编译期展开为原地 iolist 构造；同时实现 `ai_mustache:inline/2` 的真实运行期实现，使未加 parse_transform 时语义完全一致、只是慢。

## 交付物

- `src/ai_mustache.erl` 的 `inline/2` —— 运行期实现（scanner + parser + 解释求值）
- `src/ai_mustache_interp.erl` —— 运行期解释器，仅服务于 `inline/2` 的降级路径
- `ai_mustache_transform` 的 `expand/2` 中 `ai_mustache:inline/2` 的展开分支
- `test/ai_mustache_inline_tests.erl` —— 展开路径与降级路径的等价性测试
- README 中内联模板一节

## 实现要点

### 0. 前提：Erlang 不支持自定义 sigil

[06 §0](../designs/06-parse-transform.md) 的前提修正必须在实现与文档中体现：

> OTP 27 引入的 sigil 是**固定集合**（`~"..."`、`~b`、`~B`、`~s`、`~S`），编译器对未知 sigil 直接报词法错误。`~mustache"..."` **根本过不了词法**，parse_transform 拿不到 forms。

所以内联模板的载体是**合法 Erlang 语法**：识别特定函数调用 + 字面量参数。**不要**在实现或文档中出现 `~mustache"..."` 的写法。`~"Hello {{name}}"` 是合法的（`~"..."` 是标准 sigil，产出 binary 字面量），可以用；`<<"Hello {{name}}">>` 同样可以。

### 1. 识别条件

在 pass 2 的表达式遍历中匹配：

```erlang
{call, L, {remote, _, {atom, _, ai_mustache}, {atom, _, inline}}, [TplExpr, CtxExpr]}
```

只有当 `TplExpr` 是 **binary 字面量**时才展开。判定要覆盖两种 forms 形态：

- `{bin, L, [{bin_element, L, {string, L, "Hello {{name}}"}, default, default}]}` —— 来自 `<<"...">>` 与 `~"..."`
- 多段拼接的字面量 `<<"a", "b">>`：各段都是 string/integer 字面量且无 size/type 修饰时可以先求值成一个 binary 再展开。用 `erl_eval` 对该 bin 表达式求值（表达式内无变量，求值是安全的），失败则视为非字面量。

**明确不支持**（视为非字面量，走运行期）：

- 变量、函数调用、`++` 拼接的结果
- 带 unit/size/type 修饰或含变量段的 binary 构造
- 宏 —— 注意宏在 parse_transform 拿到 forms 之前已被 `epp` 展开，所以 `?TPL` 若展开成字面 binary 则**是**可展开的，这是白送的能力，测试中要覆盖

`ai_mustache:inline/2` 之外的 arity 与 `inline/2` 的本地调用（`inline(A, B)` 无模块前缀）不匹配 —— 只认完整的 remote call，避免误伤同名本地函数。

### 2. 展开形态

照 [06 §3](../designs/06-parse-transform.md)：

```erlang
greet(Name) ->
    ai_mustache:inline(~"Hello {{name}}!", #{name => Name}).
```

展开为：

```erlang
greet(Name) ->
    erlang:iolist_to_binary(
      begin
          S__1 = [#{name => Name}],
          [<<"Hello ">>,
           ai_mustache_rt:escape(ai_mustache_rt:lookup([name], S__1)),
           <<"!">>]
      end).
```

要点：

- **`CtxExpr` 只能求值一次。** 上面把它绑定到 `S__1 = [CtxExpr]` 而不是在多处内联 `CtxExpr`，这一点是硬要求：`CtxExpr` 可能有副作用（函数调用、`put/2`）或代价很高。展开后必须保证「原调用求值一次 Ctx」的语义不变。
- 栈变量名由 `#st.counter` 生成（`'S__1'`、`'S__2'`…），保证同一函数里多处 inline 不互相遮蔽，也不与用户变量冲突（[T22](T22.md) §2）。
- `begin ... end` 包住整个展开，使它在语法上仍是**单个表达式**，可以出现在原调用的任何位置（case 的分支、list comprehension 的模板、函数参数里等）。
- 生成的所有节点用**原调用的行号** `L`，堆栈仍指回用户源码。
- 实际的 iolist 构造 forms 来自 `ai_mustache_compiler:compile_inline(AST, CtxVarExpr, Opts)`（[04 §3](../designs/04-codegen.md)）—— transform 不自己造 forms（[架构不变量 #2](../designs/02-architecture.md)）。
- 扩展 tag 在内联模板中**可用**：把 `#st.ext_tags`（[T23](T23.md)）构建成分派表传给 compiler 的 `extensions` 选项。这是 `-mustache_tag` 真正参与装配的场景之一。

### 3. 内联模板不支持 partial

[06 §3.3](../designs/06-parse-transform.md)：

> `{{> x}}` 在内联模板中报编译错误 —— 内联场景没有 views 目录上下文。需要 partial 就该用文件模板。

实现：

- 展开路径：AST 中出现 `{partial, Loc, Name, _}` 时报 `{inline_partial_unsupported, Name}`，行号用**原调用行号 + 模板内相对行号 - 1**（模板是内联字面量，没有独立文件；把它折算到 `.erl` 的行号，用户才跳得过去）。多行 binary 字面量的行号折算要正确。
- **降级路径必须行为一致**：运行期解释器遇到 partial 时 `error({mustache, {partial_unsupported_in_inline, Name}})`。二者的错误时机不同（编译期 vs 运行期）是不可避免的，但都必须失败，不能一边报错一边静默渲染成空。这一条要有对照测试。

### 4. 非字面量时的处置

[06 §3.2](../designs/06-parse-transform.md)：

> `ai_mustache:inline(Tpl, Ctx)` 中 `Tpl` 是变量时，transform 原样保留调用，走运行期路径。可选地在 `warnings_as_errors` 下发一条 warning 提示无法优化。

实现：

- 原样保留 forms，**不做任何改动**。
- 发一条 warning `{inline_not_literal}`，文案：「`ai_mustache:inline/2` 的第一个参数不是 binary 字面量，无法在编译期展开，将走运行期解释路径」。
- 这条 warning 默认**发出**（不是默认静默），因为用户写 `inline` 的意图通常就是要零开销。若嫌吵，用 `nowarn_mustache_inline` 编译选项关掉 —— 提供这个开关并在 README 说明。`warnings_as_errors` 下它自然升级为错误，无需特殊处理。

### 5. 运行期降级实现

[06 §3.1](../designs/06-parse-transform.md)：

> `ai_mustache:inline/2` 本身有真实实现（运行期 scanner + parser + 解释求值）。**语义完全一致。**

这是本任务最容易被低估的一半工作量 —— 它意味着项目里存在**两套求值实现**（编译期生成代码 + 运行期解释器），必须证明二者等价。

实现要求：

- `ai_mustache_interp:render(AST, Ctx) -> binary()`，直接对 [04 §1](../designs/04-codegen.md) 的 AST 求值。
- 语义必须与生成代码**逐条一致**：[03 §2](../designs/03-semantics.md) 的规则表、[03 §2.1](../designs/03-semantics.md) 的 falsy 集合（`undefined` · `false` · `[]` · `<<>>` · `null`，`0` 与 `#{}` 为 truthy）、[03 §3](../designs/03-semantics.md) 的 section 分派表（8 种情况，含 `fun/1` / `fun/2`）、`{{+}}` / `{{-}}` / `{{*}}` 扩展、`{{.}}` 隐式迭代、`{{a.b}}` 的「首段回溯、后续段严格下钻」。
- **复用 `ai_mustache_rt`**：`lookup/2` · `escape/1` · `to_binary/1` · `truthy/1` · `section/4` · `lambda/2` 全部直接调，不重写。这样两套实现的**语义核心是同一份代码**，差异只在控制流的组织方式，等价性风险大幅降低。解释器本身应该很薄（一个对 AST 的递归 `render_node/3`）。
- 扩展 tag 在降级路径上**无法支持**（`compile_tag/4` 产出的是 abstract expression，运行期没有编译器可用）。遇到 `{ext, ...}` 时 `error({mustache, {ext_unsupported_at_runtime, Marker}})`，并在 README 中说明：**内联模板用了扩展 tag 就必须加 parse_transform**。这是三形态对比表（[06 §6](../designs/06-parse-transform.md)）中「无 transform 时降级为运行期解释」的一个未言明的例外，需要补进 README。
- **不做任何缓存**：不用 ets、不用 persistent_term（[架构不变量 #1](../designs/02-architecture.md)）。每次调用重新 scan + parse。这正是它「慢」的地方，也是它诚实的地方 —— 想要快就加 transform。

### 6. 等价性测试

这是本任务的核心验收手段：

- 建一张内联模板用例表（模板 binary + context + 期望输出），**同一张表跑两遍**：
  - 一遍在加了 `-compile({parse_transform, ai_mustache_transform})` 的测试模块里（走展开路径）；
  - 一遍在没加的测试模块里（走运行期路径）。
- 断言两遍的输出与期望**完全一致**。
- 用例表要覆盖 [03 §2](../designs/03-semantics.md) 全部 tag 类型与 [03 §3](../designs/03-semantics.md) 的 8 种 section 分派、falsy 集合的每个成员、`{{.}}`、`{{a.b}}` 的遮蔽与回溯、自定义分隔符、standalone 各组合。
- 加一条「Ctx 表达式只求值一次」的测试：`ai_mustache:inline(~"{{a}}{{a}}", begin put(n, get(n) + 1), #{a => 1} end)`，断言 `get(n)` 只增 1。

## 验收标准

- [ ] `<<"...">>` 与 `~"..."` 两种 binary 字面量都能被展开；展开成 `begin ... end` 单表达式
- [ ] 宏展开后为字面 binary 的 `?TPL` 也能被展开
- [ ] 变量、函数调用、`++` 结果、含变量段的 binary 构造保持原样并发出 `inline_not_literal` warning
- [ ] `nowarn_mustache_inline` 编译选项能关掉该 warning
- [ ] `ai_mustache:inline/2` 之外的 arity、本地调用 `inline(A, B)` 不被误匹配
- [ ] Ctx 表达式在展开后只求值一次（有副作用计数测试）
- [ ] 生成的栈变量名带 `__N` 后缀，同一函数中多处 inline 互不遮蔽，与用户变量不冲突
- [ ] 展开后的节点行号等于原调用行号（异常堆栈可断言）
- [ ] inline 调用能出现在 case 分支 / list comprehension 模板 / 函数参数 / fun 体等各种表达式位置并被正确展开（每种位置一条测试）
- [ ] 内联模板中的 `{{> x}}`：展开路径报编译错误、降级路径报运行期错误，二者都失败，行号折算到 `.erl` 的正确行
- [ ] 内联模板中的扩展 tag：展开路径正常工作、降级路径报 `ext_unsupported_at_runtime`，README 中有说明
- [ ] `ai_mustache:inline/2` 的运行期实现复用 `ai_mustache_rt` 的全部语义函数，不重写 lookup / escape / truthy / section / lambda
- [ ] 运行期路径不使用 ets / persistent_term / 任何进程
- [ ] 等价性用例表在「加 transform」与「不加 transform」两个测试模块中输出完全一致，覆盖 [03 §2](../designs/03-semantics.md) 全部 tag 类型与 [03 §3](../designs/03-semantics.md) 的 8 种 section 分派
- [ ] README 有内联模板一节，明确说明不支持自定义 sigil、不支持 partial、扩展 tag 需要 transform
