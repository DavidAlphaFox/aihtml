## 实现要点

### 1. 门面

```erlang
render(Mod, Ctx)        -> Mod:render(Ctx).
render_iolist(Mod, Ctx) -> Mod:render_iolist(Ctx).
render_string(T, Ctx)   -> render_string(T, Ctx, #{}).
render_string(T, Ctx, O)-> 编译并缓存后渲染
inline(T, Ctx)          -> 运行期回退路径
```

`render/2` 是一次直接调用，无查表开销。模块名由调用方给出，
**绝不从用户输入派生** —— 沿用 mustache 侧的决定（避免 atom 表暴露）。

`render_string/3` 的 `partials` 选项接受 `#{Name => TemplateText}`，
编译出的模块名是整个模板集合的摘要，重复调用复用 —— 与
`ai_mustache:render_string/3` 同一套机制，**可复用其实现**。

### 2. `inline/2` 的运行期回退

必须与 [T50](T50.md) 的展开路径行为一致：调用同一个共享谓词拒绝同样的节点。
这条在 [T50](T50.md) 与 [T53](T53.md) 都已列为验收项，此处是第三次确认 ——
因为它是最容易在重构中悄悄破掉的一致性。

### 3. `ai_jinja_dev`

与 `ai_mustache_dev` 一一对应：读生成模块的 `-jinja_source`，
用 `ai_jinja_compiler:source_hash/2` 重算 stamp 比对，变了就重编重载。

**不做 mtime 快速过滤**（[02 §2.3](../designs/02-architecture.md) 的论证）：
POSIX mtime 只有秒级精度，而「改完立刻刷新」正是 dev 热重载存在的理由。

**没有开关**：架构不变量禁止 ets / persistent_term / 进程，无处存放启用状态。
`check/0` 是一次性自检，`reload/1` 是显式重编重载，
**触发必须由调用方显式发起**。这一点要在 module doc 与 README 中写清楚，
否则用户会以为调一次就自动生效。

### 4. `ai_html_dev:reload_all/0`

同时刷新两个引擎的模板模块。仅此一个函数，不做进一步抽象
（[12 §3](../designs/12-jinja-toolchain.md) 解释了为何两个 dev 模块不合并）。

### 5. 异常标签

门面抛出的异常标签是 `ai_jinja`，不是 `ai_mustache` 也不是 `ai_html`
（[T32](T32.md) §2）。有专项用例。

## 验收标准

- [ ] `render/2` 是单次直接调用（源码审查）
- [ ] `render_string/3` 的模块复用生效（连续调用两次不重编，有断言）
- [ ] `inline/2` 与 transform 展开路径行为一致（参数化用例复用 [T50](T50.md) 的表）
- [ ] `ai_jinja_dev:check/0` 能检出模板改动，`reload/1` 能生效
- [ ] dev 模块不使用 mtime 做过滤（源码审查 + 同一秒内两次修改的用例）
- [ ] dev 模块无 ets / persistent_term / 进程
- [ ] `ai_html_dev:reload_all/0` 同时刷新两个引擎
- [ ] 异常标签是 `ai_jinja`
- [ ] module doc 与 README 写明 dev 需显式触发
