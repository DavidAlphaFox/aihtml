# 04 · 编译器与生成代码

## 1. AST 设计

替换现有的扁平 IR，引入带位置信息的 AST（`include/ai_mustache.hrl`）：

```erlang
-type keys() :: [atom()].
-type loc()  :: {Line :: pos_integer(), Col :: pos_integer()}.

%% 注意：类型名不能叫 node() —— 那是 Erlang 内置类型，重定义会被编译器拒绝。
-type ast_node() ::
      {text,    loc(), binary()}
    | {var,     loc(), keys(), escape | raw}
    | {section, loc(), keys(), [ast_node()]}                    %% {{#x}}
    | {inverted,loc(), keys(), [ast_node()]}                    %% {{^x}}
    | {has,     loc(), keys(), [ast_node()], boolean()}         %% {{+x}} / {{-x}}
    | {lambda,  loc(), keys()}                                  %% {{*x}}
    | {partial, loc(), Target, Indent :: binary()}
    | {ext,     loc(), Marker :: char(), keys(), [ast_node()]}. %% 用户扩展 tag

%% partial 的 Target 在 resolve_partials/2 前后类型不同：
%%   前：binary()  —— 模板里写的原始路径，如 <<"shared/item">>
%%   后：module()  —— 归一化后的目标模块名，如 view_shared_item
-type partial_target() :: binary() | module().
```

相比现有 IR 的改进：

- **带 `loc()`** —— 生成代码时映射行号，模板出错时堆栈能指回 `.mustache` 的原始行
- **`{ext, ...}`** —— 扩展 tag 的一等公民表示，见 [06](06-parse-transform.md)
- **`{partial, ..., Indent}`** —— standalone 缩进作为结构化字段而非混进文本

## 2. AST 后处理（修掉 P1/P2/P3）

三个 pass，全部**递归下钻到所有含 body 的节点**（section / inverted / has / ext），且用 `lists:reverse/1` 而非 `Acc ++ [I]`：

1. `merge_text/1` —— 合并连续 `{text, _, _}`
2. `drop_empty/1` —— **只移除空 body 的 `has` 与 `ext` 节点**。

   > **`section` 的空 body 不能删。** `{{#w}}{{/w}}` 在 `w` 是 `fun/2` 时，标准语义要求调用 `F(<<>>, Frame)` 并输出其返回值；编译期无法证明某个 key 在运行期不是函数，删掉就会丢输出。`inverted` 的空 body 同样保留（它的语义在于"是否执行"而非"执行什么"）。空 body 的 section 照常生成 body 函数，只是函数体返回 `[]`。
3. `resolve_partials/2` —— partial 路径 → 目标模块名，产出依赖列表

## 3. 编译器接口

```erlang
-module(ai_mustache_compiler).

-export([forms/2, compile_inline/3, source_hash/2]).

-type opts() :: #{
    module     := module(),            %% 目标模块名
    source     := file:filename_all(), %% 模板源路径
    prefix     => binary(),            %% partial → 模块名的前缀，默认 <<"view_">>
    views      => file:filename_all(),
    extensions => [module()],          %% 扩展模块列表，见 06
    ext_opts   => #{module() => term()}, %% 透传给各扩展 compile_tag/4 的配置
    stack_var  => atom(),              %% 生成代码中 context stack 的变量名
    line_map   => boolean()            %% 是否映射模板行号，默认 true
}.

%% 完整模块：给 rebar3 plugin
-spec forms([ast_node()], opts()) -> {ok, [erl_parse:abstract_form()], Deps :: [module()]}
                               | {error, term()}.

%% 单表达式：给 parse_transform 的内联展开
-spec compile_inline([ast_node()], CtxVar :: erl_parse:abstract_expr(), opts())
                    -> {ok, erl_parse:abstract_expr()} | {error, term()}.
```

两个入口共用同一套 body 编译逻辑，只是外层包装不同 —— 这是[架构不变量 #2](02-architecture.md#8-架构不变量)。

## 4. 生成代码形态

模板 `views/complex.mustache`：

```mustache
<h1>{{header}}</h1>
<ul>
  {{# items}}
    {{> shared/item}}
  {{/ items}}
</ul>
{{> shared/user}}
{{*yield}}
```

生成 `_gen/view_complex.erl`：

```erlang
%% Generated by rebar3_aihtml from views/complex.mustache -- DO NOT EDIT.
-module(view_complex).

-mustache_source(#{path  => <<"views/complex.mustache">>,
                   stamp => <<16#a3f1...:256>>,   %% 内容+选项+版本 的组合，非模板原文 hash
                   mtime => 1757203845,
                   vsn   => 1,
                   opts  => #{views => <<"views">>, prefix => <<"view_">>,
                              extensions => [], line_map => true}}).

-export([render/1, render_iolist/1, render_stack/1, render_stack/2, partials/0]).

render(Ctx)        -> erlang:iolist_to_binary(render_stack([Ctx], <<>>)).
render_iolist(Ctx) -> render_stack([Ctx], <<>>).
render_stack(S)    -> render_stack(S, <<>>).
partials()         -> [view_shared_item, view_shared_user].

render_stack(S, I) ->
    [<<"<h1>">>,
     ai_mustache_rt:escape(ai_mustache_rt:lookup([header], S)),
     <<"</h1>\n<ul>\n">>,
     sec_1(S, I),
     <<"</ul>\n">>,
     view_shared_user:render_stack(S, I),
     lam_2(S)].

%% {{# items}} —— views/complex.mustache:3
sec_1(S, I) ->
    case ai_mustache_rt:lookup([items], S) of
        %% falsy 必须排在最前 —— 见下方说明
        undefined                -> [];
        false                    -> [];
        null                     -> [];
        <<>>                     -> [];
        []                       -> [];
        L when is_list(L)        -> [sec_1_body([E | S], I) || E <- L];
        M when is_map(M)         -> sec_1_body([M | S], I);
        true                     -> sec_1_body(S, I);
        F when is_function(F, 2) -> F(erlang:iolist_to_binary(sec_1_body(S, I)), hd(S));
        F when is_function(F, 1) -> ai_mustache_rt:section(F(hd(S)), fun sec_1_body/2, S, I);
        V                        -> sec_1_body([V | S], I)      %% 标量：压栈，使 {{.}} 可用
    end.

sec_1_body(S, I) ->
    [<<"    ">>, view_shared_item:render_stack(S, <<I/binary, "    ">>), <<"\n">>].

%% {{*yield}} —— views/complex.mustache:8
lam_2(S) -> ai_mustache_rt:lambda(ai_mustache_rt:lookup([yield], S), hd(S)).
```

### 关键点

1. **静态文本是字面量** —— 进 BEAM literal pool，跨进程零拷贝，彻底替代 ets。
2. **section body 是独立函数** —— list comprehension `[sec_1_body([E|S], I) || E <- L]` 干净且高效，**不构造新 context map**（对比旧实现每次迭代 `maps:merge` 全量拷贝，同时修掉 [B1](01-current-state.md#b1-·-多层-section-名丢失兄弟键（正确性）)）。
3. **partial 是跨模块调用** —— `view_shared_user:render_stack(S, I)`。增量编译粒度正确，循环引用天然支持。
4. **`I` 是 standalone 缩进**，逐层向下传递，实现 spec 要求的 partial 多行缩进。
5. **`sec_1/2` 的 case 分支在编译期全部展开** —— 无运行期查表、无 apply。
6. **falsy 分支必须显式排在最前**。`false` / `undefined` / `null` / `<<>>` 都不是 list 也不是 map，若没有显式子句就会落到兜底的标量分支被压栈执行 body，与 [03 §2.1](03-semantics.md#21-falsy-的定义) 的 falsy 定义直接冲突。`ai_mustache_rt:section/4`（处理 `fun/1` 的返回值这类编译期不可知的情况）内部同样必须先判 falsy。
7. **`-mustache_source` 的 `opts` 字段是必需的，不是冗余**。增量判断要算「内容 + 编译选项 + compiler 版本」的组合值（[05 §3.1](05-rebar3-plugin.md#31-增量判断只看内容-hash)），而 dev 热重载（T27）要忠实复现 plugin 当初的编译，二者都需要 `views` / `prefix` / `extensions` / `line_map`。缺了它，改 `mustache_opts` 不会触发重编，dev 重编出来的模块也会和 plugin 产物不一致。字段名用 **`stamp` 而非 `hash`** —— 它存的是组合戳，不是模板原文的摘要，叫 `hash` 会被误读。
8. 函数名带序号（`sec_1` / `lam_2`），注释标注模板原始行号；开启 `line_map` 时 forms 的 line 直接用模板行号。

### 4.1 source hash 的计算归属

hash 必须由 **aihtml 侧**导出一个函数，plugin 与 dev 模块都调它：

```erlang
-spec ai_mustache_compiler:source_hash(Body :: binary(), opts()) -> Stamp :: binary().
```

绝不能让 plugin 自己算一份、dev 再算一份 —— 两侧口径一旦漂移，dev 会认为模块永远是陈旧的从而无限重编，而 plugin 会认为永远是新鲜的从而不重编。计算输入固定为：模板内容、规范化后的编译选项、`?COMPILER_VSN` 宏。选项规范化（排序 + 去掉不影响产物的项）也在这个函数里做。

## 5. 运行时模块 `ai_mustache_rt`

生成代码唯一的运行期依赖，只依赖 OTP：

```erlang
-module(ai_mustache_rt).
-export([lookup/2, escape/1, to_binary/1, section/4, lambda/2, truthy/1]).

%% context stack 回溯查找
-spec lookup(keys(), [term()]) -> term().
lookup([K | Rest], Stack) ->
    case find_frame(K, Stack) of
        {ok, V} -> descend(Rest, V);      %% 首段回溯，后续段严格下钻
        error   -> undefined
    end.
```

### 5.1 `escape/1` —— 单遍扫描

替换 ailib 那 8 遍 `re:replace`（见 [B3](01-current-state.md#b3-·-html-escape-缺分号且极慢（在-ailib-中）)）：

```erlang
-spec escape(term()) -> iodata().
escape(B) when is_binary(B) -> escape(B, B, 0, 0, []);
escape(V) -> escape(to_binary(V)).

%% 无需转义时零拷贝返回原 binary（这正是返回 iodata() 而非 binary() 的原因）；
%% 需要转义时用 binary:part/3 切片 + iolist 拼接，不做逐字节 append。
```

返回类型是 `iodata()` 而非 `binary()`：不需要转义时直接把原 binary 原样返回（零拷贝），需要转义时返回切片拼成的 iolist，都不做一次 `iolist_to_binary`。这与 `render_iolist/1` 的整体输出策略一致，最终只在 `render/1` 出口收敛一次。

转义表（**修正 `&amp` 缺分号**）：

```
&  →  &amp;      <  →  &lt;       >  →  &gt;
"  →  &quot;     '  →  &#39;
```

> **移除 `/` `=` `` ` `` 的转义。** 旧实现把这三个也转义，会破坏 URL（`href="/a/b"` → `href="&#x2F;a&#x2F;b"`）与普通文本。标准 mustache 只要求前五个。这是行为变更，需在 README 的 Incompatible Changes 中列出。

## 6. 编译期优化

| 优化 | 说明 |
|---|---|
| 相邻字面量合并 | AST 后处理已做，生成的 iolist 中静态段最少 |
| 空 section 消除 | `drop_empty/1` |
| 常量折叠 | 整个模板无动态 tag 时，`render_iolist/1` 直接返回单个 binary 字面量 |
| 缩进静态化 | `I` 在编译期可确定为 `<<>>` 时（非 standalone partial），直接省掉参数传递 |
| escape 静态化 | 静态文本在编译期已确定不需转义，不生成任何 escape 调用 |

## 7. 错误处理

编译期错误统一格式，供 plugin 与 parse_transform 输出成标准编译诊断：

```erlang
{error, {File :: binary(), Line :: pos_integer(), Reason}}

Reason :: {unclosed_tag, Keys}
        | {mismatched_close, Expected, Got}
        | {partial_not_found, Name}
        | {partial_in_inline_template}    %% 内联模板中禁止 {{> x}}，见 06 §3.3
        | {unknown_marker, Char}          %% 未注册的扩展 tag
        | {invalid_delimiter, Bin}
```

plugin 侧格式化为 `views/index.mustache:12: unclosed tag {{#items}}`，与 erlc 诊断一致，编辑器可点击跳转。

> **没有 partial 循环错误码。** 文件模板路径下 partial 编译成跨模块调用，循环引用天然合法（[02 §2.2](02-architecture.md#22-partial-编译成跨模块函数调用)）；内联模板路径又完全禁止 partial（[06 §3.3](06-parse-transform.md#33-内联模板不支持-partial)）。两条路径都不存在需要检测循环的场景。
