# 07 国际化（实施中：第 1、2 步已完成）

给组件的界面文字和格式化加上统一的语言设置：页面声明一次语言，所有组件的默认文字、日期和数字格式都跟着变。方案已确认（见文末「已定事项」），按「实施步骤」分步进行。

## 现状

- **没有统一的语言设置。** 界面文字默认英文。16 个组件有 `labels` 类的选项可以覆盖文字（datagrid、pagination、datepicker、calendar、scheduler、upload、time_ago、status_bar 等），但每个组件要单独传；pivotgrid 另有 `locale => en | zh`，是唯一有语言开关的组件。
- **写死、无法覆盖的文字：**
  - Erlang：约 25 个模块、40 处 `aria_label`、`title`、`placeholder`，例如 alert 的 "Close"、colorpicker 的 "Hue"、timepicker 的 "AM/PM"。
  - 共享模板：约 10 处，例如 datepicker 的 "Wk"、timepicker 的 "AM/PM"、node_graph 的 "Delete group"。
  - TypeScript：约 15 处，集中在 node_graph 的右键菜单和搜索框，另有 toolbar、menu、tile_layout、datepicker、datetime_input、cascader 各一两处。
- **格式化只有一种写法：** datagrid 的数字用 `,` 分千位、`.` 作小数点；星期从周日开始（scheduler 除外）；time_ago 的悬停提示用浏览器的 `toLocaleString()`，与服务端的语言无关。
- **`aihtml_page` 的 `lang`** 只写到 `<html lang>`，不影响组件。

## 目标

1. 页面设置一次语言（`aihtml:page(Body, #{lang => <<"zh-CN">>})`），所有组件的默认文字、日期名称、一周起始日、数字格式都跟着变。
2. action 的回复、推送、URL 片段里渲染的组件，和页面使用同一种语言；业务层仍然无状态。
3. 文字只有一个来源：服务端的 JSON 文案表。浏览器端需要的文字由服务端写进元素，不另外打包一份 JS 文案。
4. 兼容：默认语言是 `en`，现有页面的 HTML 输出逐字节不变；`labels` 选项照常覆盖单条文字。
5. 自带 `en` 和 `zh`，使用方可以增加别的语言，也可以改写自带的条目。

不在本文范围：演示站自身文字的多语言（暂不做，见「已定事项」）、从右到左的书写方向。

## 设计

### 文案表

模块 `aihtml_i18n`，文案是 JSON 文件，每种语言一个：自带的放在 `apps/aihtml/priv/i18n/<语言>.json`（随 release 一起打包）。文案按「组件 + 键」组织，沿用各组件现有 `labels` 的键名：

```json
{
  "format": {"decimal": ".", "group": ",", "first_day": 0,
             "months": ["January", ...], "weekdays": ["Sunday", ...]},
  "messages": {
    "common":     {"close": "Close", "loading": "Loading..."},
    "datagrid":   {"total": "Total {0}", "empty": "No data"},
    "pagination": {"prev": "Previous"}
  }
}
```

- 选 JSON 而不是 Erlang 模块：不会 Erlang 的人也能翻译和校对。文件在第一次用到时读入 `persistent_term`，之后查表不读文件；`aihtml_i18n:reload/0` 重新读取。
- 键在 Erlang 这边是原子：`text(datagrid, total)`、`texts(datagrid)` 返回 `#{total => ...}`。JSON 里的键只来自受信任的文件，不来自请求。
- 多个组件共用的文字（关闭、加载中、确定、取消）放在 `common`。
- 占位符统一用 `{0}`、`{1}`；time_ago 现有的 `{n}` 保留兼容。
- 复数：只在确实需要的键上拆成 `one` / `other`（如 node_graph 的 "Duplicate 3 nodes"），不引入通用的复数规则库。

### 当前语言

组件在渲染时才取文字（record 是惰性渲染的，见 05-records），所以语言是**渲染时的上下文**，放在进程字典里，由渲染入口设置：

| 入口 | 语言从哪来 |
|---|---|
| `aihtml:page/2` | `lang` 选项（默认是默认语言），原样写到 `<html lang>`，并作为整页（含 `<head>`）渲染时的语言 |
| action 的回复 | 浏览器在请求体里带上 `document.documentElement.lang`（`{action, event, stream, lang}`），`aihtml_action:execute/3` 在执行期间设置；`aihtml_action:lang(Ctx)` 可读 |
| URL 片段（`fetch/3,4`） | 运行时请求时加请求头 `X-Aihtml-Lang`（与已有的 `X-Aihtml`、`X-Aihtml-Target` 同一前缀）；使用方的路由用 `aihtml_i18n:with(Lang, Fun)` 包住渲染 |
| 推送 | HTML 只渲染一次、发给所有订阅者，所以用发布时指定的语言：`aihtml_push:publish(Topic, Fun, #{lang => L})`，默认是默认语言，**不是**调用它的 action 的语言（订阅这个主题的页面不一定都是这种语言）。多语言站点按语言分主题（如 `{todos, <<"zh">>}`），页面订阅自己语言的主题。底层是 `aihtml_action:render_ops/2`；`render_ops/1` 用当前语言 |
| 直接调用 `aihtml:render/1` | `aihtml_i18n:with(Lang, fun() -> aihtml:render(El) end)`；不设置时是默认语言 |

**默认语言**：应用环境 `{aihtml, [{default_locale, <<"zh">>}]}`，不设置时是 `en`。单一语言的站点设置它就够了，页面、推送、`aihtml:render/1` 都用它。

**语言标签**：统一成小写、`-` 连接（`zh_CN`、`zh-CN` → `zh-cn`）。来自浏览器的值格式不对（不是 `xx`、`xx-yyyy` 这类形式，或超过 35 字节）时按默认语言处理，不会报错，也不会产生新的原子。

**语言回退**：`zh-TW` → `zh` → `en`，逐条回退，所以部分翻译的语言也能用。所有语言里都找不到的键报错 `{aihtml, {no_text, Scope, Key}}`。

### 组件怎么取文字

```erlang
T = aihtml_i18n:texts(datagrid, R#ah_datagrid.labels)
%% = 当前语言的 datagrid 文案，逐条回退到 en，再用 labels 覆盖（键不存在照旧报错）
aihtml_i18n:text(common, close)
aihtml_i18n:format(first_day)
```

- **已有 `labels` 的 16 个组件**：`default_labels()` 挪进 `en.json`，组件改调 `texts/2`，选项和行为不变。
- **写死的文字**：全部改成查表。要不要给这些组件新增 `labels` 选项，逐个看：只有读屏文字的（colorpicker 的 "Hue"）不加，跟随语言就够了。
- **一周起始日**：calendar、datepicker、datetime_input 的 `first_day` 默认值从 `0` 改成 `undefined`，表示「跟随语言」（en 为 0，zh 为 1）。scheduler 现在默认是 1，保持原值不变。显式写的值照常生效。
- **数字格式**：datagrid 的 `n`、`c`、`p` 格式按语言取小数点和千位分隔符；日期格式模式本来就由使用方写，不变。

### 浏览器端

- **只用服务端给的文字。** 需要在浏览器里生成文字的组件，把文字写进根元素的 `data-ah-labels`（datagrid、datepicker、calendar、datetime_input、upload、markdown_editor、dock_layout 已经这样做），node_graph、toolbar、menu 等写死文字的组件也改成这样。JS 不带文案表，不需要按语言加载额外代码块，打包产物不变。
- **共享模板**：模板里写死的文字改成模板变量，Erlang 和 JS 两端都从上面的文案传入，现有的「两端输出逐字节相同」测试照常覆盖。
- **time_ago**：悬停提示改用 `Intl.DateTimeFormat(document.documentElement.lang)`，与页面语言一致。
- **图表**：echarts 自带界面文字很少（工具栏提示），按页面语言选 echarts 的内置语言包（它自带 EN、ZH）。

### 扩展与改写

```erlang
%% sys.config：增加语言，或改写自带语言的条目
{aihtml, [{default_locale, <<"zh">>},
          {locales, #{<<"ja">> => {priv_dir, myapp, "i18n/ja.json"},   % 新语言
                      <<"zh">> => "/etc/myapp/zh.json"}}]}          % 覆盖自带 zh 的部分条目
```

来源可以是文件路径，或 `{priv_dir, App, 相对路径}`。使用方的文件只写需要的条目：与同名的自带语言逐项合并（使用方的优先），缺的再逐条回退。配置里的语言标签格式不对、文件读不到，第一次查表时报错（`{aihtml, {bad_locale, L}}`、`{aihtml, {i18n_catalog, File, Reason}}`）。

## 兼容性

- 默认语言 `en`，文字与现在完全相同。验收时照 05-records 的做法，导出全部演示的 HTML，与改动前逐字节比对。
- `labels` 选项、pivotgrid 的 `locale` 选项继续可用；pivotgrid 的 `locale` 不写时改为跟随页面语言。
- action 请求体多一个可选字段 `lang`；旧页面不带时按默认语言处理。
- `aihtml_action:ctx()` 是不透明类型，内部多了语言字段，使用方不受影响。
- **会变化的地方**：设置了 `lang` 的页面（目前只影响 `<html lang>`），组件文字会变成对应语言。自带语言只有 en、zh，其它语言回退到 en，与现在一致。

## 测试

- 文案完整：自带语言的键集合相同；每个组件用到的键都在 en 里。
- 防止新增写死的文字：一个检查脚本扫描 Erlang 源码、模板和 TS 里的 `aria-label`、`title`、`placeholder` 等位置的英文字面量，测试里运行，有新的就失败（附白名单）。
- en 的演示输出与改动前逐字节相同；zh 下为每个组件的第一个演示做快照。
- 浏览器测试：node_graph 菜单、datepicker 等在浏览器里生成文字的组件，在 zh 页面下显示中文。
- action 回复：请求带 `lang => <<"zh">>` 时，回复里组件的文字是中文。

## 实施步骤

1. **基础设施（已完成）**：`aihtml_i18n`（当前语言、`with/2`、`normalize/1`、`text/2,3`、`texts/1,2`、`format/1`、回退、`default_locale` 与 `locales` 配置、`reload/0`），`priv/i18n/en.json`（目前只有 `format` 和 `common`）；`aihtml_page` 设置语言；action 请求带 `lang`，`aihtml_action:lang/1`；`fetch` 带 `X-Aihtml-Lang`；`publish` 的 `lang` 选项与 `render_ops/2`。460 个演示的输出与改动前逐字节相同；测试在 `aihtml_i18n_tests`。顺带修了 `aihtml_action`：模块同时声明 `aihtml_element` 和 `aihtml_action` 两个行为时，第二个没被识别，令牌被拒。
2. **迁移已有 `labels` 的组件（已完成）**：16 个组件（datagrid、pagination、calendar、scheduler、datepicker、datetime_input、gantt、swimlane、time_ago、status_bar、upload、markdown_editor、docking、dock_layout、pivotgrid、heatmap_calendar）以及 range_selector 的月份名的默认文字挪进 `en.json`，共 242 条。月份和星期名称在这些组件里是同一套，放进 `format`（`months`、`months_short`、`weekdays`、`weekdays_short`、两个字母的 `weekdays_min`、`am`、`pm`），heatmap 默认只显示一、三、五，从 `weekdays_short` 推出。pivotgrid 原有的中文放进 `zh.json`，它的 `locale` 选项改为从文案表取对应语言。各组件自己的合并、校验和报错不变，只换了默认值的来源。迁移前把旧的默认值原样拷成快照逐项比对，242 条全部一致；460 个演示的输出逐字节不变。新增测试：自带语言的每个键在 en 里都存在，列表长度一致。
3. **写死的文字**：Erlang 约 40 处、模板约 10 处、TS 约 15 处改为查表或读 `data-ah-labels`；加上防回归的检查脚本。输出不变。
4. **中文**：`zh.json`、一周起始日、数字分隔符、time_ago、echarts 语言包；zh 快照和浏览器测试。
5. **文档**：中英 README 增加「国际化」一节，本文改为「已完成」。

每一步单独可验收，第 1–3 步不改变任何现有输出。
